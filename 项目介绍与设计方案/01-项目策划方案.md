# Pi Study Helper 项目策划方案

> 多智能体角色权限、返修和降级口径见[《多智能体协同审核与可视化说明》](./03-多智能体协同审核与可视化说明.md)。
>
> 赛题：XH-202630 领域知识个性化生成与多智能体协同决策系统研究

## 一、项目概述

Pi Study Helper 是一套面向职业技能学习的可插拔个性化学习工作台。本阶段选择 Pandas 数据清洗作为完整示范领域，把固定可信教学正文、学习者诊断、确定性学习路径、多智能体内容审核、客观题练习、Python 代码评测和学习总结组织成一条可追溯闭环。

项目要解决的不是“让模型多说几句话”，而是三个实际问题：

1. 通用大模型可能生成超出专业依据、答案不唯一或难以复核的教学内容和题目；
2. 同一份课程很难同时照顾基础薄弱、已有基础和偏好不同的学习者；
3. 学习者看懂概念，不代表能够在真实数据上完成可靠处理。

我们的基本策略是“双轨并行”：以 Profile 资料包保存权威正文、规则、来源和评测资产，以确定性程序保存学习事实、路径和评分；在这个边界内，再由多智能体生成经过审核的课前导学和客观题，把学习反馈转化为下一步练习重点。

## 二、建设目标

### 2.1 总目标

建设一个可以运行、可以演示、可以复核的 Pandas 个性化学习 Demo，完整展示：

```text
学习者输入
→ 固定客观诊断
→ Evidence 与 KnowledgeState
→ 个性化路径和可选跳过
→ 版本化中文教学正文
→ AI课前导学
→ AI客观题生成与多Agent审核
→ 代码补全和正式测试点评测
→ 错题补救与画像更新
→ 学习成果总结
```

### 2.2 阶段目标

| 目标 | 交付含义 | 当前材料口径 |
|---|---|---|
| 专业可信 | 六个 Pandas 知识点有统一规则、来源和三套讲解版本 | 已形成 Profile 资料包和结构化教学正文；最终候选仍需复核 |
| 个性化 | 诊断、讲解偏好、学习证据和错题影响后续资源 | 确定性路径负责事实决策，Agent负责解释和动态内容 |
| 多Agent协同 | Generator、Hunter、Defender（条件触发）、Judge与确定性安检工位有清晰职责和轨迹 | 已实现串行审核链及一次受控返修闭环；最终候选仍需用真实运行验收 |
| 实操迁移 | 每章有客观题和代码活动，代码结果由 Node/Python正式评测 | Pandas六节活动已接入；最终提交前需完成整体验收 |
| 可交付 | 评委能在陌生 Windows 机器部署并打开网页 | 已提供一键启动入口和部署说明；需在干净机器复现 |

## 三、目标用户与使用场景

### 3.1 目标用户

- 希望系统学习数据清洗的 Python 初学者；
- 有 Python 或 Pandas 基础、希望快速查漏补缺的学习者；
- 需要通过真实 CSV 处理任务检验迁移能力的职业技能学习者；
- 需要维护统一专业课程、评测规则和学习案例的培训组织。

### 3.2 典型使用场景

**场景A：基础薄弱学习者。** 用户选择逐步讲解，诊断显示多个知识点缺少证据。系统保留必要先修内容，绑定 `guided` 正文，课前导学先解释本节位置和学习主线，答错后生成针对薄弱知识点的补救题。

**场景B：已有基础学习者。** 用户选择重点速览，诊断在某些模块形成两类以上证据。系统向用户提供是否跳过对应章节的选择，绑定 `concise` 正文；用户仍可保留章节学习，并在总结中区分“诊断已掌握”和“学习后新掌握”。

**场景C：局部薄弱学习者。** 用户选择案例优先，在重复订单或类型转换边界上出错。系统绑定 `practice` 正文，动态题在正文约束下重复考察错题暴露的知识点，代码活动用多个输入输出测试点验证迁移。

以上是案例设计口径。最终材料只有在对应会话、轨迹、截图和输出文件齐全后，才能把案例写成“实际运行案例”。

## 四、产品方案

### 4.1 领域资料包

当前领域是 Pandas 数据清洗，六个知识模块形成稳定主线：

```text
读取 CSV
→ 检查 DataFrame 结构
→ 处理缺失值
→ 处理重复订单
→ 规范类型与格式
→ 验证清洗结果
```

每个模块保存三套中文正文：

| 用户讲解偏好 | 正文版本 | 设计重点 |
|---|---|---|
| 逐步讲解 | `guided` | 先建立直觉，再分步理解规则和反例 |
| 重点速览 | `concise` | 压缩叙述，突出主线、边界和检查项 |
| 案例优先 | `practice` | 从数据情境、任务和结果观察知识点 |

三套正文覆盖相同规则和来源，只改变表达与组织方式。当前 Session 只绑定一套，不能在学习过程中切换版本；重新建会话并重新选择偏好后才能更换。

### 4.2 学情诊断与路径

开始页收集学习目标和讲解偏好，诊断阶段使用固定客观题。每道题的判分、Evidence、KnowledgeState、路径状态和预计时长由服务端确定性代码完成。画像 Agent 不直接改分数或路径，它只解释已有事实并提出学习建议。

当某知识模块达到预设的多类证据条件，路径会把它标记为可跳过，并把“跳过/保留”交给用户选择。用户跳过的章节不能被当作已学习掌握，最终总结必须展示跳过记录和证据不足情况。

### 4.3 学习与练习

进入章节后，页面先展示 AI 个性化课前导学（如果本次生成成功），包括本节要学什么、与前后章节的关系、学习主线和建议。正式正文始终可用，动态提醒不能替换或删减正文。

随后完成：

- AI 客观题：Generator 根据当前正文生成 4 至 6 道中文单选题，候选答案和解析只在服务端审核链内部使用；
- 代码补全：页面提供完整题面、已有代码骨架、TODO 区域、公开输入输出样例，用户提交后由 Python 正式评测多个测试点；
- 补救学习：客观题或代码失败后，系统记录错题与知识证据，并在允许重做时让新题组同时参考正文和上一轮错题。

### 4.4 多智能体协作

动态内容采用串行流水线：

```text
教学依据准备
→ 学情画像读取
→ Generator 生成候选
→ 确定性安全与 Schema 检查
→ Hunter 反向找错
→ 程序路由器按预设规则判断是否需要 Defender 辩护
→ Judge 最终裁决
→ 接受则发布；可修复则返修；不可修复则明确降级
```

其中，学情画像Agent、Generator、Hunter、Defender（条件触发）和Judge属于模型Agent；Safety是独立的确定性安检工位，不是模型Agent，也不调用大模型。安检通过程序规则检查输出Schema、来源绑定、题目和选项重复、旧题复用、跨题答案提示、越权字段及敏感信息。Hunter只提交问题和证据，无权直接命令Generator返修；Defender处理无法由程序直接证明的语义争议和高风险；Judge是唯一最终裁决者。安检未通过时可返回Generator定向修复；目标流程中Judge返回 `revise` 后也应由流程编排程序生成受控修复要求，并让新候选重新经过完整审核。教学依据准备与发布属于流程工位，不作为模型Agent计数。

当前代码已实现安检后的Generator定向修复、Hunter合同重试，以及Judge返回 `revise` 后的一次受控返修回路。返修候选会重新经过Safety、Hunter、必要时的Defender与Judge；只有Judge `accepted` 才发布。最终提交前仍需以真实运行轨迹验证该链路，不能只凭代码存在就宣传为实测效果。

缓存只在正文版本、画像/补救上下文、模型和提示词版本等键完全一致且已有审核结果时复用。API 失败、超时、Schema 不合法或审核拒绝时，系统使用明确标记的固定保障，不把固定题写成实时 AI 成功。

## 六、效果评测与证据总结

本项目的测试材料分为两类，统计口径彼此独立：一类是用于计算总体效果的规模化对照测试；另一类是用于展示用户输入、系统决策和运行过程的三组端到端案例。三组案例不作为核心指标的统计样本，也不用于推导大范围测试结论。

核心指标评价采用统一的原子事实、冻结案例和知识点口径，计算公式如下：

```text
幻觉率 = 错误或无依据原子事实数 / 已判定原子事实总数
难度匹配准确率 = 命中预先冻结 gold 集合的案例数 / 可判定案例数
核心知识点覆盖率 = 满足 requiredEvidence 的知识点数 / 核心知识点总数
```

### 6.1 规模化对照测试结果

| 指标 | 规模化对照测试结果 | 比赛目标 | 结果说明 |
|---|---:|---:|---|
| 幻觉率 | 3.64%（9/247） | <5% | 低于目标上限 |
| 难度匹配准确率 | 85.00%（153/180） | ≥85% | 达到目标线 |
| 核心知识点覆盖率 | 83.33%（5/6） | ≥90% | 已覆盖 5 个正式核心知识点，结果与目标差距如实保留 |

本节数据来自独立的规模化单智能体/多智能体对照测试：幻觉率与有效溯源等内容指标以 `247` 条已裁决原子事实为样本，难度适配等路径指标以 `180` 个节点观察值为样本。完整分子分母、Token 和耗时统计见[《核心指标对照结果》](../测试数据材料和结果/01-测试方案与评价口径/核心指标对照结果.md)，不得以三组案例中的小范围运行次数替代或解释本节结果。

### 6.2 三组过程性案例与复现证据

以下内容是三类学习者测试用例的过程性展示结果，目的在于让评审核对“输入画像—路径决策—内容生成—作答反馈—学习总结”的完整闭环。它们用于展示系统如何工作和提供可复现的过程数据，不参与第 6.1 节核心指标的汇总计算。

1. 三组差异化学习者范例均已完成，覆盖基础薄弱、中等基础和高基础学习者，包含背景输入、13 道诊断、路径选择、学习活动和最终总结；
2. 范例运行中记录了 14 次章节客观题，均为 `ai_live` 来源；其中 10 次实际执行 Generator、安检、Hunter 和 Judge，4 次复用已审核缓存结果。该数量只描述范例运行过程，不代表规模化测试样本量；
3. 三组范例均展示一次错题补救闭环；固定基础补救活动与实时题组来源在运行记录中明确区分，范例中的章节客观题没有回退为固定保障；
4. 范例中完成的 11 个代码活动均由服务端评测器判定通过，每个活动的 5 个测试点均通过；该结果用于展示评测闭环，不作为总体学习效果指标；
5. 三组完整运行轨迹、多智能体过程记录、运行耗时、复现输入和测试方案均已归档，部署启动、环境版本和安全边界由交付说明统一约束。

详细证据目录和复现顺序见[《测试材料说明》](../测试数据材料和结果/提交材料说明.md)。

## 七、风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| API Key无效、余额不足或网络不可用 | 实时题生成失败 | 明确显示 `live_model` 配置状态；使用固定保障并记录失败原因 |
| Generator输出结构或知识依据不合格 | 错题、幻觉或无法发布 | Schema、安全检查、Hunter和Judge逐层阻断；保留脱敏轨迹 |
| 旧数据与新 Profile 不兼容 | 页面打不开或读取错误会话 | 通过 revision seal隔离数据目录；新候选使用新会话 |
| 页面状态与服务端运行记录脱节 | 用户误以为卡住或看到错误章节状态 | 流水线绑定当前节点和 runId；等待显示阶段及读秒 |
| 指标与证据口径不一致 | 材料失去可信度 | 统一分子分母、版本号和证据索引；未执行项目如实标注，不以目标值代替实测 |
| 代码评测环境不一致 | 测试结果不可复现 | 固定 Node/Python/pandas 合同版本，启动器预检并记录解释器路径 |
