## 1. W2-A：Pandas诊断资产合同

### 1.1 题面蓝图

文件固定为`assessments/diagnostic/questions.json`。根对象允许下列核心字段和`x-`扩展，其他字段拒绝；`questions[]`条目只允许接口列出的精确字段，不允许未知字段或`x-`扩展：

```ts
interface DiagnosticBlueprintAsset {
  blueprintId: string;
  profileRevision: 2;
  goalIds: string[];
  estimatedMinutes: number;
  minimumCoverage: 1;
  questions: DiagnosticQuestionAsset[];
  scoringVersion: string;
  [extensionName: `x-${string}`]: JsonValue;
}

interface DiagnosticQuestionAsset {
  questionId: string;
  knowledgePointId: string;
  kind: "single_choice" | "judgment";
  difficulty: "S-R" | "S-U" | "M-U" | "M-A" | "C-A";
  prompt: string;
  options?: string[];
  maxScore: 1;
  required: boolean;
  evaluatorRef: string;
  sourceAnchorIds: string[];
}
```

约束：

1. 共8至12题，预计总时长不超过10分钟；六个Pandas核心知识点各至少一题，并至少一题抽样`basic-python`。
2. `single_choice`必须有3至5个非空且互不重复的`options`；`judgment`必须省略`options`。
3. 单选提交值是`options`中的原始字符串；判断提交值是布尔值。
4. `evaluatorRef`固定为`private/answer-key.json#<questionId>`；知识点、目标和来源锚点必须存在于同一revision。
5. 本revision拒绝`code_reading`、`output_prediction`、`multi_choice`和其他题型；未来增加必须修订合同。
6. `blueprintId/questionId/scoringVersion`必须是去首尾空格后仍非空的稳定ASCII标识，格式为`[A-Za-z0-9][A-Za-z0-9._-]*`；`questionId`在蓝图内唯一。
7. `goalIds`必须非空、去重且全部存在；每题`sourceAnchorIds`必须非空、去重且全部存在；每题只能引用一个存在的`knowledgePointId`。
8. `estimatedMinutes`必须是1至10的有限整数；`minimumCoverage`和`maxScore`只能是数值字面量`1`；`questions`必须为8至12项。
9. `prompt`去首尾空格后不得为空；`required`必须是布尔值。`required=true`表示关键覆盖题，但仍允许显式跳过；跳过只登记该知识点证据不足，不改写为答错。
10. 六个Pandas核心知识点各至少出现一题，`basic-python`至少出现一题；同一题不得通过扩展字段声明第二个计分知识点或题目自定义Evidence权重。

### 1.2 私有答案

文件固定为`assessments/diagnostic/private/answer-key.json`，根对象和条目只允许精确字段，不允许扩展：

```ts
interface DiagnosticAnswerKeyAsset {
  blueprintId: string;
  evaluatorVersion: string;
  answers: DiagnosticAnswerKeyEntry[];
}

type DiagnosticAnswerKeyEntry =
  | { questionId: string; kind: "single_choice"; correctAnswer: string }
  | { questionId: string; kind: "judgment"; correctAnswer: boolean };
```

`blueprintId/evaluatorVersion`必须符合稳定ASCII标识格式；`answers[].questionId`唯一。答案必须与题面一一闭合，不得缺少或多出条目；条目`kind`必须与题面一致，单选正确值必须严格等于一个选项。题面、前端、安全DTO、普通日志和模型上下文不得出现本文件内容。

## 2. W2-B：诊断运行与事务合同

### 2.1 保存、提交和锁定

- `saveDiagnosticDraft`只保存背景问卷、当前位置和未正式提交的界面草稿，不判分、不写Evidence候选。
- `submitDiagnosticAnswer`由服务端读取私有答案并确定性判分，写不可变`DiagnosticAnswerRecord`和Evidence候选。
- 同一`questionId + requestId`重复到达返回首次结果，不重复写候选。
- 同一题已经`answered`或`skipped`后，使用不同`requestId`再次提交返回`diagnostic_answer_conflict`；首次结果不覆盖。
- 跳过是显式提交，状态为`skipped`，不创建Evidence候选、不写0分，并把该题的知识点加入本次诊断快照的`insufficientKnowledgePointIds`；同一知识点重复跳过时只保留一个ID。
- 被跳过知识点没有其他有效直接Evidence时保持`mastery=null/confidence=0/unverified`；已经存在其他有效直接Evidence时仍按11号公式正常计算，跳过本身不参与分数或置信度计算。
- 诊断Evidence权重只能沿用11号定义的Evidence来源权重；题面、答案和运行记录均不得增加题目自定义权重字段。

### 2.2 完成和批量提交

Pandas诊断只有在8至12题全部处于`answered`或`skipped`后才能完成。`completeDiagnostic`必须：

```text
读取不可变答案与候选
→ 校验blueprint/profile/diagnostic/session版本
→ 一次重算全部KnowledgeState
→ 调用一次LearningSessionRepository.commit
→ 使用evidenceCandidates批量公开正式Evidence
→ 原子替换latest.json并保存latestDiagnostic/LearnerDiagnostic快照
→ 异步请求五维初始画像
```

有一条以上答题Evidence时使用非空`evidenceCandidates`，全部候选共享一个新`evidenceVersion`；全部题均跳过时省略Evidence批量且`evidenceVersion`保持原值。两种完成均必须携带`diagnosticCandidate`，只递增一次`sessionVersion`，并通过`latestDiagnostic/committedDiagnosticId`返回已提交快照身份。任一候选无效、版本冲突或存储失败时整批拒绝，正式Evidence、版本、KnowledgeState和诊断快照均保持原值。五维画像失败不回滚已经成功的确定性完成事务。
