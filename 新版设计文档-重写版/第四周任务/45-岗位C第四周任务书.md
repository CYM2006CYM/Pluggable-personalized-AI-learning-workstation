# 45 岗位C第四周任务书

> 所有权：Bootstrap基础设施、Node HTTP、Demo启动器和服务端安全
>
> 正常上传：D3，必须消费A/B/D正式提交

## 0. 开工输入

C可在D1—D2准备Node内建HTTP和进程管理的独立骨架，但不得封存正式路由、复制DTO或上传。D3正式实现前必须拉取A、B、D三个正式提交，报告各完整哈希，并核对：A的Facade/contracts和激活事务可导入、B的revision 3 seal可复算、D的两个端口实现与录制响应可绑定。缺一项只允许完成不依赖它的本地测试，不得用C自造stub冒充正式联调PASS。

开工必读20号D54—D60、42号第6、8、9节、41号调度、A/B/D交接单和09号架构边界。C只组合既有公共入口；发现入口缺失时向对应所有者提交最小HTTP反例。

## 1. 一次性交付目标

把A的应用用例、B的revision 3资产和D的录制响应接成本机可启动服务；从干净`.demo-data`提供安全Bootstrap与学习API。C不重写确定性业务规则，不修改前端页面。

## 2. 必做实现

1. **D3：**实现`AppBootstrapFacade`只读适配：安全Profile、目标、章节、完整诊断信封、可恢复会话和`SessionRecoverySafeView`；刷新恢复不得依赖浏览器内存。
2. **D3：**使用Node内建HTTP实现路由适配，每个资源化路由只调用一个Facade用例；请求上限64KiB。
3. **D3：**严格实现42号HTTP状态映射，业务fail/insufficient/path_infeasible/evaluator故障不得映射为4xx/5xx。
4. **D3：**`npm run demo`默认`.demo-data`和录制响应；显式`PI_STUDY_DATA`才覆盖。
5. **D3：**无active时调用A的仓储事务激活revision 3；active revision 3同seal时幂等复用；遇到其他active或不同seal时停止并输出安全迁移提示。C不得复制Profile目录、手改manifest或另算一套seal。
6. **D3：**`demo:live`才读取三个`OPENAI_*`变量；Key不得进入日志、进程参数证据或文件。
7. **D3：**API固定4310、Vite固定5173；端口占用直接失败，不漂移、不杀外部进程。
8. **D3：**API ready后启动Vite；任一子进程退出或终止时关闭同组另一个进程。
9. **D3：**服务端序列化使用A的contracts白名单，不把仓储对象直接返回；在组合根绑定D实现的`AdaptiveContentPort/CapabilityTaskPort`。

## 3. 执行顺序

1. 先实现无业务逻辑的请求解析、64KiB限制、loopback绑定、统一响应信封和进程生命周期测试。
2. 拉取正式上游后建立组合根：仓储和确定性用例来自A、active资产来自B、动态端口和录制响应来自D；不得复制上游实现到C目录。
3. 接入Bootstrap和资源化路由，逐路由核对“一个路由只调用一个Facade短用例”及42号状态码矩阵。
4. 完成revision 3首次激活、同seal复用和其他active阻断；迁移只返回提示，不提供C自有迁移命令。
5. 完成`demo`/`demo:live`、API ready后启动Vite及双进程联动关闭，再运行干净`.demo-data`HTTP主链。
6. 最后执行响应、日志、错误和启动参数泄漏扫描，并向E交付端点表、启动命令、安全DTO示例和可复现测试种子。

## 4. 集成与安全测试

- 空`.demo-data`首次启动、同seal二次启动、其他active阻断三条轨迹。
- `/api/bootstrap`无会话、有可恢复会话、指定恢复会话和不存在资源；恢复视图分别覆盖诊断草稿、路径游标和进行中Attempt。
- 请求过大、坏JSON、错误Content-Type、语义错误、CAS冲突、存储故障、初始化未就绪的状态码。
- 从HTTP完成问卷、推荐诊断或章节直达、建路、确认、题组打开/提交、刷新恢复、下一活动推进。
- 响应和日志扫描答案、private、hidden、Rubric、reference solution、Key和绝对路径零命中。
- Python评测器集成单独登记；客观题HTTP主链不依赖本机Python。
