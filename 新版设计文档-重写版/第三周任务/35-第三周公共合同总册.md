## 5. 公共结果和C内部协议

21号合同A的精简`ActivityResult`是唯一跨边界结果，源码只从领域类型导入。`CodeEvaluationPort`固定为：

```ts
interface CodeEvaluationPort {
  prepare(input: PrepareEvaluationInput): Promise<PreparedEvaluation>;
  run(input: RunEvaluationInput, signal: AbortSignal): Promise<ActivityResult>;
}
```

C内部可以保留prepare、user_code、public_tests、hidden_tests、summarize五阶段、完整Rubric明细、阻断断言和裁剪前运行材料，但必须在端口内确定性映射为公共结果。C源码不得依赖Attempt、Evidence、KnowledgeState或PathRepository，不得创建正式事实。隐藏测试、完整Rubric、参考实现、私有CSV和宿主路径不得进入公共结果、普通日志、Agent上下文或浏览器。

## 7. 正式提交事务

```text
openActivity创建attemptId
→ saveActivityDraft
→ prepareActivityRun
→ CodeEvaluationPort返回公共ActivityResult
→ A映射Attempt/Evidence候选
→ UnitOfWork原子commit
→ KnowledgeState
→ 路径未完成后缀和checkpoint
```

- 同一`requestId + attemptId`及相同内容重复提交返回首次结果，不重复计分。
- 同一幂等身份但内容、版本或绑定不同，返回`idempotency_conflict`。
- 修改代码重新正式提交必须创建新attemptId。
- 每个提交阶段故障均不得留下半写入或重复Attempt/Evidence。
- 只有确定通过、部分正确和学习者错误可生成正式Evidence；依赖、环境、测试资产或协议故障不生成负Evidence、不降低mastery、不触发路径重算。
