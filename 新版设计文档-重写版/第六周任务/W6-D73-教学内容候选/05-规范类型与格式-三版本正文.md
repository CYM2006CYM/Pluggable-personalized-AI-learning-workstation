**需要掌握**

2. 按`YYYY-MM-DD`严格转换无时区日期。
3. 规范城市、状态和字符串列，同时保留未知城市。
4. 验证结果dtype、允许值、输入不可变和重复运行稳定性。

### 先建立直觉：统一外形，才能可靠计算

公开订单中的金额可能写成`88`、`"¥1,200.50"`、`"￥2,000"`、`N/A`、`Infinity`或空白。人眼大致能猜出哪些是金额，但程序不能在每次计算时重新猜。类型规范化要把合法金额转换成真正的数值，把无法证明的内容变成缺失，并保留订单行。

日期、城市和状态也存在同类问题。`上海市`、`沪`和`上海`指向同一规范城市；`Completed`与` completed `应归一成`completed`；`2026/01/06`看起来像日期，却不符合冻结格式。规范化不是把数据“改得好看”，而是把同一含义统一成可验证表示。

### 把金额拆成两个步骤

第一步只整理文本，移除获批的货币符号、千位逗号和空格：

```python
amount_text = result["amount"].astype("string")
amount_text = amount_text.str.replace(r"[¥￥,\s]", "", regex=True)  # 只移除合同允许字符
```

第二步把合法文本转数值，非法内容变成缺失：

```python
amount = pd.to_numeric(amount_text, errors="coerce")  # N/A等无法转换时为缺失
amount = amount.replace([float("inf"), float("-inf")], pd.NA)  # 无穷值也不是有效金额
result["amount"] = amount
```

`errors="coerce"`不是“忽略错误”，而是把失败结果统一成可检查的缺失。它不会把非法金额改成0，也不会删除订单。

金额管线必须分两段，是因为文本清理和数值判定解决不同问题。货币符号与千位逗号属于可恢复的表示差异，去掉后仍能得到原金额；`N/A`和任意非法文字没有可证明数值，只能降级为缺失。若直接对原文本调用数值转换，可恢复金额也会被误判；若直接使用正则提取数字，可能把`abc12`错误变成12。

```python
raw = pd.Series(["¥1,200.50", "abc12", "0"], dtype="string")
cleaned = raw.str.replace(r"[¥￥,\s]", "", regex=True)
numeric = pd.to_numeric(cleaned, errors="coerce")
```

真实0会保留为0，`abc12`不会因含数字就被接受。这体现“只移除批准字符，不猜测剩余内容”。

【术语注释：数值类型】能够参与加减、比较和统计的数字表示。文本`"88"`和数值`88`看起来相似，但运算行为不同。

### 严格处理日期

资料包只接受`YYYY-MM-DD`，因此代码要显式提供格式：

```python
result["order_date"] = pd.to_datetime(
    result["order_date"],
    format="%Y-%m-%d",  # 四位年-两位月-两位日
    errors="coerce",    # 格式错误或不存在的日期转缺失
)
```

`2026-01-03`有效，`2026/01/06`、`01-11-2026`、`2026-02-30`无效。转换结果不带时区，因为订单合同只表示本地日历日期，没有声明UTC或地区偏移。

【术语注释：无时区日期时间】日期时间值没有附带UTC偏移或地区时区。没有来源依据时，不能自行加时区。

### 城市映射：只改已登记别名

先转可空字符串并去空格，再应用有限映射：

```python
CITY_MAP = {
    "上海市": "上海", "沪": "上海",
    "北京市": "北京", "京": "北京",
    "广州市": "广州", "穗": "广州",
}
city = result["city"].astype("string").str.strip()
result["city"] = city.replace(CITY_MAP)
```

`深圳`没有映射需要，保持`深圳`；`未知城`也必须保留，而不是自动改成缺失或最近城市。有限映射体现“有证据才改变”。

### 状态规范：先整理，再检查允许集合

状态先处理首尾空格和大小写，使同一合法状态具有统一形式；再用封闭集合判断，集合外内容转缺失。

```python
VALID_STATUS = {"completed", "pending", "cancelled"}
status = result["status"].astype("string").str.strip().str.lower()
result["status"] = status.where(status.isin(VALID_STATUS), pd.NA)
```

`Completed`、` completed `都会变成`completed`；`shipped`不在允许集合，变成缺失但保留订单。不能因为`shipped`听起来合理就临时加入集合。

【术语注释：允许集合】合同明确列出的合法取值范围。集合之外的值不能靠猜测自动纠正。

### 统一字符串列

金额和日期有专门dtype，其余五列统一成pandas可空字符串。统一表示不改变每列各自的缺失规则。

```python
STRING_COLUMNS = ["order_id", "customer_id", "city", "status", "note"]
for column in STRING_COLUMNS:
    result[column] = result[column].astype("string")  # 使用pandas StringDtype
```

`StringDtype`能统一文本操作并保留`pd.NA`，比混杂的Python`object`列更容易验证。`note`在上一节已经将缺失变为空字符串，这里只确保dtype一致。

### 跟着公开值看转换

下面的公开小样例同时覆盖可恢复文本、非法文本、别名、未知城市、大小写和非法状态，便于逐字段观察。

```python
probe = pd.DataFrame({
    "amount": ["¥1,200.50", "N/A", "Infinity", " 77 "],
    "order_date": ["2026-01-03", "2026/01/06", "2026-02-30", None],
    "city": ["上海市", "京", "未知城", "深圳"],
    "status": [" Completed ", "CANCELLED", "shipped", None],
})
```

预期金额依次为1200.5、缺失、缺失、77；日期只有第一条有效；城市依次为上海、北京、未知城、深圳；状态依次为completed、cancelled、缺失、缺失。先写预期再运行，能判断每条规则是否真实生效。

运行后不要只打印整张表，要把关键列前后并排解释。`未知城`仍在说明有限映射没有越权；`shipped`变缺失说明状态集合生效；`Infinity`变缺失说明数值有限性检查完整。每个变化都能对应一条公开规则。

```python
before_after = pd.DataFrame({
    "amount_before": probe["amount"],
    "amount_after": result["amount"],
    "city_before": probe["city"],

print(before_after)
```

### 缺失不是失败，而是拒绝猜测

转换后缺失数量可能增加，因为非法金额、非法日期和非法状态被明确识别。这是清洗规则的正常结果，不应统一显示成程序错误。真正的实现失败包括：可恢复金额被误判、严格无效日期被接受、未知城市被丢弃、非法状态被默认，或行数发生变化。

例如`2026-02-30`不是存在的日期，转缺失比自动改成2月28日更诚实；`Infinity`在数学上有表示，但不满足普通订单金额意义；`shipped`可能在其他业务合法，却不在当前冻结集合。系统不能用通用常识覆盖资料包合同。

### 字符串整理的细节

城市和状态明确要求去首尾空格；订单号已在缺失阶段规范；备注缺失已转空字符串。`customer_id`仍可保持缺失。统一StringDtype后，缺失继续是`pd.NA`，不会被文本化为`"nan"`。

```python
customer = result["customer_id"].astype("string").str.strip()
note = result["note"].astype("string").fillna("").str.strip()
result["customer_id"] = customer
result["note"] = note
```

这里不改变客户号内部格式，也不改写备注语义，只执行公开的首尾空格与缺失规则。

### 哪里容易错

#### 直接astype(float)

含货币符号和`N/A`时会抛错，也没有表达非法值策略。

```python
result["amount"] = result["amount"].astype(float)  # 错误
result["amount"] = pd.to_numeric(amount_text, errors="coerce")  # 正确
```

#### 宽松猜日期

省略格式会让解析器根据样本猜测，斜杠日期或月日顺序可能在不同环境中得到不同结论。

```python
pd.to_datetime(result["order_date"], errors="coerce")  # 风险：自动猜格式
pd.to_datetime(result["order_date"], format="%Y-%m-%d", errors="coerce")  # 正确
```

#### 未知城市全部转缺失

`map`只认识映射表中的键，未登记城市通常会变缺失，违反“未知非空值保留”规则。

```python
result["city"] = city.map(CITY_MAP)       # 错误：未知城市会丢失
result["city"] = city.replace(CITY_MAP)   # 正确：只替换已知别名
```

#### 非法状态默认pending

非法状态表示当前值不可接受，不等于可以推导为待处理。填默认值会伪造业务进度。

```python
result["status"] = status.where(status.isin(VALID_STATUS), "pending")  # 错误
result["status"] = status.where(status.isin(VALID_STATUS), pd.NA)       # 正确
```

#### 修改输入

类型转换涉及多列赋值，必须先复制并在结束后证明调用者输入仍与快照相同。

```python
before = df.copy(deep=True)
result = normalize_types(df)
assert df.equals(before)  # 所有转换只发生在结果副本
```

### 为什么转换顺序要清楚

文本去空格应在城市映射和状态集合检查之前，否则`" completed "`无法命中。金额先去符号再转数值，否则`to_numeric`会把本来可恢复的金额也判成缺失。日期必须直接按冻结格式解析，不能先把分隔符全部替换成横线，因为那会把原本不接受的格式伪装成合法输入。

列之间也有顺序边界。去重阶段已经使用严格日期副本选择获胜记录，类型阶段只转换选中记录的正式日期列；不能在类型转换后重新去重，否则某些无效日期的排名语义可能被悄悄改变。每个阶段只消费上一步输出，不回头重做前一步决策。

### 输入、行数和行序不变量

本节只改变字段表示，不删除、不新增、不排序记录。转换前后行数、索引和订单号序列应一致。若结果少行，通常是错误使用`dropna`；若顺序改变，说明混入排序；若输入dtype改变，说明直接在原表赋值。

```python
before_ids = result["order_id"].copy()
before_index = result.index.copy()
# 执行类型规范化
assert result.index.equals(before_index)
assert result["order_id"].equals(before_ids.astype("string"))
```

订单号dtype统一可能改变表示类型，因此比较时要考虑获批规范，但值和顺序不能变化。

### 如何解释结果

非法金额和日期转缺失不表示程序失败，而表示系统拒绝猜测。未知城市被保留，说明合同允许开放文本；非法状态转缺失，说明状态是受限枚举。教学页面应逐字段解释这种差别。

```python
summary = {
    "amount_missing": int(result["amount"].isna().sum()),
    "date_missing": int(result["order_date"].isna().sum()),
    "status_missing": int(result["status"].isna().sum()),
}
```

摘要只记录数量，不展示私有值，也不产生正式Evidence。

本节是最后一个允许修改业务列表示的阶段。完成后下一节只能验证，不得再填值、改城市或重排记录。

```python
typed = normalize_types(dedupe_ready)
validated = validate_orders(typed)
```

类型阶段完成后，金额可计算、日期可比较、城市与状态可稳定验证、字符串列dtype一致。下一节不再修数据，而是检查这些不变量是否全部成立。

### 术语与依据

- **coerce**：转换失败时统一产生缺失。
- **无穷值**：超出普通有限数值意义的`inf/-inf`，本合同视为非法金额。
- **StringDtype**：pandas可空字符串类型。
- **允许集合**：合同列出的合法枚举值。
- **有限映射**：只替换明确登记的别名，未知值保持原样。

## 版本二：重点速览 `concise`

### 学习目标

**需要了解**

1. 字段规范化是从原始表示到合同表示的确定性映射。
2. 严格解析、有限映射、允许集合和可空dtype的边界。
3. 缺失、非法、未知和真实0值不能混为一类。

**需要掌握**

1. 为金额、日期、城市、状态和字符串列实现独立转换管线。
2. 用向量化操作避免逐行猜测和隐式默认值。
3. 验证dtype、有限值、时区、枚举和输入不可变。
4. 形成字段级转换摘要并准确归因失败。

### 字段转换矩阵

金额：清理文本→数值转换→排除无穷。日期：严格格式→无时区datetime。城市：去空格→有限replace。状态：去空格→小写→允许集合。字符串：统一`StringDtype`。每列只有一个明确管线。

### 金额管线

金额转换分为可恢复文本清理、数值转换和有限值过滤，三步分别对应不同失败来源。

```python
text = result["amount"].astype("string").str.replace(r"[¥￥,\s]", "", regex=True)
amount = pd.to_numeric(text, errors="coerce")
result["amount"] = amount.replace([float("inf"), float("-inf")], pd.NA)
```

`errors="coerce"`处理`N/A`和其他非法文本，显式replace处理`Infinity`。0和负数是有限数值，合同没有要求在本节删除；不能根据个人业务常识增加范围规则。

### 日期管线

日期使用唯一声明格式，并显式验证结果没有时区信息，防止环境或个人习惯改变合同。

```python
result["order_date"] = pd.to_datetime(
    result["order_date"], format="%Y-%m-%d", errors="coerce"
)
assert getattr(result["order_date"].dtype, "tz", None) is None
```

固定格式确保版本和地区差异不影响结论。无时区断言防止实现自行添加UTC。

### 城市与状态管线

城市是开放文本加有限别名映射，状态是封闭枚举；两列看似都是字符串，非法值策略却相反。

```python
city = result["city"].astype("string").str.strip()
result["city"] = city.replace(CITY_MAP)  # 未登记城市保留

status = result["status"].astype("string").str.strip().str.lower()
result["status"] = status.where(status.isin(VALID_STATUS), pd.NA)
```

`replace`和`map`不能互换使用：map对无映射键通常产生缺失，而合同要求未知非空城市保留。状态恰好相反，它是封闭集合，集合外值必须缺失。

### StringDtype统一

最后把五个文本字段统一为可空字符串类型，便于后续做精确dtype和缺失比较。

```python
for column in ["order_id", "customer_id", "city", "status", "note"]:
    result[column] = result[column].astype("string")
```

统一dtype不代表统一缺失策略。`note`为空字符串，`customer_id/status`可为`pd.NA`，只是这些列共享字符串表示能力。

### 顺序与输入边界

先建立结果副本，字符串整理先于映射和枚举，金额清理先于数值转换。各列相互独立，转换不应改变行数和行序。

```python
before = df.copy(deep=True)
result = df.copy(deep=True)
before_index = result.index.copy()
# 执行字段转换
assert result.index.equals(before_index)
assert df.equals(before)
```

### 规范表示与业务值的区分

规范化可以改变表示，不能无依据改变含义。`"¥1,200"→1200`是等价表示转换；`"沪"→"上海"`来自登记别名；`" Completed "→"completed"`来自允许状态规则。相反，`N/A→0`、`shipped→pending`、`未知城→pd.NA`都会改变或丢失业务含义。

```python
approved_changes = {
    "¥1,200": 1200,
    "沪": "上海",
    " Completed ": "completed",
}
```

实现审计应逐项问：改变是否有公开规则？原始未知是否仍可观察？若答案是否定的，转换即使让表更整齐也不合格。

### 单一事实源

城市映射、状态集合、日期格式和字符串列清单不能散落成互相不同的常量。教学正文、Profile资产和运行代码应引用同一冻结语义。若未来增加状态或城市别名，必须先更新资料包来源与seal，而不是在某个页面组件里偷偷增加替换。

当前版本可在模块内部使用公开常量，但测试要比较它们和Profile规则，防止正文写一套、执行器跑另一套。三套个性化正文的例子可以不同，合法集合必须相同。

类型阶段不是筛选阶段。任何行数变化都应视为回归。

### 验证矩阵

dtype只是第一层，取值集合、有限性和未知城市保留还要分别断言。下面的检查组合覆盖主要公共出口。

```python
assert result["amount"].dtype.kind in "fiu"
assert getattr(result["order_date"].dtype, "tz", None) is None
assert set(result["status"].dropna().astype(str)) <= VALID_STATUS
for column in STRING_COLUMNS:
    assert str(result[column].dtype) == "string"
```

还需检查金额不存在正负无穷、城市映射和未知保留均正确、日期格式错误转缺失。只看dtype不足以证明取值规则。

```python
finite_amount = result["amount"].dropna().map(lambda value: float("-inf") < value < float("inf"))
assert finite_amount.all()
```

### 反例矩阵

以下四种短写法分别破坏金额、日期、城市和状态规则，不能用“运行未报错”作为正确依据。

```python
result["amount"].astype(float)  # 含符号时失败
pd.to_datetime(result["order_date"])  # 宽松猜测
city.map(CITY_MAP)  # 未知城市丢失
status.fillna("pending")  # 伪造默认状态
```

正确写法分别是清理后`to_numeric(coerce)`、带format的`to_datetime`、有限`replace`和非法状态转`pd.NA`。四个错误来自四种不同合同边界，不能用一个笼统异常替代。

### 错误归因

金额仍为字符串通常是清理或赋值遗漏；`Infinity`仍存在说明有限值检查缺失；斜杠日期被接受说明格式未固定；未知城市变缺失说明误用map；`shipped`被保留说明枚举检查缺失；输入变化说明副本边界错误。

```python
summary = {
    "numeric_amount": result["amount"].dtype.kind in "fiu",
    "timezone_free_date": getattr(result["order_date"].dtype, "tz", None) is None,
    "valid_status_only": set(result["status"].dropna().astype(str)) <= VALID_STATUS,
}
```

### 字段级失败保持

转换函数应先在独立副本上完成全部字段，再把完整结果返回。如果处理状态时发生错误，调用者仍持有原始输入，不会得到只转换了金额和日期的半成品。Demo无需建设复杂事务，但必须避免部分结果冒充正式完成。

```python
before = df.copy(deep=True)
try:
    candidate = normalize_types(df)
finally:
    assert df.equals(before)
```

上层只有在函数完整返回并通过验证后才使用candidate。异常路径不生成判分结果，不修改Evidence和路径。

### 完成性判定

完成状态要求：金额为有限数值或缺失；日期为无时区datetime或缺失；城市已执行有限映射且未知值保留；状态仅含允许集合；五个字符串列为StringDtype；行数和行序不变；输入不变；重复运行稳定。任一维度缺失，都不能把本节写成通过。

只比较表面文本或只检查一条公开记录都不足。测试应同时包含合法、非法、缺失、别名、未知和边界值，且所有结论可以从公开规则复算。

### 幂等性

规范化结果再次运行应保持不变。货币符号已经移除，规范城市不会再次变化，小写状态仍在允许集合，严格日期列再次转换仍表达相同日期。

```python
again = normalize_types(result)
assert again.equals(result)
```

若重复执行把空值变成文本、日期丢失或dtype漂移，说明转换没有正确处理已规范输入。

### 相邻阶段边界

缺失阶段已处理订单号和备注，去重阶段已选择记录；本节不得删除行或重新选择重复项。下一节只验证，不应再替本节修复类型。职责分开后，每个错误都能回到唯一负责模块。

### 与最终任务连接

最终实操的类型维度要求金额为规范数值、日期无时区、字符串列为StringDtype、城市和状态符合公开规则。类型完成后交给最终不变量验证。

验证阶段若发现错误，应回到对应字段管线修改并重新运行完整转换，不能在断言前临时修值。这样才能证明实际输出而不是测试脚本制造的输出满足合同。

### 交付给验证阶段的事实

类型阶段应交付一张行数和顺序不变的DataFrame，以及一份字段级摘要。摘要说明金额和日期有多少值因规则失败而转缺失、非法状态数量、字符串dtype是否统一、城市映射版本和环境版本；它不包含私有订单正文。验证阶段据此知道应该检查哪些不变量，但仍以DataFrame实际内容为权威。若金额仍含无穷、日期带时区、状态集合外还有值、未知城市被删除、任一字符串列不是StringDtype，必须阻塞并回到本节修复。不能把这些问题登记为“仅显示差异”后继续最终提交，因为它们直接影响确定性判分和业务解释。

### 术语与来源

- **转换管线**：按固定顺序执行的一组字段转换。
- **向量化**：一次对整列执行操作，而非手工逐行循环猜测。
- **封闭集合**：只允许列出的值，其他值非法。
- **开放文本**：未知非空值可以保留，例如城市。
- **dtype漂移**：相同逻辑重复运行后类型意外变化。

来源同共同事实表。

## 版本三：案例实战 `practice`

### 学习目标

**需要了解**

1. 货币符号、非法日期、城市别名和状态大小写会怎样影响统计与验收。
2. 为什么未知城市保留、未知状态却要转缺失。
3. 类型转换失败如何明确降级而不删除订单。

**需要掌握**

1. 编写完整的字段规范化函数并保持行数、行序和输入不变。
2. 用公开订单样例验证金额、日期、城市、状态和字符串dtype。
3. 根据结果症状定位具体转换步骤。
4. 生成脱敏转换摘要并交给最终验证。

### 业务场景：表能打开，但金额无法求和

运营表中`amount`既有88，也有`¥1,200.50`、`N/A`和`Infinity`。直接求和会失败或得到不可靠结果。城市同时出现“上海市”“沪”，状态同时出现“Completed”“CANCELLED”和“shipped”。规范化的目的，是让相同含义具有相同表示，让非法或未知内容明确变成缺失。

### 第一步：创建结果副本

所有字段转换都在副本上执行，行数和顺序保持不变。

```python
result = df.copy(deep=True)
original_index = result.index.copy()
```

### 第二步：规范金额

先整理符号，再转数值，再排除无穷。

```python
amount_text = result["amount"].astype("string").str.replace(r"[¥￥,\s]", "", regex=True)
amount = pd.to_numeric(amount_text, errors="coerce")
result["amount"] = amount.replace([float("inf"), float("-inf")], pd.NA)
```

公开样例中`¥2,500`变2500，`N/A/NaN/Infinity`变缺失，真实0和负数保留。

### 第三步：严格解析日期

实战中明确写出格式，让错误日期稳定降级为缺失，并保留订单行。

```python
result["order_date"] = pd.to_datetime(
    result["order_date"], format="%Y-%m-%d", errors="coerce"
)
```

`2026-01-03`有效；`2026/01/06`、`01-11-2026`、不存在的`2026-02-30`变缺失。订单行仍然保留。

### 第四步：规范城市

城市先去首尾空格，再只替换登记别名。没有映射的非空城市必须原样保留。

```python
CITY_MAP = {"上海市": "上海", "沪": "上海", "北京市": "北京", "京": "北京", "广州市": "广州", "穗": "广州"}
city = result["city"].astype("string").str.strip()
result["city"] = city.replace(CITY_MAP)
```

深圳和未知城保持原值，因为合同没有授权猜测更多映射。

### 第五步：规范状态

状态先统一大小写与空格，再依据封闭集合保留或转缺失，不能生成默认状态。

```python
VALID_STATUS = {"completed", "pending", "cancelled"}
status = result["status"].astype("string").str.strip().str.lower()
result["status"] = status.where(status.isin(VALID_STATUS), pd.NA)
```

`shipped`和空状态变缺失，大小写和首尾空格被规范。

### 第六步：统一字符串dtype

完成各字段语义处理后，统一五个文本列的pandas字符串dtype，并确认行数和索引未变化。

```python
STRING_COLUMNS = ["order_id", "customer_id", "city", "status", "note"]
for column in STRING_COLUMNS:
    result[column] = result[column].astype("string")
```

完成后确认行数、索引和输入：

```python
assert result.index.equals(original_index)
assert len(result) == len(df)
```

### 先用公开记录预测结果

公开CSV提供了足够多的可观察边界：O001金额含货币符号和逗号，城市为上海市，状态有空格和首字母大写；O004金额为N/A、日期使用斜杠、城市为京；O007状态为shipped；O014城市为未知城；O016金额为真实0；O017日期不存在。运行代码前先写出每条预期，可以防止为了测试通过临时改规则。

```python
public_ids = ["O001", "O004", "O007", "O014", "O016", "O017"]
probe = result.loc[result["order_id"].isin(public_ids)]
print(probe[["order_id", "amount", "city", "order_date", "status"]])
```

预期O001金额1200.5、城市上海、状态completed；O004金额和日期缺失、城市北京；O007状态缺失；O014未知城保留；O016金额仍为0；O017日期缺失。每个结论都对应公开合同。

### 结果变化如何向用户解释

页面不能只显示“转换完成”。对于可恢复表示，可以说“去除货币符号后转为数值”；对于非法内容，可以说“无法按批准规则解释，已保留订单并将该字段标记为缺失”；对于别名，可以说“按登记映射统一”；对于未知城市，可以说“没有依据修改，保留原值”。

这种反馈让学习者理解系统不是任意美化数据，而是在证据边界内行动。缺失增加不一定是坏结果，它可能表示系统拒绝伪造。

### 行数与行序回归

类型阶段不负责删行或排序。可以保存订单号序列和索引，在转换后比较；这比只比较长度更强，因为长度相同仍可能重排。

```python
before_ids = dedupe_ready["order_id"].astype("string").tolist()
result = normalize_types(dedupe_ready)
after_ids = result["order_id"].astype("string").tolist()
assert after_ids == before_ids
```

如果该断言失败，应检查是否混入`dropna`、排序或重新去重，而不是调整预期顺序。

### 现场故障一：金额仍是文本

通常是只调用`to_numeric`却忘记先去货币符号和逗号，或转换结果没有写回。

```python
pd.to_numeric(result["amount"], errors="coerce")  # 错误：结果未接收
result["amount"] = pd.to_numeric(amount_text, errors="coerce")  # 正确
```

### 现场故障二：Infinity仍通过

`to_numeric`可以产生无穷数，它不是NaN，所以还要显式排除。

```python
result["amount"] = result["amount"].replace([float("inf"), float("-inf")], pd.NA)
```

### 现场故障三：斜杠日期被接受

斜杠日期仍显示为有效时间，说明代码省略了固定格式或提前替换了分隔符。

```python
pd.to_datetime(result["order_date"], errors="coerce")  # 错误：格式未冻结
pd.to_datetime(result["order_date"], format="%Y-%m-%d", errors="coerce")  # 正确
```

### 现场故障四：未知城消失

未知非空城市变成缺失，通常是使用`map`代替有限`replace`，导致未登记键没有输出。

```python
result["city"] = city.map(CITY_MAP)      # 错误：无映射值变缺失
result["city"] = city.replace(CITY_MAP)  # 正确：未知值保留
```

### 现场故障五：非法状态被默认

非法或空状态被统一成pending，会伪造订单进度。正确结果应是缺失并保留订单。

```python
result["status"] = status.fillna("pending")  # 错误：未知被伪造
result["status"] = status.where(status.isin(VALID_STATUS), pd.NA)
```

### 完整实战函数

前面步骤可以组合为一个职责明确的`normalize_types`函数。函数不删行、不去重，也不修复输入对象。

```python
def normalize_types(df):
    result = df.copy(deep=True)
    amount_text = result["amount"].astype("string").str.replace(r"[¥￥,\s]", "", regex=True)
    amount = pd.to_numeric(amount_text, errors="coerce")
    result["amount"] = amount.replace([float("inf"), float("-inf")], pd.NA)
    result["order_date"] = pd.to_datetime(result["order_date"], format="%Y-%m-%d", errors="coerce")
    result["city"] = result["city"].astype("string").str.strip().replace(CITY_MAP)
    status = result["status"].astype("string").str.strip().str.lower()
    result["status"] = status.where(status.isin(VALID_STATUS), pd.NA)
    for column in STRING_COLUMNS:
        result[column] = result[column].astype("string")
    return result
```

### 公开结果验证

完整函数返回后，从dtype、时区、状态集合、城市映射和输入不变多个角度验证，不能只看没有异常。

```python
result = normalize_types(dedupe_ready)
assert result["amount"].dtype.kind in "fiu"
assert getattr(result["order_date"].dtype, "tz", None) is None
assert set(result["status"].dropna().astype(str)) <= VALID_STATUS
assert df.equals(before)
```

城市可检查公开别名，未知城市必须仍在；字符串列逐项检查dtype。不要只验证代码没有抛异常。

### 字段级排错顺序

金额问题先打印清理后的文本，再看`to_numeric`结果和无穷过滤；日期问题先看原文本与严格解析；城市问题对比去空格值和映射后值；状态问题对比小写值与`isin`掩码。逐阶段观察比反复改一整段函数更快。

```python
print(amount_text.head())
print(status.head())
print(status.isin(VALID_STATUS).head())
```

排错输出只使用公开样例和有限摘要，正式日志不记录整列私有内容。

### 重复运行与恢复

已经规范的金额是数值，再次转字符串清理后仍应回到相同数值；规范日期再次严格解析应保持日期；规范城市和状态再次处理不应变化。幂等测试能发现空值被文本化或dtype漂移。

```python
again = normalize_types(result)
assert again.equals(result)
```

若第一次运行失败，输入副本未改，修复后从同一dedupe结果重试。中途临时列和部分转换不得写入正式Attempt结果。

### 故障恢复

转换失败或断言不通过时，原始输入仍在。修复代码后从同一`dedupe_ready`重跑，不使用已部分转换的临时结果。

```python
before = dedupe_ready.copy(deep=True)
result = normalize_types(dedupe_ready)
assert dedupe_ready.equals(before)
```

### 实战摘要

用数量说明哪些字段因不符合规则而降级为缺失，同时避免输出具体订单内容。

```python
summary = {
    "invalid_amount": int(result["amount"].isna().sum()),
    "invalid_date": int(result["order_date"].isna().sum()),
    "invalid_status": int(result["status"].isna().sum()),
}
```

摘要说明有多少内容被明确降级为未知，不记录原始订单详情。它是教学和调试观察，不改变学习者正式状态。

### 实战完成标准

现场必须证明金额可计算且无穷值不存在、日期严格且无时区、城市映射正确且未知值保留、状态集合闭合、字符串dtype统一、行数行序不变、输入不变。任何一项只在页面上写成标签却没有程序证据，都不能算完成。

类型阶段通过后，系统不再修改数据。若最终验证发现问题，应修复本函数并重新生成结果，而不是在验证代码中填值或排序制造通过。

交接时还要确认公开样例和完整固定数据都经过同一函数，而不是为演示页面单独准备一份已清洗表。只有真实输入、真实转换和真实验证使用同一事实链，现场结果才可复算。若某项转换只能靠手工修改后台文件完成，应明确判为未完成。

这一边界必须坚持。

### 接到最终验证

类型格式是最后一个修改数据的阶段。下一节应只检查七列、唯一性、缺失规则、dtype、允许值和行序，不再悄悄修数据。

```python
typed = normalize_types(dedupe_ready)
validate_orders(typed)
```

### 术语与来源

- **规范化**：把同一含义转换成统一表示。
- **严格格式**：只接受合同明确声明的格式。
- **有限值**：不是正负无穷的普通数值。
- **城市别名**：登记后可映射到规范城市名的文本。
- **枚举**：有限、明确的允许值集合。

API和字段规则来源同共同事实表。
