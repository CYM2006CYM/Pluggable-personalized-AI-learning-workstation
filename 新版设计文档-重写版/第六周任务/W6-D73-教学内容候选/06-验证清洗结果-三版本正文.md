## 版本一：逐步讲解 `guided`

### 学习目标

**需要了解**

1. “代码运行结束”和“结果满足合同”为什么是两件事。
2. 列、缺失、唯一性、dtype、允许值和行序分别验证什么。
3. 为什么验证阶段不能顺手修复数据或展示隐藏答案。

**需要掌握**

1. 编写清晰的结果不变量断言，并理解每条失败含义。
2. 使用`assert_frame_equal`比较DataFrame且不掩盖列序、dtype和行序。
3. 将失败归因到结构、缺失、去重或类型阶段。
4. 生成安全、可行动、可复算的公开反馈。

### 先建立直觉：最后一眼不能只看“长得像”

清洗代码没有抛异常，只能说明程序走到了结尾。结果可能少一列、列序错误、订单号重复、金额仍是文本、日期带时区，或者记录被按订单号重新排序。`head()`看起来整齐，也不能证明这些问题不存在。

验证阶段要把“合格结果”拆成一组机器可检查的不变量。每条不变量都有明确来源和失败责任。验证只做裁判，不再上场改数据；否则它可能在比较前把错误修掉，制造虚假的通过。

【术语注释：不变量】在处理完成后必须成立的条件，例如订单号唯一、列序固定。它不是某一行样例，而是对整个结果的约束。

### 为什么要分层验证

不同不变量之间存在依赖。列结构不正确时，继续访问`amount`可能只产生“找不到列”的次生错误；订单号为空时，唯一性结果也难以解释；dtype不正确时，数值范围比较可能失去意义。因此验证通常先结构、再关键键、再类型与取值、最后完整比较。

分层并不意味着只报告第一个错误后就忘记其他问题。公开交互可以先给学习者一个最可行动的错误，内部审计可以在安全边界内收集多个维度状态。重要的是任何汇总都不能越过前置失败写成整体通过。

```python
if clean_df.columns.tolist() != EXPECTED_COLUMNS:
    raise AssertionError("columns_invalid")  # 结构失败时先停止字段检查
```

### 断言是程序化教学目标

学习目标说“掌握固定七列、非空唯一订单号、正确dtype和行序”，断言把这些自然语言变成可重复执行的条件。每条断言应该只表达一项核心事实，失败信息指向负责小节。过于宽泛的`assert result_ok`无法告诉学习者哪里错，也不利于负责人复算。

```python
assert ids.notna().all(), "order_id_missing"
assert ids.is_unique, "duplicate_order_id"
```

断言文本仍是内部开发示例。正式公共反馈使用批准错误码和安全中文解释，不能直接把隐藏测试表达式回传页面。

### 第一层：固定七列和顺序

先定义唯一列清单，再做精确列表比较。正文先明确：集合相同但顺序不同仍不合格。

```python
EXPECTED_COLUMNS = [
    "order_id", "customer_id", "amount", "city",
    "order_date", "status", "note",
]
assert clean_df.columns.tolist() == EXPECTED_COLUMNS  # 名字和顺序同时检查
```

不能在断言前调用`reindex`或排序列。验证发现错序，应回到结构阶段修复实际输出。

### 第二层：订单号非空且唯一

缺失阶段负责非空，去重阶段负责唯一，验证阶段确认两项都真实成立。

```python
ids = clean_df["order_id"].astype("string").str.strip()
assert ids.notna().all()  # 没有缺失标记
assert ids.ne("").all()  # 没有空字符串
assert ids.is_unique      # 每个订单号只出现一次
```

若第一项失败，回到缺失处理；若唯一性失败，回到去重；验证不能现场删除重复行。

### 第三层：dtype和允许值

金额需要是真正数值，日期需要是无时区datetime，文本列需要使用StringDtype。

```python
assert clean_df["amount"].dtype.kind in "fiu"  # 浮点或整数数值
assert getattr(clean_df["order_date"].dtype, "tz", None) is None

for column in ["order_id", "customer_id", "city", "status", "note"]:
    assert str(clean_df[column].dtype) == "string"
```

状态还要检查值集合：

```python
VALID_STATUS = {"completed", "pending", "cancelled"}
actual_status = set(clean_df["status"].dropna().astype(str))
assert actual_status <= VALID_STATUS  # 结果集合必须是允许集合的子集
```

dtype正确不保证值合法，值合法也不保证dtype正确，两类断言不能互相替代。

### 第四层：金额有限、字段缺失语义正确

无穷数虽然属于浮点表示，却不是有效订单金额。可以逐值确认所有非缺失金额有限。

```python
finite = clean_df["amount"].dropna().map(
    lambda value: float("-inf") < value < float("inf")
)
assert finite.all()
```

`customer_id`允许缺失，`note`不应再保留缺失标记。验证不能统一要求整表零缺失。

```python
assert clean_df["note"].notna().all()  # 备注缺失已转空字符串
# customer_id/amount/order_date/status仍允许按合同缺失
```

### 第五层：行序与索引

合同要求保持被选记录原始相对顺序。索引标签本身可以在比较前重置，但记录不能排序。

```python
actual = clean_df.reset_index(drop=True)   # 只重建0..n-1索引
expected = expected_df.reset_index(drop=True)
pd.testing.assert_frame_equal(actual, expected)
```

`reset_index`不会改变行的先后，只改变行标签；`sort_values`会改变记录顺序，不能在比较前使用。

【术语注释：assert_frame_equal】pandas提供的DataFrame比较工具，可以同时检查值、列、dtype、索引等结构。

### 跟着一个错误结果逐层检查

假设结果七列齐全，订单号唯一，但`amount`仍是字符串，O011被放到表尾。只检查列和唯一性会通过，dtype和完整DataFrame比较会失败。这说明验证必须覆盖多个维度。

```python
checks = {
    "columns": clean_df.columns.tolist() == EXPECTED_COLUMNS,
    "unique_id": bool(ids.is_unique),
    "numeric_amount": clean_df["amount"].dtype.kind in "fiu",
}
print(checks)
```

检查摘要帮助定位，但最终仍由断言决定。不能看到三个True就忽略剩余维度。

### 哪里容易错

#### 只比较行数

两张表行数相同，值、列序和dtype仍可能完全不同。

```python
assert len(actual) == len(expected)  # 不充分
pd.testing.assert_frame_equal(actual, expected)  # 完整比较
```

#### 比较前自动排序

排序会把错误行序隐藏掉。

```python
actual = actual.sort_values("order_id")    # 错误：修改被验证对象
expected = expected.sort_values("order_id")
```

```python
pd.testing.assert_frame_equal(actual.reset_index(drop=True), expected.reset_index(drop=True))
```

#### 比较前填空

填空会改变未知值语义，使错误结果在进入比较器前被人为修正，因此验证阶段禁止这样做。

```python
actual = actual.fillna(0)  # 错误：验证器改写未知值
```

正确做法是让缺失差异明确失败，再回到负责字段处理的阶段。

#### 只看values忽略dtype

把所有值转成字符串可能让数值88与文本`"88"`看起来相同，却掩盖后续计算能力差异。

```python
assert actual.astype(str).equals(expected.astype(str))  # 错误：类型差异被抹平
```

应保留原dtype交给`assert_frame_equal`。

### 失败归因

列错误回到结构检查；空订单号回到缺失处理；重复订单或错误获胜者回到去重；金额、日期、城市、状态和StringDtype回到类型格式；行序错误通常回到去重恢复步骤。验证反馈指出维度，不展示私有断言内容。

```python
public_feedback = {
    "dimension": "type_format",
    "code": "amount_dtype_invalid",
}
```

### 一次失败怎样回到正确学习内容

错误码和知识点映射必须由固定表决定。例如`columns_invalid`回到结构检查，`duplicate_order_id`回到去重，`date_invalid`回到类型格式。AI可以把原因解释得更自然，却不能把日期错误推荐成CSV读取问题，也不能修改mastery。

```python
REMEDIATION = {
    "columns_invalid": "pandas.clean.inspect-dataframe",
    "duplicate_order_id": "pandas.clean.duplicate-orders",
    "date_invalid": "pandas.clean.type-format",
}
```

如果多个维度失败，应优先处理最靠前的根因，再重新运行完整流水线。不要在一个错误结果上连续打补丁，因为后续现象可能只是前置错误造成的。

### 验证器为什么不能返回修补结果

若`validate_orders`发现列序错误后自动重排，调用者看到的将是验证器制造的新表，而不是学习者代码的真实输出。正式判分便无法回答学习者实际掌握了什么。验证器应返回结论或抛出受控错误，被验证对象保持原样。

```python
before = clean_df.copy(deep=True)
try:
    validate_orders(clean_df)
finally:
    assert clean_df.equals(before)
```

失败结果可以保存为Attempt的一部分用于恢复，但不能产生伪造的通过Evidence。修正后新Attempt重新运行清洗和验证。

### 怎样人工复算主要结论

负责人或评委不需要阅读所有测试源码，也能根据公开规则复算核心事实：查看列名列表；统计订单号缺失与重复；查看dtype；列出非空状态集合；确认金额无无穷；比较获胜记录顺序。结构化摘要应提供这些分子、分母或布尔状态。

```python
audit = {
    "rows": len(clean_df),
    "columns": clean_df.columns.tolist(),
    "duplicate_ids": int(ids.duplicated().sum()),
    "statuses": sorted(set(clean_df["status"].dropna().astype(str))),
}
```

摘要不提供私有CSV内容和隐藏预期，但足以证明验证不是静态绿灯页面。

### 安全边界

公开反馈可以说“金额类型不符合要求”或“订单号仍重复”，不能显示hidden test文件、具体私有订单号、参考实现和完整Rubric。测试代码也不能执行输入中携带的任意程序。

```python
safe_message = "金额列尚未转换为规范数值，请回到类型与格式步骤。"
```

### 刷新和失败后的事实

页面刷新只能重新读取服务端保存的Attempt和判分结果，不能凭浏览器缓存把旧红灯改成绿灯。评测器异常时应显示“本次未判分”，保留草稿并允许重试；学习者测试失败则保留真实失败维度。两类错误都不能用同一个“提交成功”文案。

验证代码本身不依赖实时模型，所以`LIVE_MODEL=LIVE_NOT_RUN`不会阻断正式判分。Agent解释失败时，固定安全反馈仍可从错误码生成。

### 接到最终提交

验证是完整流水线的最后一步。全部不变量通过后，`clean_df`才可作为正式活动结果；失败时不应半写入Evidence或推进路径。

```python
clean_df = clean_orders(raw_df)
validate_orders(clean_df)  # 只验证，不返回修补后的另一张表
```

### 术语与依据

- **不变量**：处理完成后必须成立的条件。
- **断言**：条件不成立时明确失败的程序检查。
- **子集**：结果状态集合中的每个值都属于允许集合。
- **索引**：DataFrame的行标签，不等同于记录业务顺序。
- **安全反馈**：能指导修改但不泄漏私有评测资产的信息。

DataFrame比较绑定`src-pandas-testing`，执行和反馈安全绑定`src-python-security`，最终不变量绑定revision 3公开合同。

## 版本二：重点速览 `concise`

### 学习目标

**需要了解**

1. 最终验证应覆盖结构、键、类型、取值、缺失、顺序和副作用。
2. 验证器修数据会破坏证据可信度。
3. 公开反馈与私有评测细节的安全分界。

**需要掌握**

1. 构建分层不变量集合并准确映射失败维度。
2. 使用`assert_frame_equal`执行严格DataFrame比较。
3. 检查输入/结果不可变边界和失败保持性。
4. 输出安全错误码与可行动中文反馈。

### 验证维度矩阵

结构：七列及顺序。键：`order_id`非空唯一。类型：金额数值、日期无时区、五列StringDtype。取值：状态集合、城市映射和有限金额。缺失：备注非缺失、其他列按合同允许。顺序：获胜记录原始相对顺序。副作用：验证不修改结果。

每个维度需要独立断言，不能用总行数或一个DataFrame截图替代。

### 快速结构与键门禁

先验证决定后续检查能否安全执行的字段。

```python
assert clean_df.columns.tolist() == EXPECTED_COLUMNS
ids = clean_df["order_id"].astype("string").str.strip()
assert ids.notna().all() and ids.ne("").all() and ids.is_unique
```

列缺失时继续访问字段只会产生次生错误，所以结构应优先。

### 类型和取值门禁

类型门禁确认数据是否具有合同要求的计算和比较能力，取值门禁确认内容是否落在允许范围，两者必须组合。

```python
assert clean_df["amount"].dtype.kind in "fiu"
assert getattr(clean_df["order_date"].dtype, "tz", None) is None
assert set(clean_df["status"].dropna().astype(str)) <= VALID_STATUS
for column in STRING_COLUMNS:
    assert str(clean_df[column].dtype) == "string"
```

金额还需有限值，城市需验证登记别名和未知保留，日期无效值应为缺失。dtype门禁只是类型维度入口。

### 严格DataFrame比较

有确定性期望表时，使用官方比较工具，而不是逐列手工拼接宽松规则。

```python
pd.testing.assert_frame_equal(
    actual.reset_index(drop=True),
    expected.reset_index(drop=True),
    check_dtype=True,
    check_like=False,  # 不忽略列或行布局
)
```

`check_like=False`保持布局敏感；重置索引只忽略标签差异，不排序记录。数值容差只能使用合同批准值，不能为通过测试不断扩大。

### 精确比较与数值容差

字符串、列名、状态和行序通常要求精确相等；浮点金额可能按合同使用极小容差。容差只解决浮点表示误差，不能让1200和1201被视为同值，也不能用于日期或字符串。

```python
pd.testing.assert_frame_equal(
    actual.reset_index(drop=True),
    expected.reset_index(drop=True),
    rtol=0,
    atol=0.000001,  # 只使用冻结的小数容差
)
```

若当前比较合同要求完全精确，则继续使用默认或明确零容差。测试不能在看到失败后临时放宽。

### 验证器纯度

验证前后对象应相同。可以保存深拷贝并在结束后比较，防止断言代码使用`fillna/sort_values/astype`改写结果。

```python
before = clean_df.copy(deep=True)
validate_orders(clean_df)
assert clean_df.equals(before)
```

验证函数最好返回结构化结论或抛出受控错误，不返回一张“修好后的表”。

### 反例矩阵

这些“方便比较”的操作都会降低证据强度，可能把真实错误变成表面相等。

```python
len(actual) == len(expected)                     # 忽略内容
set(actual.columns) == set(EXPECTED_COLUMNS)     # 忽略列序
actual.astype(str).equals(expected.astype(str))  # 忽略dtype
actual.sort_values("order_id")                   # 掩盖行序
actual.fillna(0)                                 # 掩盖缺失语义
```

这些操作可以让错误表看起来接近期望，却不能证明实际`clean_df`正确。

### 失败优先级

建议按结构→关键键→类型→取值→缺失→顺序→完整比较执行。前一层失败时，可以停止后续依赖检查并返回最可行动错误；同时保留完整内部诊断供负责人审计，但公共反馈必须脱敏。

```python
if clean_df.columns.tolist() != EXPECTED_COLUMNS:
    raise ValidationError("columns_invalid")
if not ids.is_unique:
    raise ValidationError("duplicate_order_id")
```

### fail-fast与完整报告

正式提交链可以在结构阻断时立即停止，避免次生异常；内容教学页则可以在不泄漏私有细节的前提下列出多个公开维度状态。二者使用同一不变量，只是输出粒度不同。

```python
public_checks = {
    "columns": clean_df.columns.tolist() == EXPECTED_COLUMNS,
    "order_id_unique": bool(ids.is_unique),
    "amount_numeric": clean_df["amount"].dtype.kind in "fiu",
}
```

只要任一阻断项为False，整体仍是未通过。多维报告不能把三项中的两项通过换算成最终通过。

### 资产绑定与可复算性

验证结果必须绑定profileRevision、environmentHash、assetBundleHash、evaluatorVersion和Attempt。否则同一个绿色结论无法证明使用了哪一版规则和数据。公共结果可以包含安全哈希，不能包含私有文件路径。

```python
binding = {
    "profileRevision": 3,
    "environmentHash": environment_hash,
    "assetBundleHash": asset_bundle_hash,
}
```

重复提交同一Attempt和代码应重放首次结果；相同幂等键对应不同代码必须冲突，不能重新打分覆盖历史。

### 错误维度映射

`columns_invalid`归结构；`order_id_missing`归缺失；`duplicate_order_id/row_order_invalid`归去重；`amount_invalid/date_invalid/city_invalid/status_invalid/string_dtype_invalid`归类型格式。映射稳定后，系统可以推荐对应小节，而不是让AI自由决定下一步。

### 安全投影

内部测试可以知道具体断言，公共`ActivityResult`只返回有限错误码、维度分数和安全中文提示。不得包含测试文件路径、私有输入值、精确隐藏预期或参考代码。

```python
safe_result = {
    "verdict": "partial",
    "errorCode": "date_invalid",
    "safeFeedback": "部分日期未按本项目格式规范。",
}
```

### 公开反馈的质量标准

反馈至少回答“哪个维度未满足”和“应回到哪类动作”，但不回答“隐藏测试具体期待哪一行”。例如“状态列仍含未批准值”是安全且可行动的；“私有变体W207第5行应为pending”则泄漏评测资产。

固定中文反馈应能在模型关闭时工作。若Agent审核轨迹可用，可以补充来源解释，但不得改变错误码、分数和推荐小节。

### 验证覆盖不能由单个整表比较独占

`assert_frame_equal`能做强比较，但显式维度断言仍有价值：它们提供更清楚错误归因，并证明公开合同各项有对应测试。整表比较负责最终一致性，维度断言负责教学和诊断。

若只有整表比较失败，学习者可能只收到“结果不同”；若只有维度断言，可能漏掉未枚举的值或行序差异。两层组合更稳妥。

### 失败保持性

验证失败不创建一个替代结果，不覆盖旧Attempt，不推进路径。学习者修复负责阶段后重新提交，新结果重新执行全部断言。验证函数本身无需持久化中间状态。

### 完成性判定

只有所有阻断不变量通过且总分达到正式活动阈值，最终任务才完成。本文不展示完整Rubric权重或hidden tests，但公开检查足以让学习者理解主要维度。`LIVE_MODEL=LIVE_NOT_RUN`不影响确定性验证。

### 与演示证据连接

演示应展示一次正确结果和至少一次可解释失败：例如金额dtype错误时不产生假分数，修复后同一输入通过；刷新或重试不改变原结果。所有数字来自真实运行，不能用静态PASS页面代替。

### 完成性与停止条件

验证模块完成需要：公开维度均有明确断言；正式私有检查不泄漏；错误映射稳定；输入和结果不被验证器修改；失败不推进路径；成功结果绑定环境和资产；重复运行结论一致。若任何一项只能通过手工改后台文件或前端写死状态实现，应停止冻结并登记阻塞。

验证成功也不代表真实在线模型通过。确定性主链与`LIVE_MODEL`状态分别登记，避免把可选解释能力混入代码判分。

两者必须分开记录。

### 验证证据的保留方式

每次正式验证至少绑定requestId、attemptId、profileRevision、environmentHash、assetBundleHash、evaluatorVersion和公开结果摘要。失败记录不能在修复后删除，成功记录也不能覆盖此前失败；二者共同展示学习过程。结构化证据只保存允许公开的错误码、维度结果和哈希，不保存私有测试源码。负责人复核时应能够从提交、环境、资产和输入重新运行并得到同一结论。若页面显示的状态无法关联到服务端Attempt，或报告只留下最终绿色截图，没有真实命令与退出结果，应判为证据不足，而不是正式通过。

### 术语与来源

- **验证器纯度**：验证过程不改变被验证对象。
- **阻断不变量**：失败时结果不能判为完成的条件。
- **安全投影**：从内部事实中只公开允许字段。
- **错误维度映射**：把失败稳定关联到负责知识点。
- **check_like**：DataFrame比较时是否忽略布局差异的选项。

来源同共同事实表。

## 版本三：案例实战 `practice`

### 学习目标

**需要了解**

1. 一张“看起来正确”的表可能在哪些隐蔽维度失败。
2. 验证失败应如何定位到具体清洗工位。
3. 为什么现场演示必须使用真实断言和安全反馈。

**需要掌握**

1. 编写一套可执行的最终结果检查函数。
2. 构造最小错误结果，验证列序、dtype、唯一性和行序问题能被发现。
3. 保证验证不修改结果，失败不产生半写入。
4. 形成可供用户理解、可供负责人复算的验收摘要。

### 业务场景：报表能打开，但能交付吗

清洗函数返回26行订单，页面也能显示。运营准备据此统计金额，但金额列其实仍是字符串；另一版结果金额正确，却把订单按编号排序；还有一版把未知状态全部填成pending。三张表都“能打开”，只有满足全部不变量的表能交付。

### 第一步：验证固定结构

先用正文说明：结构错误会让后续字段断言失去对象，因此它必须最先执行。

```python
EXPECTED_COLUMNS = ["order_id", "customer_id", "amount", "city", "order_date", "status", "note"]
assert clean_df.columns.tolist() == EXPECTED_COLUMNS
```

### 第二步：验证订单键

订单号必须有值、去空格后非空，并且唯一。

```python
ids = clean_df["order_id"].astype("string").str.strip()
assert ids.notna().all()
assert ids.ne("").all()
assert ids.is_unique
```

### 第三步：验证类型和取值

订单键通过后，再检查金额、日期、状态和五个字符串列的类型与取值边界。

```python
assert clean_df["amount"].dtype.kind in "fiu"
assert getattr(clean_df["order_date"].dtype, "tz", None) is None
assert set(clean_df["status"].dropna().astype(str)) <= VALID_STATUS
for column in STRING_COLUMNS:
    assert str(clean_df[column].dtype) == "string"
```

再确认非缺失金额全部有限、备注不含缺失。城市使用公开别名样例检查映射，并确认未知城市没有消失。

### 第四步：比较完整结果

维度断言通过后，使用官方比较工具验证整表值、dtype、列和行序的一致性。

```python
pd.testing.assert_frame_equal(
    clean_df.reset_index(drop=True),
    expected.reset_index(drop=True),
)
```

重置索引不改变行序。不要在比较前排序两张表，否则无法发现去重阶段的顺序错误。

### 第五步：保护被验证结果

验证前保存快照，验证后比较，确保断言代码没有为了通过而修改任何字段。

```python
before = clean_df.copy(deep=True)
validate_orders(clean_df)
assert clean_df.equals(before)
```

验证器只读结果。若断言失败，实际错误表仍保留，便于调试和重新提交。

### 故障演练一：列序交换

先人为交换前两列，证明列表比较会失败，即使列集合仍完全相同。

```python
wrong = clean_df[["customer_id", "order_id", "amount", "city", "order_date", "status", "note"]]
assert wrong.columns.tolist() == EXPECTED_COLUMNS  # 应失败
```

集合比较会漏掉这个问题，列表比较能立即发现。

### 故障演练二：金额转回文本

把数值列转成字符串，值的外观看似不变，但dtype断言和完整比较都应失败。

```python
wrong = clean_df.copy()
wrong["amount"] = wrong["amount"].astype("string")
assert wrong["amount"].dtype.kind in "fiu"  # 应失败
```

数值外观看起来不变，dtype断言仍能发现无法可靠计算的表示。

### 故障演练三：制造重复订单

复制一条订单制造重复键，验证器必须在订单号维度明确拒绝。

```python
wrong = pd.concat([clean_df, clean_df.iloc[[0]]], ignore_index=True)
assert wrong["order_id"].is_unique  # 应失败
```

这类错误应推荐返回去重小节，而不是让用户重新学习CSV读取。

### 故障演练四：比较前排序

反转实际行序后再把两张表按订单号排序，可能制造相等，因此这种比较方式必须禁止。

```python
wrong = clean_df.iloc[::-1].reset_index(drop=True)
pd.testing.assert_frame_equal(
    wrong.sort_values("order_id").reset_index(drop=True),
    expected.sort_values("order_id").reset_index(drop=True),
)  # 错误：排序可能掩盖行序失败
```

正确比较保留实际顺序，仅重置索引。

### 故障演练五：验证器偷偷填值

下面的坏验证器把金额缺失填成0，再返回成功，直接违反“验证只读”的边界。

```python
def bad_validate(df):
    df["amount"] = df["amount"].fillna(0)  # 错误：验证阶段改数据
    return True
```

验证发现缺失可以报告，但不能决定填0。修复必须回到类型规则并重新运行完整流水线。

### 完整检查函数骨架

下面把公开不变量组合成检查函数。正文先明确：它不返回修补后的DataFrame，只在失败时抛出可归因异常。

```python
def validate_orders(clean_df):
    assert clean_df.columns.tolist() == EXPECTED_COLUMNS
    ids = clean_df["order_id"].astype("string").str.strip()
    assert ids.notna().all() and ids.ne("").all() and ids.is_unique
    assert clean_df["amount"].dtype.kind in "fiu"
    assert getattr(clean_df["order_date"].dtype, "tz", None) is None
    assert set(clean_df["status"].dropna().astype(str)) <= VALID_STATUS
    for column in STRING_COLUMNS:
        assert str(clean_df[column].dtype) == "string"
```

完整正式评测还有已冻结的私有检查，但公共教学只展示安全规则，不泄漏私有数据或精确隐藏预期。

### 完整走一次失败到修复

假设首次结果金额为StringDtype。验证器返回`amount_dtype_invalid`和固定中文提示，不创建掌握Evidence，也不推进到总结。学习者回到类型小节，使用获批金额管线修复并提交新Attempt；系统重新运行全部检查，而不是只重跑金额断言。

```python
first = validate_orders(wrong_result)  # 失败：金额dtype错误
fixed = normalize_types(dedupe_ready)
second = validate_orders(fixed)        # 从完整结果重新验证
```

示例表达流程，正式接口会返回结构化ActivityResult而不是简单布尔值。旧失败Attempt保留，便于展示学习过程。

### 人工复算演练

负责人可以从公开结果重新计算七列、订单号重复数、状态集合和dtype摘要，再与结构化验证结果比较。若机器报告唯一但人工统计仍有重复，说明证据或投影有问题。

```python
manual = {
    "column_count": len(clean_df.columns),
    "duplicate_order_id": int(ids.duplicated().sum()),
    "status_values": sorted(set(clean_df["status"].dropna().astype(str))),
}
```

人工复算不读取hidden tests，也不修改正式结果。它验证的是公开合同与证据一致性。

### 从失败定位工位

错误码映射使用固定表，让用户回到真正负责该不变量的学习模块，而不是重新走完整路径。

```python
REMEDIATION = {
    "columns_invalid": "检查DataFrame结构",
    "order_id_missing": "处理缺失值",
    "duplicate_order_id": "处理重复订单",
    "amount_dtype_invalid": "规范类型与格式",
}
```

映射由确定性程序完成，AI只能把原因翻译成自然语言，不能更改判分和下一步合法性。

### 安全验收摘要

摘要只公开数量、布尔状态和批准错误码，用于现场展示与复算，不包含订单正文和私有预期。

```python
summary = {
    "rows": len(clean_df),
    "columns_ok": clean_df.columns.tolist() == EXPECTED_COLUMNS,
    "unique_order_id": bool(ids.is_unique),
    "numeric_amount": clean_df["amount"].dtype.kind in "fiu",
}
```

摘要用于演示和复算，不包含订单正文、隐藏断言、私有路径或参考答案。

### 页面状态与真实事实

提交中页面显示运行状态；学习者错误显示失败维度和修改入口；评测器错误显示未判分并保留草稿；成功才显示正式分数和下一步。页面不能在请求返回前乐观写成PASS，也不能在刷新后只从本地缓存恢复分数。

```python
view_state = "passed" if activity_result.verdict == "pass" else "needs_revision"
```

这行只负责展示映射，真正verdict来自服务端权威评测器。前端无权重新计算或覆盖。

### 行序错误为什么难发现

若所有订单号和金额都正确，只是行序反转，按集合比较、按订单号排序比较或逐列排序都会通过。必须保留实际顺序，与冻结期望按位置比较。行序来自去重获胜记录原位置，是业务不变量，不是视觉偏好。

现场演示可以选取相邻公开订单说明顺序，并展示错误版本被比较器拒绝。无需暴露私有记录即可证明行序检查真实存在。

### 失败恢复与重试

首次验证失败时保留错误Attempt，不产生错误Evidence，不推进路径。用户修正负责模块后创建新Attempt，同一输入重新运行清洗和全部验证。刷新或服务重启后从服务端事实恢复，不依赖页面内存中的绿色标签。

重启后若评测器准备状态丢失，应重建准备信息并重新运行，旧的未判分结果不能变成负分。磁盘写失败时显示进度未确认保存，正式快照保持旧版本。验证结果的可信度不仅来自断言，也来自失败路径没有半写入。

最后还要确认重新提交后只有一个新的权威结果，旧失败仍可查看，路径只依据新提交的确定性结论推进；页面刷新不得重复计分。

### 最终交付标准

最终结果必须同时通过公开不变量、正式隐藏检查和确定性Rubric阈值。真实模型未运行仍登记`LIVE_NOT_RUN`，不会让确定性代码评测失效。验证全部通过后才能将会话推进到总结。

### 术语与来源

- **验收摘要**：只包含允许公开的数量和状态。
- **故障注入**：主动构造错误结果，确认验证器能发现问题。
- **修复映射**：把错误码稳定关联到负责小节。
- **失败保持性**：失败不会改写正式事实或被验证对象。
- **完整比较**：同时比较DataFrame结构、值、dtype和顺序。

比较、安全和公开边界来源同共同事实表。
