### 先建立直觉：我们不是在“打开文件”，而是在建立后续工作的起点

一份CSV文件看上去很像表格：第一行通常是列名，后面的每一行是一条记录，不同字段之间用逗号分开。但对Python来说，它一开始仍然只是一段保存在磁盘上的文本。我们不能直接对文件名做去重，也不能对一串文本询问“金额列里有多少缺失值”。因此，数据清洗的第一步不是马上删除错误，而是先把文本可靠地读进一个适合处理表格的数据对象。

在本项目里，这个对象叫DataFrame。你可以暂时把它理解成“Python里的表格工作区”：它有行、有列，也知道每一列叫什么名字。后面的缺失处理、重复订单选择、金额转换和结果验证，都要在这个工作区里进行。读取CSV的任务，就是把磁盘上的订单文本变成这个工作区，同时尽量保留原始信息。

这里有一个很重要的边界：读进来不等于清洗完成。公开订单文件故意包含`¥1,200.50`、`N/A`、错误日期、空订单号、重复订单和大小写不一致的状态。`read_csv`的职责不是替我们猜业务规则，而是先把这些内容组织成表。哪些值应该删除、转换或保留，要由后续小节按照冻结合同处理。

### 把概念拆开

#### 1. CSV是文件格式，不是正在运行的表格对象

CSV是Comma-Separated Values的缩写，中文常说“逗号分隔值”。它用普通文本表示表格：一行对应一条记录，逗号通常用来分开不同字段。这里的“通常”很重要，因为有些文件使用分号或制表符，所以读取程序需要知道真正的分隔方式。

CSV里某个字段本身也可能包含逗号。例如金额`1,200`中就有逗号。为了不把它错误拆成两个字段，文件会把它写成`"1,200"`。引号告诉解析器：这段内容虽然包含逗号，但仍然属于同一个单元格。手工使用字符串的`split(',')`很容易在这里出错，而`read_csv`会按照CSV规则处理引号和分隔符。

```python
line = 'O001,C001,"1,200",Shanghai'
print(line.split(","))  # 错误：金额中的逗号也被拆开
orders = pd.read_csv("orders-learning.csv")  # 正确：交给CSV解析器
```

【术语注释：解析】“解析”是把原始文本按照一套明确规则读懂并转换成结构化数据。这里的规则包括哪一个字符分隔字段、哪一行是表头、引号如何包住含逗号的内容等。解析只负责理解文件结构，不负责决定订单业务是否正确。

#### 2. DataFrame是读取后的二维表

`pandas.read_csv`通常返回DataFrame。所谓“二维”，就是数据同时沿着行和列组织。每一行可以代表一条订单记录，每一列代表一种字段，例如`order_id`或`amount`。DataFrame不仅保存值，还保存列名、行索引和每列当前的数据类型信息，因此它比单纯的字符串列表更适合做清洗和验证。

```python
orders = pd.read_csv("orders-learning.csv")
print(orders.columns.tolist())       # 查看有哪些列
print(orders["amount"].head(3))     # 只预览金额，不在这里转换
```

【术语注释：DataFrame】DataFrame是pandas提供的二维表格数据结构。可以把它想成一张带列名的电子表格，但它由代码控制，可以批量选择、转换、筛选和验证数据。

变量名可以自行决定，但应表达用途。`orders`表示原始订单表，`raw_df`表示尚未清洗的表，都比`x`更容易理解。本节不要急着把变量命名为`clean_df`，因为它还没有通过清洗合同。最终任务要求的`clean_df`必须经过后续全部步骤。

```python
raw_df = pd.read_csv("orders-learning.csv")
# 当前还是原始表，完成后续清洗后才能命名为clean_df
```

#### 3. 路径、分隔符、表头和编码决定“怎样读”

`read_csv`的第一个常见输入是文件路径。路径告诉程序文件位于哪里。在比赛Demo中，文件来自经过登记的Profile资料包，不允许学习者任意上传其他CSV。这样做不是限制学习，而是为了保证所有人使用同一份可复验输入，现场演示和测试结果才能一致。

如果资料包明确使用逗号分隔，可以采用默认分隔规则，也可以写出`sep=','`强调意图。文件第一行是七个字段名时，默认表头推断会把它们作为列名。若真实文件没有表头，就必须显式声明；不能随意把第一条订单误当成列名。编码用于说明文本怎样转换成字符，尤其影响中文。如果来源已经声明编码，就按声明填写；没有证据时不要不断尝试不同编码直到“看起来能打开”，因为那可能掩盖数据来源问题。

```python
path = "orders-learning.csv"
expected_columns = ["order_id", "customer_id", "amount", "city", "order_date", "status", "note"]
# 文件有表头时，让第1行成为列名
orders = pd.read_csv(path, sep=",", header=0, encoding="utf-8")
# 文件没有表头时，必须明确提供列名
no_header = pd.read_csv(path, header=None, names=expected_columns)
```

【术语注释：表头】表头是描述每一列名称的那一行。本项目公开CSV的表头是`order_id, customer_id, amount, city, order_date, status, note`。

【术语注释：编码】编码是一套把文件中的字节还原为文字的规则。编码不匹配时，中文可能乱码或读取失败。它属于输入合同的一部分，不是清洗算法可以随意猜测的内容。

#### 4. 自动推断只是一种读取结果，不是业务结论

读取CSV时，pandas会根据单元格内容尝试安排当前表示方式。有的列可能看起来像数字，有的列因为混入货币符号而保持文本，有些缺失标记可能被识别为空值。这些都只是解析阶段的初步结果。`amount`最终应是什么数值类型、`order_date`接受哪种日期格式、`status`允许哪些值，仍然要按本项目合同处理。

```python
print(orders.dtypes)                              # dtype只是检查线索
print(orders[["amount", "order_date"]].head())  # 先看原值，不急着转换
```

所以，不要因为程序没有报错就宣布数据已经合格。读取成功只回答一个问题：“这份文件能否按当前参数组织成一张表？”它没有回答列是否齐全、每列类型是否正确、订单号是否缺失、重复记录该保留哪一条。下一节会专门检查这些问题。

### 跟着公开数据走一遍

资料包公开文件的前几行类似下面这样：

```csv
order_id,customer_id,amount,city,order_date,status,note
 O001 , C001 ,"¥1,200.50",上海市,2026-01-03, Completed ,首单
O002,C002,88,沪,2026-01-04,pending,
O004,C004,N/A,京,2026/01/06,completed,异常金额
```

第一行提供七个列名。第二行的金额含货币符号和逗号，因此使用引号包围；订单号、客户号和状态周围还有空格。第四行含`N/A`和非冻结日期格式。现在先不要修这些值，只把它们读入表格。

```python
import pandas as pd

orders = pd.read_csv("orders-learning.csv")  # 读取并保留原始异常
print(type(orders))                           # 确认得到DataFrame
print(orders.head(3))                         # 少量预览，不代表整表合格
```

第一行导入pandas并使用惯用简称`pd`。第二行调用`pd.read_csv`，将返回结果保存到`orders`。第三行确认对象类型，预期能够看到DataFrame；第四行只预览少量记录，帮助我们确认文件确实被读取。`head(3)`只是预览前三行，不代表对整张表做了质量检查。

输出会呈现一张带列名的表。你可能发现`N/A`显示为空值，金额列仍可能包含`¥1,200.50`这样的文本，状态两侧空格也还在。这不是程序失败，而是说明读取阶段忠实地保留了需要后续处理的现实问题。当前最正确的动作，是把`orders`交给下一节检查，而不是在这里临时加入一串未经解释的修正代码。

如果文件由资料包明确声明了分隔符和编码，可以把意图写得更清楚：

```python
orders = pd.read_csv(
    "orders-learning.csv",  # 资料包登记的公开文件
    sep=",",                # 明确使用逗号分隔
    encoding="utf-8",       # 按来源声明解释中文
)
```

这并不意味着所有CSV都必须照抄这些参数。参数要和真实来源一致。示例的重点是：读取条件应该显式、可审计，而不是靠个人电脑上的偶然默认值。

### 哪里容易错

#### 反例一：把文件路径当成表

先看错误写法：

```python
orders = "orders-learning.csv"  # 错误：这里只保存了路径字符串
print(orders.columns)
```

这里的`orders`只是一个字符串，保存的是文件名。字符串没有订单表的列，因此不能进行DataFrame检查。正确做法是把路径传给`pd.read_csv`，再保存返回的DataFrame。

```python
orders = pd.read_csv("orders-learning.csv")  # 正确：保存读取结果
print(orders.columns)
```

#### 反例二：手工按逗号切分

先看错误写法：

```python
line = 'O001,C001,"¥1,200.50",上海市'
cells = line.split(",")  # 错误：会把金额拆成两个字段
```

手工切分会把引号中的金额逗号也当作分隔符，得到错误列数。真实CSV还会涉及换行、引号转义和缺失字段，因此不应重新手写一个不完整解析器。正确做法是使用经过验证的`read_csv`并明确参数。

```python
orders = pd.read_csv("orders-learning.csv", sep=",", encoding="utf-8")  # 正确解析引号
```

#### 反例三：读取时顺手完成全部清洗

有人为了少写几行代码，会在读取时同时指定大量缺失、日期和类型参数，希望一步得到最终结果。这样做不一定在技术上永远错误，但在本项目中会把读取、业务清洗和验证混在一起，使错误难以定位，也可能绕过冻结规则。正确流程是先读取并检查结构，再按缺失、重复、类型格式的顺序处理，最后验证唯一`clean_df`。

```python
# 各阶段分开，出错时才能知道问题发生在哪里
raw_df = pd.read_csv("orders-learning.csv")
inspected_df = inspect_orders(raw_df)
```

最终独立实操要求实现`clean_orders(df)`并返回满足七列合同的`clean_df`。这一节提供的是可靠输入起点：你需要知道数据怎样进入DataFrame，也需要保留原始异常，让后续规则有真实对象可处理。读取正确但清洗错误，最终任务仍不会通过；清洗逻辑正确但一开始读错分隔符或表头，同样无法得到合法结果。

### 术语与依据

- **CSV**：使用分隔符组织表格数据的文本文件格式，本节示例使用逗号。
- **解析**：按分隔符、表头、引号和编码等规则，把文本转换成结构化数据。
- **DataFrame**：pandas中的二维表格对象，保存行、列、列名和当前类型信息。
- **参数**：函数调用时提供的配置，例如文件路径、`sep`和`encoding`。
- **表头**：用于声明各列名称的一行。
- **编码**：把文件字节还原成文字的规则。
- **类型推断**：读取器根据当前内容猜测列的表示方式；它不是最终业务类型判定。

### 先看结论：读取步骤的交付物是什么

本节的合格交付物不是“文件成功打开”，也不是最终`clean_df`，而是一个来源明确、解析参数可说明、原始异常尚未被业务规则改写的DataFrame。它必须能够交给下一节检查七列结构。读取阶段只建立输入边界，不负责判断金额、日期、状态和重复订单是否合法。

对高基础学习者，可以把这一节理解为一条接口合同：输入是资料包登记的CSV和确定的解析参数；输出是DataFrame；失败表现包括文件不可达、分隔符或表头配置错误、编码不匹配和CSV结构破损；成功之后仍必须执行结构验证。只要这条边界清楚，读取代码通常很短。

### 目标、先修和本节不做的事

你需要能够使用`pd.read_csv`获得DataFrame，解释`path/sep/header/encoding`分别控制什么，并把“解析成功”和“业务数据正确”分开。你应当已经理解Python函数调用和变量赋值。这里不处理缺失，不去重，不转换金额和日期，不映射城市，不规范状态，也不生成最终`clean_df`。

本项目不开放任意CSV上传。正式输入由Profile资料包登记，公开学习数据和私有评测变体均有固定引用与哈希。读取代码不能扫描宿主目录寻找“差不多的文件”，也不能在路径失败后静默切换另一份数据。否则同一提交可能在不同电脑上读取不同内容，结果便失去可复算性。

### 核心边界一：让成熟解析器处理CSV语法

CSV虽然是文本，但不能等同于“每行调用一次`split(',')`”。引号包围的字段可能包含逗号，例如`"¥1,200.50"`；字段可能为空；文本中还可能出现转义规则。`read_csv`的价值首先是正确执行这些语法规则，然后再把记录组织成二维表。

```python
cells = 'O001,C001,"1,200"'.split(",")      # 错误：不理解CSV引号规则
raw_orders = pd.read_csv("orders-learning.csv")  # 正确：使用成熟解析器
```

【术语注释：解析器】解析器是按照文件格式规则识别文本结构的程序。它负责判断哪个逗号是字段分隔符、哪个逗号属于引号内的金额，不负责判断金额是否满足订单业务规则。

资料包公开CSV的第一行是固定七列表头：

```text
order_id, customer_id, amount, city, order_date, status, note
```

读取器可以把第一行识别为列名，但这一行为仍需在下一节通过`columns`验证。原因是“读到七个名字”和“这些名字恰好等于合同要求且顺序正确”是两件事。若分隔符错误，整行甚至可能被读成一个列名；若文件缺少表头，第一条订单可能被误当成表头。

```python
expected = ["order_id", "customer_id", "amount", "city", "order_date", "status", "note"]
assert raw_orders.columns.tolist() == expected  # 读取后仍要验证列名和顺序
```

### 核心边界二：类型推断不得升级成业务判定

公开数据的`amount`列同时包含普通数字、货币符号、逗号、`N/A`、`Infinity`和空值。读取器可能把整列保留为文本，也可能将部分标记识别成缺失。无论当前dtype是什么，都不能在本节宣称金额已经规范化。最终数值转换必须执行去符号、去逗号、非法文本转缺失等冻结规则。

```python
print(raw_orders["amount"].dtype)  # 当前表示类型，不是业务合格证明
print(raw_orders["amount"].head())
# 读取阶段不要直接调用astype(float)
```

日期也一样。`2026-01-03`看起来像日期，`2026/01/06`和`01-11-2026`看起来也可能被某些宽松工具理解，但本项目只接受资料包声明的格式。读取阶段应保留输入，日期解析放到类型格式小节，避免默认推断随版本或样本变化。

```python
raw_dates = raw_orders["order_date"].copy()  # 保留原始日期文本
print(raw_dates.head())                      # 日期解析留到后续阶段
```

【术语注释：dtype】dtype是DataFrame中一列当前的存储或表示类型。读取后的dtype是检查线索，不是业务合格证明。

### 最小、明确、可审计的读取代码

当资料包已经登记路径、逗号分隔和UTF-8编码时，可以写成：

```python
import pandas as pd

raw_orders = pd.read_csv(
    "orders-learning.csv",  # 获批输入
    sep=",",                # 获批分隔符
    encoding="utf-8",       # 获批编码
)
```

变量名`raw_orders`强调这是原始订单表。显式参数让审阅者能够快速判断读取假设。如果来源没有要求显式编码，也可以采用获批运行环境的约定，但不能在证据中声称测过一个实际没有测量的编码。

读取后建议只做轻量确认：

```python
assert isinstance(raw_orders, pd.DataFrame)  # 先确认对象类型
print(raw_orders.shape)                      # 行数和列数
print(raw_orders.columns.tolist())           # 列名和顺序
```

这里的断言只确认对象种类。`shape`和列名输出帮助进入下一节，不能代替下一节的完整结构合同。尤其不要因为`head()`看起来整齐，就跳过列序、dtype和缺失统计。

### 输入到输出的关键变化

输入是按行保存的CSV文本，输出是带列名和行索引的DataFrame。引号中的金额逗号不再被误拆成新列，空单元格会以DataFrame能够表达的缺失形态出现，中文城市和备注成为字符串内容。这个转换改变了数据的组织方式，但没有完成订单清洗。

```python
raw_orders = pd.read_csv("orders-learning.csv")
print(raw_orders.loc[0, ["order_id", "amount"]])  # 查看一行中的两个字段
```

可以把读取阶段的结果概括为“结构化但未认证”。结构化表示代码可以按列操作；未认证表示它尚未满足固定七列、类型、缺失、唯一性和行序不变量。这个词组有助于避免把技术成功误写成业务PASS。

### 反例与边界回归

#### 反例一：读取成功就立即提交

下面的代码只完成读取，却把变量提前命名为最终结果：

```python
clean_df = pd.read_csv("orders-learning.csv")  # 错误：只读取就冒充清洗完成
return clean_df
```

这段代码能返回DataFrame，但公开数据仍含空`order_id`、重复订单、货币符号、非法日期和非法状态。它只满足“能读”，不满足最终清洗合同。修正方式是把读取结果作为流水线输入，依次执行结构检查、缺失、去重、类型格式和验证。

```python
raw_orders = pd.read_csv("orders-learning.csv")  # 正确：先保留原始表
clean_df = clean_orders(raw_orders)               # 再执行完整清洗流程
```

#### 反例二：使用默认参数掩盖未知输入

下面的路径和解析条件都没有经过资料包绑定：

```python
raw_orders = pd.read_csv(user_supplied_path)  # 错误：来源和参数都未绑定
```

问题不在于默认参数本身，而在于`user_supplied_path`没有资料包绑定，分隔符、编码、列集合和安全边界均未知。本Demo只接受固定登记输入。若未来扩展任意上传，必须另建验证和安全合同，不能把未来能力偷偷塞入本节。

```python

raw_orders = pd.read_csv(approved_path, sep=",", encoding="utf-8")
```

#### 反例三：用异常捕获静默返回空表

下面的异常处理会把真实失败伪装成一张正常空表：

```python
try:
    raw_orders = pd.read_csv(path)
except Exception:
    raw_orders = pd.DataFrame()  # 错误：把读取失败伪装成零订单
```

空表会让后续错误看起来像“没有订单”，掩盖真正的文件或解析失败。正确做法是让失败明确暴露，由调用边界显示可理解的错误和恢复方式，不伪造成功数据。

```python
try:
    raw_orders = pd.read_csv(path)
except (FileNotFoundError, UnicodeError) as error:
    # 正确：保留失败原因，让上层显示明确错误
    raise RuntimeError("csv_input_unavailable") from error
```

### 与最终任务的连接

最终`clean_df`要满足固定七列和顺序、`order_id`非空唯一、金额和日期类型正确、字符串列规则明确，并保持被选记录的原始相对顺序。读取阶段对这些要求的贡献是保证输入来源固定、CSV语法被正确解析、原始行序可追踪、异常值没有被无依据改写。

本节完成标准只有五项：绑定正确文件；解析参数有依据；输出为DataFrame；读取异常明确失败；结果进入结构检查。不要在这一节追求最终分数，也不要通过预填清洗结果让下一节失去真实输入。

### 工程交接记录

在真实项目里，读取步骤还应留下最小而有用的交接信息：使用的数据资产ID或相对路径、实际解析参数、读取时间、行列数量，以及失败时的公开错误分类。记录这些信息不是为了把普通日志变成数据库，也不能把宿主绝对路径或私有数据写进去；它的作用是让后续排查者知道“哪一份输入以什么方式进入了流水线”。当结构检查发现列数异常时，团队可以先回看读取参数，而不是立即怀疑去重或类型转换。对比赛Demo而言，这种清楚的责任边界也能证明结果来自真实程序，而不是事后手工整理的表格。

```python
# 只记录可公开复验的摘要，不记录绝对路径或原始数据
record = {"asset_id": "dataset-public-orders", "rows": len(raw_orders), "columns": len(raw_orders.columns)}
```

### 术语与来源

- **CSV**：文本表格格式；字段通常由逗号分隔，引号可保护字段内部的逗号。

### 开工前检查：先确认输入合同

正式Demo不接受任意上传。输入由Profile资料包登记，公开数据用于学习和公开测试，私有变体只由服务端评测边界读取。当前工作只使用公开文件，不扫描下载目录，也不接收用户随手指定的盘符路径。

```python
PUBLIC_INPUT = "orders-learning.csv"  # Profile登记的公开输入
raw_orders = pd.read_csv(PUBLIC_INPUT)  # 不扫描下载目录寻找其他文件
```

公开文件的表头是：

```text
order_id, customer_id, amount, city, order_date, status, note
```

它采用逗号分隔，内容包含中文。金额`"¥1,200.50"`使用引号，是因为单元格内部含逗号。这个细节决定我们必须使用真正的CSV解析器，而不是手工拆字符串。

【术语注释：输入合同】输入合同是对数据来源、文件格式、列和解析条件的明确约定。它让开发、测试和现场演示处理同一类输入，避免每个人凭感觉解释文件。

### 第一步：建立最小读取脚本

先用一段短代码把输入合同落实为明确参数：

```python
import pandas as pd

source_path = "orders-learning.csv"  # 固定输入来源
raw_orders = pd.read_csv(
    source_path,
    sep=",",           # 逗号分隔
    encoding="utf-8",  # 正确读取中文
)
```

`source_path`保存获批文件的相对路径。`sep=','`明确字段分隔方式，`encoding='utf-8'`明确中文文本的解释方式。`pd.read_csv`负责理解CSV语法，并把结果交给`raw_orders`。

【术语注释：相对路径】相对路径是从当前获批工作目录出发定位文件的路径，不包含某台电脑专属的盘符和用户目录。它更容易在不同机器上复现。

【术语注释：DataFrame】DataFrame是pandas里的二维表。它保存行、列、列名和当前dtype，使后续代码可以按列处理订单。

为什么变量叫`raw_orders`而不是`clean_df`？因为数据只是读进来了，还没有满足清洗合同。命名是给维护者的第一条提示：这是原始输入，后续步骤不能省略。

### 第二步：做交接级确认，而不是提前清洗

读取后只观察对象与结构，不在这里修改订单值：

```python
print(type(raw_orders))            # 是否为DataFrame
print(raw_orders.shape)            # 行列数量
print(raw_orders.columns.tolist()) # 列名和顺序
print(raw_orders.head(3))          # 仅用于快速预览
```

这几行用于现场确认读取动作是否发生。对象类型应为DataFrame；`shape`显示当前行列数量；列名列表帮助发现分隔符或表头是否明显错误；`head(3)`显示前三条记录。它们是运行观察，不是最终质量结论。

假如输出中仍然看到`Completed`周围有空格，或者某些金额显示成文本，不要立刻把它们当成读取故障。公开文件本来就包含这些脏数据。读取器的工作是忠实组织输入，业务清洗要在后续明确步骤中完成。

【术语注释：dtype】dtype表示一列当前怎样存储。金额列混入货币符号时可能不是数值类型；这正是后续类型规范化要解决的问题。

### 第三步：理解读取后的数据交给谁

读取完成后，`raw_orders`进入“检查DataFrame结构”小节。下一步要确认固定七列是否齐全、顺序是否一致、当前dtype是什么、缺失概况如何。只有结构边界明确后，才按顺序处理缺失、重复订单、金额日期和文本格式，最后验证`clean_df`。

```python
checked_orders = inspect_orders(raw_orders)  # 下一工位：结构检查
clean_df = clean_orders(checked_orders)      # 后续工位：完整清洗
```

这条交接顺序能提高排错效率。若列数只有一列，优先检查分隔符；若中文乱码，优先检查编码和来源；若列齐全但金额不是数值，说明读取大体成功，应进入类型格式阶段；若`order_id`为空，则由缺失值阶段按合同删除该行。每类问题都有明确归属，不需要把所有修复堆进一个函数调用。

### 现场故障一：金额被拆成两列

错误做法：

```python
rows = [line.split(",") for line in open(source_path, encoding="utf-8")]  # 错误：金额会错列
```

当程序遇到`"¥1,200.50"`时，普通`split`不知道引号保护规则，会把一个金额拆成两个字段。后果是列错位，城市可能跑到日期列，后面的校验全部失真。修复方式是停止手工解析，使用`pd.read_csv`并绑定正确分隔符。

```python
raw_orders = pd.read_csv(source_path, sep=",", encoding="utf-8")  # 正确处理引号
```

### 现场故障二：文件打不开就返回空表

错误做法：

```python
try:
    raw_orders = pd.read_csv(source_path)
except Exception:
    raw_orders = pd.DataFrame()  # 错误：系统会误以为当天没有订单
```

这种代码表面上“不中断”，实际上把文件缺失、权限问题或格式破损伪装成零订单。业务方可能据此得出当天没有交易的错误结论。Demo中应明确显示输入或解析失败，保留恢复入口，而不是伪造一张成功DataFrame。

```python
try:
    raw_orders = pd.read_csv(source_path)
except FileNotFoundError as error:
    # 正确：把可识别错误交给上层处理
    raise RuntimeError("csv_input_unavailable") from error
```

### 现场故障三：读完马上把异常改掉

错误做法可能在`read_csv`后紧接着删除空值、猜测日期和替换状态，却没有说明依据。这样一旦结果不对，很难判断是文件读错，还是业务清洗错。更严重的是，宽松日期推断可能把`01-11-2026`解释成不同日期，破坏冻结合同。

```python
raw_orders = pd.read_csv(source_path)
raw_orders = raw_orders.dropna()  # 错误：读取阶段提前删除了业务记录
```

正确做法是分层：读取阶段保留原始异常；结构检查阶段确认列和dtype；缺失阶段只按字段规则处理；去重阶段执行三级选择；类型阶段按声明格式转换；验证阶段检查不变量。每一步都有输入、输出和错误归属。

```python
raw_orders = pd.read_csv(source_path)       # 读取阶段只组织原始输入
checked_orders = inspect_orders(raw_orders) # 下一阶段再检查结构
```

### 实战验收清单

在把`raw_orders`交给下一步之前，逐项确认：

```python
expected_columns = ["order_id", "customer_id", "amount", "city", "order_date", "status", "note"]
assert isinstance(raw_orders, pd.DataFrame)               # 对象正确
assert raw_orders.columns.tolist() == expected_columns     # 七列及顺序正确
```

1. 文件来自Profile登记的公开输入，不是临时上传或宿主绝对路径；
2. 分隔符、表头和编码有来源依据，没有通过反复试错猜出来；
3. `pd.read_csv`返回DataFrame，而不是路径字符串、普通列表或伪造空表；
4. 引号内逗号被正确解析，表格没有明显列错位；
5. 读取代码没有提前删除行、转换金额、猜测日期、修改状态或去重；
6. 原始行序仍可供后续重复订单规则使用；
7. 读取失败会明确暴露，不会静默生成成功结果；
8. 下一步固定进入结构检查，不直接把结果冒充`clean_df`。

### 接到最终`clean_df`

最终任务的输入不是一串文件文本，而是DataFrame参数。理解读取步骤，可以帮助你区分“文件进入系统”和“DataFrame进入清洗函数”两个边界。现场演示中，资料包已经负责固定文件和哈希，学习者主要处理DataFrame；但知道DataFrame从哪里来，才能解释为什么列名、行序、dtype和缺失形态会影响后续结果。

```python
raw_orders = pd.read_csv("orders-learning.csv")  # 输入边界
clean_df = clean_orders(raw_orders)               # 清洗边界
```

读取阶段不直接贡献最终清洗分数，却决定后续所有规则有没有可靠对象可执行。它像流水线的进料口：进料口把字段切错，后面每个工位都会收到错误零件；进料口偷偷修零件，后面又无法复算原始问题。因此，最实用的读取代码往往不是参数最多的代码，而是来源明确、行为简单、失败清楚、便于交接的代码。

### 术语与来源

- **CSV**：用文本行和分隔符保存表格数据的格式。
- **CSV解析器**：理解分隔符、引号、表头等CSV语法的程序。
- **DataFrame**：pandas二维表对象，是后续订单清洗的工作区。
- **输入合同**：对来源、格式、参数和允许范围的明确约定。
- **相对路径**：相对于获批工作目录定位文件的路径，避免绑定某台电脑。
- **dtype**：DataFrame列当前的表示类型，需要检查后再按业务规则规范。
- **静默失败**：发生错误却不报告，返回一个看似正常但实际虚假的结果。
- **可复验**：其他人在相同输入、代码和环境下能够重新得到同一行为。
