> 当前文件均为本地提交候选草案，不代表最终功能、指标、PPT或视频已经完成。

## 2. 使用顺序

```text
先冻结最终候选源码与Profile
→ 按05实际运行至少两组、争取三组完整案例
→ 执行正式指标、部署复现和安全检查
→ 在06集中填写版本、状态、分子、分母和证据索引
→ 用06反向校正01至05
→ 从01/03/04/05提炼PPT与视频文案
→ 负责人执行最终一致性复核
```

## 3. 当前必须保留的事实边界

- 当前完整示范领域是Pandas数据清洗，不虚构第二个已完成领域；
- 路径、Evidence、KnowledgeState和判分由确定性程序保障；
- Agent负责生成、质疑、辩护、裁决、解释和个性化建议；
- 固定题是实时AI不可用或审核失败时的保障，不能冒充实时AI题；
- Node/Python承担代码权威评测，Pyodide保持关闭；
- Agent安全可视化、学情画像Agent整链、完整案例和正式指标以最终候选实测为准；
- 所有未执行项写`NOT_RUN`，所有目标百分比不能提前写成实际结果。

## 4. 与评分权重的对应

| 评分维度 | 主要材料 | 最关键证据 |
|---|---|---|
| 作品完整性30分 | 01、02、03 | 一组从诊断到动态更新的真实闭环案例 |
| 技术创新性25分 | 02、04 | 同一原稿的Hunter质疑、Defender回应、Judge终稿与盲评 |
| 用户体验15分 | 01、02、03 | 真实页面、等待状态、返回/重试/恢复和多端走查 |
| 实用价值30分 | 03、05 | 专业Profile、三组案例和三项可复算指标 |

## 5. 最终发布条件

本目录内容只有在以下条件全部满足后，才能转为正式提交版：

1. 最终Git提交、Profile revision和seal已经冻结；
2. 至少两组完整差异化案例来自实际运行；
3. 所有宣称的指标均有分子、分母和原始证据；
4. PPT、视频、README、截图和报告来自同一候选版本；
5. 干净环境部署复现完成；
6. 最终压缩包完成解压复扫和敏感信息审计；
7. 负责人在统一口径表中给出`APPROVED`结论。
