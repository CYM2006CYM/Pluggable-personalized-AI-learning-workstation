# 前端重构方案 · 审查意见

审查对象：`idea/前端重构方案.md`
核对基准：`pi-study-helper/` 当前代码（`src/web/`、 `tests/web/`、 `package.json`、 `scripts/`）

## 结论

动线先行这个主线是对的，源码证据也基本属实（引用的行号、变量值、文件路径都对得上）。但方案有 **6 处会直接卡住或导致返工** 的问题，其中 3 处是硬性的：会撞测试、撞契约、或建在后端不保证的假设上。另有若干章节内容偏薄，不足以指导落地。

按严重度排列如下。

---

## 一、会卡住的硬问题

### H1 · 「跳过即完成」这条规则是错的，且有测试直接拦着

方案 2.4 / 2.5 写：诊断跳过的章节「标记已跳过，不计入阻塞」，2.5 写进度公式 `(completed + skipped) / total`。

代码里不是这样。`PathPage.tsx:62` 已区分两种状态：

```
已跳过            → node.status === "skipped"
已跳过教学（保留实操）→ 带 diagnostic_skip_selected，但 status !== "skipped"
```

`PathPage.tsx:51-54` 的注释写得很明确：这类节点「故意不是 skipped，但教学内容仍被跳过，且必须计入面向学习者的汇总」。`SummaryPage.tsx:83,89` 也对用户展示「已跳过章节教学；最终综合实操仍保留」——**这类节点还有必做的最终综合实操**。

所以按方案实现会出现：用户看到「已跳过」，实际该节点还有没做的必做活动，且进度条已把它算成 100%。

更硬的是测试：`tests/web/pages.test.tsx:229`「only exposes the first unfinished path node as startable after diagnostic skips」、`:936`「distinguishes learner-selected diagnostic skips from learned mastery in the summary」、`:312`「allows an explicitly skipped lesson to be relearned without disguising a review as progress」——三条都在要求区分，不是要求合并。

**改法**：`LessonStatus` 的 `skipped` 拆成两个值：

```ts
export type LessonStatus =
  | "completed" | "current" | "locked"
  | "skipped"                    // 整节跳过，无遗留活动
  | "teaching-skipped";          // 跳过教学，保留最终实操 → 不进分子
```

进度公式同步改：只有 `completed` 与 `skipped` 进分子，`teaching-skipped` 不进分子也不阻塞，但要在步骤条上显示「还剩 1 个实操」。这条规则要写明来源是 `reasonCodes.includes("diagnostic_skip_selected") && node.status !== "skipped"`。

### H2 · 「准备」环节建在后端不保证的假设上

方案把 `basic-python` 单列为循环前的「准备」环节，并写死进 `StudyStepId`。

后端没有这个约定。全仓只有两处提到 `basic-python`：
- `src/web/learning-labels.ts` 的标签映射
- `src/infrastructure/session-capability-evidence-provider.ts:52`（只是知识状态的一个知识点）

路径引擎不保证 `basic-python` 一定出现在 `path.nodes` 里、一定排第一、且是唯一这类节点。而 `StartPage` 有**两种入口模式**——`recommended` 和 `chapter`（`StartPage.tsx:106`，`pages.test.tsx:113` 专门测了「both entry modes」）。按章节学习时路径是子集，`basic-python` 很可能压根不在里面。届时「准备」是个空环节，或者冒出一个别的无教材节点，而「排除辅助节点」的硬编码 id 又失效。

**改法**：改为数据判定，不认 id。判据用「该节点在 `session.learningCards` 里没有绑定教材」或 `next.card === undefined`。`StudyStepId` 里保留 `prepare`，但它的存在与否由 `lessonProgress()` 运行时决定——没有这类节点时该环节不渲染。同时补一句：章节模式下 N 会更小，验收要覆盖两种入口模式。

### H3 · `study-flow.ts` 会重复造一个已有且被测过的轮子

方案 2.5 要新建 `lessonProgress()` 和 `canEnter()`。

`PathPage.tsx:72-91` 的 `projectSequentialPathNodes()` 已经在做这件事，而且就是方案想解决的那个问题——函数注释原文：「诊断跳过后路径引擎可能把多个独立节点标为 available，但学习者侧路径仍按顺序走，所以只有第一个未完成节点可以宣称『可以开始』」。方案全文没提这个函数。

直接另起炉灶的后果：同一套规则两份实现，改一处漏一处，`pages.test.tsx:229` 那条测试会在重构后期才炸。

**改法**：阶段 1 的第一步不是新建，是**搬迁**——把 `projectSequentialPathNodes` 从 `PathPage.tsx` 提到 `flow/study-flow.ts`，`PathPage` 改为调用它。这样测试立刻跟着走，`canEnter` 的逻辑也直接复用它。方案的阶段 1 描述要改成「搬迁 + 扩展」。

### H4 · 阶段 2 的验收标准不可达成，且与执行原则 2 自相矛盾

验收写「改 `--accent` 一个值，全站主色随之变化」。

`styles.css` 实测：3209 行，**208 处硬编码十六进制色值（137 个唯一值）**，只有 183 处 `var()`。而且深色侧栏那一整块（`.app-sidebar` 及其子元素，约 15 条规则）**完全不消费任何变量**，全是 `#f6faf7` / `#34413c` / `#3a4742` / `#c2cec9` / `#273631` 这类字面量。`.path-rail` 也是硬编码深色 `#26332e`。

同时执行原则 2 写「渐进替换，不做一次性重写，新旧共存」。新旧共存期间改一个变量不可能全站变色——两条要求互斥。

**改法**：阶段 2 验收改为可度量的三条：
1. `styles.css` 硬编码 hex 数量从 208 降到 ≤ 60（给出可 `grep -c` 的验收命令）
2. `:root` 中不再出现 `--green` / `--green-dark` / `--sidebar` / `--surface-soft: #eef2ee`
3. 新增组件 100% 走 token；存量文件逐个迁移，每迁一个文件更新一次计数

把「改一个值全站变色」挪到阶段 6 完成后作为最终验收，别放在阶段 2。

### H5 · 归档 SHA-256 不能删，删了会撞测试也删掉演示证据

方案 7.4 禁用清单写「禁止在 UI 显示 …… 任何哈希」。

`SummaryPage.tsx:49` 展示了 `归档SHA-256: {session.completionArchiveSha256}`，区块标题叫「可复验完成归档」。这是**可复现性证据**，不是内部状态外泄——正是比赛评审要看的东西。

而且 `pages.test.tsx:1063` 有测试「replays the frozen completed summary and archive hash from bootstrap」，删了直接红。

**改法**：禁用清单改为「禁止显示会话 ID、节点 ID、活动 ID 等**内部标识符**；完成归档 SHA-256 属于可复验证据，保留但收进折叠区」。同时 6.1 的文案映射表要显式列出这条豁免，否则执行的人会照着禁用清单删掉它。

### H6 · Stepper 是第 7 个进度可视化，不是第 1 个

方案第四章说「Stepper 为核心」，但没盘点现状。当前前端已有 6 套进度表达：

| # | 位置 | 形态 |
|---|---|---|
| 1 | `AppShell.tsx:37` `nav-index` | 01–06 伪步骤条 |
| 2 | `PathPage.tsx:194-195` `path-node` + `path-sequence` | 节点列表 + 补零序号 |
| 3 | `LearnPage.tsx:296` `path-rail` / `rail-node` | 深色侧栏目录 |
| 4 | `DiagnosticPage` `progress-track` | 细进度条 |
| 5 | `components/AgentPipeline.tsx` `agent-station` | **8 站点**流程条（`agent-pipeline.test.tsx:87` 断言「eight stable stations」） |
| 6 | `components/SummaryGenerationPipeline.tsx` `summary-generation-stage` | 生成阶段条 |

直接加 Stepper 就是第 7 套，信息层级会更乱——用户同屏能看到 AppShell 步骤条 + LearnPage 目录 + Agent 8 站点三条进度。

**改法**：新增一节「进度表达合并表」，逐条给出处置：

| 现有 | 处置 | 注意 |
|---|---|---|
| AppShell nav-index | 替换为 Stepper | — |
| LearnPage path-rail | **删除**，功能并入 Stepper | 需同步删 `.path-rail-toggle` 的移动端行为；`learn-layout` 的 225px 列一并去掉 |
| PathPage path-list | 保留为「路径明细」，但去掉补零序号 | 它是路径确认的证据展示，不是导航 |
| DiagnosticPage progress-track | 保留，换 token | 与 Stepper 不同层级 |
| AgentPipeline 8 站点 | **保留不动** | 它是 Agent 过程面，不是学习动线；受 `agent-pipeline.test.tsx` 保护 |
| SummaryGenerationPipeline | 保留不动 | 同上 |

顺带：方案第八章的布局图把 Stepper 放进 232px 侧栏，但没提 LearnPage 自己还有 225px 侧栏。两者并存的话主区只剩 `1240 − 232 − 225 − 间距`，正文 720px 读宽放不下。必须明写「删 `path-rail`」。

## 三、内容偏薄、需要补的部分

### 3.1 缺排版尺度表（第五章）

第五章给了配色、字体栈、间距、圆角、动效，**唯独没给字阶**。这是最需要的一张表。至少要覆盖：

| 层级 | 字号 | 字重 | 行高 | 字距 | 用在哪 |
|---|---|---|---|---|---|
| H1 页面标题 | | | | | `.page-heading h1`（现 28px/1.25） |
| H2 区块标题 | | | | | 现 18px/1.4 |
| H3 小节标题 | | | | | 现 15px |
| 正文（衬线） | | 400 | | | `.lesson-paragraph` 现 1.82 |
| 正文（界面） | | | | | 现 13–14px |
| 辅助文字 | | | | | 现 11–12px |
| 数据/等宽 | | | | | `.agent-mono` 现 11–12px |

现有 `styles.css` 对这些层级的定义是散的（H1 28px、H2 18px、H3 15px、正文 13–16px、辅助 10–12px），方案不给出目标值，执行时每个人各写一套，第五章等于白立。

### 3.2 字体栈有回退风险（5.2）

`"Source Han Serif SC", "Noto Serif SC", "Songti SC", "SimSun", serif` —— `Songti SC` 是 macOS 字体，`Source Han Serif SC` / `Noto Serif SC` 需自行安装。评测机如果是干净的 Windows，前三个全部落空，回退到 `SimSun`（有），但西文会变成宋体自带的西文字形；如果是 Linux，全部落空后回退到 generic `serif`，西文变 Times New Roman。

方案说了「必须用系统字体栈，不得引入 CDN」，方向对，但没考虑回退形态。

**改法**：补一句验收——在目标演示机上实际渲染一段中英混排正文，确认回退字形可接受；并把 `serif` 的兜底改成更稳的写法，或在 `styles.css` 里对 `.lesson-*` 正文显式声明 `font-family: var(--font-serif)` 并逐页验证。

### 3.3 缺响应式策略

`layout-contract.ts` 里有 `tabletBreakpoint: 980px` / `mobileBreakpoint: 700px`，`styles.css` 里有 980 / 620 / 600 三档媒体查询。方案全文**没有一章讲响应式**。

而 Stepper 恰恰是最难折的组件——232px 侧栏在 700px 以下不存在。第八章的布局图只画了桌面态。

**改法**：新增一节或补进第八章，至少明确三件事：
1. Stepper 在移动端折成什么（顶部横向滚动条？可折叠抽屉？）
2. CTA「全站固定在主区右下角」在移动端是否改为底部吸底栏
3. 720px 正文读宽在移动端如何处理（大概率是 100% 宽度 + 左右 padding）

### 3.4 缺无障碍基线

现有代码有 `aria-live`、`aria-current`、`aria-expanded`、`aria-label` 等用法（`LearnPage.tsx:124,136,140,290`；`SummaryPage.tsx:89`）。Stepper 作为核心导航组件，方案没有规定它的无障碍语义。

**改法**：Stepper 规格补三条——容器用 `<nav aria-label="学习流程">`、当前项用 `aria-current="step"`、不可点项用 `aria-disabled` 而非仅 `disabled`（前者可被读屏播报）。

### 3.5 阶段 0 的基线记录不完整

阶段 0 只说「`npm run typecheck`、`npm test` 全绿」。但 `package.json` 里 `verify` 是：

```
typecheck && test && check:docs && smoke:extension && check:release
```

多出来的 `check:docs` 会扫全仓 markdown 的链接有效性，`check:release` 会校验 git 跟踪文件与密钥模式。基线应该记 `npm run verify`，否则阶段 6 提交时才发现 `check:docs` 挂了，排查成本很高。

另外阶段 0 的截图存档只写了「对现有页面截图存档」，没说存哪、怎么比对。建议明确路径（比如 `docs/审查/前端重构基线/`）与命名规则。

### 3.6 新增文件会被边界测试自动扫描

`tests/web/boundary-contract.test.mjs` 会递归扫 `src/web` 下**所有** `.ts/.tsx/.html`（排除 `mocks/`），断言不匹配 `/repositories|src\/demo|fixtures\/profiles|answer-key|hiddenTests|referenceSolution/iu`。

新建的 `flow/study-flow.ts`、`copy/ui-copy.ts` 会自动进入扫描范围。这个测试目前大概率不会挂，但方案应该把它写进约束——语义层如果为了「兜底值必须是中文通称」而写下 `referenceSolution` 之类的词，就会红。

## 五、优先级建议

如果时间紧，按这个顺序改：

1. **H1**（跳过即完成）—— 会产出错误的学习状态，且撞 3 条测试
2. **H2**（准备环节假设）—— 章节模式下会露馅
3. **H3**（重复造轮子）—— 越晚改成本越高
4. **H4**（阶段 2 验收）—— 不改成可度量的话阶段 2 无法收尾
5. **H5 / H6**、事实性修正、第十一章补全 —— 属于执行期踩坑，可边做边补
6. 3.1–3.6 的内容补全 —— 影响交付质量但不阻塞开工
