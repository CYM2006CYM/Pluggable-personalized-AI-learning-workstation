# Pi Study Helper 前端重构方案

本文是 `idea/notes.md` 中界面问题的对应整改方案。

**本方案以动线重构为主线。** 原因是：界面上暴露的所有问题——导航混乱、卡片堆叠、信息焦点不明、指引缺失——都源于同一个根因：产品没有显式定义"用户怎么走完一次学习"。动线定不下来，后面每一层都是在错误结构上施工。因此全文的组织顺序是：先立动线，再让 token、语义、组件、布局、页面逐层为动线服务。

---

## 一、目标与边界

### 1.1 目标

| 维度 | 现状 | 目标 |
|---|---|---|
| 动线 | 隐式，散落在各页 `navigate()` | 显式流程模型，界面如实表达 |
| 产品语言 | 开发者口吻（版本号、哈希、服务端快照） | 学习者口吻（进度、章节、掌握程度） |
| 结构 | 3209 行样式 + 各页手写 JSX，无中间层 | token / 语义 / 组件 / 布局 / 页面 五层 |
| 视觉 | 冷调深绿后台风格 | 米色纸感阅读风格 |

### 1.2 不动的红线

以下内容**禁止改动**，改了会影响评测、证据链和后端契约：

1. `src/contracts/` 的 SafeView DTO 结构
2. `pi-loop-graph-sdk` 版本（固定 0.2.0，提交 `401d3e9`）
3. `src/domain/`、`src/application/`、`src/infrastructure/` 业务逻辑
4. `evaluation/` 的评测输入与 gold 标注
5. `npm run verify` 全链路校验必须保持通过

### 1.3 安全区

前端是被 DTO 契约保护的重构空间。前端只**消费** DTO，不生产数据，因此只要不修改 DTO 结构，`src/web/` 可以整体重写而不影响后端、评测与证据链。这是本次重构的可行性基础。

## 二、动线模型（方案地基）

### 2.1 主动线

```
诊断 → 分析 → 〔 学习 ⇄ 测试 〕× N → 总结
                 └──── 每一节走一遍 ────┘
```

「诊断、分析、学习、测试、总结」是这条动线的五个环节。其中**学习与测试构成循环体**，每学完一节正文就进入该节的测试，测试通过后进入下一节，全部完成后到总结。

### 2.2 代码映射

| 环节 | 页面 | 职责 | 代码依据 |
|---|---|---|---|
| 诊断 | `DiagnosticPage` | 问卷 + 诊断题，产出知识状态 | `PathPage.tsx:48-57` 消费知识状态 |
| 分析 | `PathPage` | 按诊断证据算路径、章节、时长 | `PathPage.tsx:125` 路径投影 |
| 学习 | `LearnPage` | 教材正文 + 个性化导学 | `LearnPage.tsx:295-305` |
| 测试 | `ActivityPage` | 客观题组 / 代码题 | 经 `open()` 从学习页进入 |
| 总结 | `SummaryPage` | 确定性事务生成 | `SummaryPage.tsx:35` |

### 2.3 循环的三个动态因素（不可硬编码）

这是最容易出错的地方。循环次数 **N 由路径引擎运行时计算**，受三个因素影响：

1. **节点数动态**——`PathPage.tsx:125` 的 `path.nodes` 由引擎产出，不是常量
2. **诊断可跳过章节**——`PathPage.tsx:55-57` 存在 `diagnostic_skip_selected`，掌握良好的模块可由用户选择跳过
3. **存在一个辅助节点**——`basic-python` 不扩写教材（`LearnPage.tsx:298` 明确"本节点不扩写独立教材"），性质与六节正文不同

因此界面上的「第 N 节 / 共 M 节」，M 必须运行时读取，不得写死为 6。

### 2.4 两条处理约定

| 情形 | 处理 | 理由 |
|---|---|---|
| 辅助节点 `basic-python` | **不计入节数**，单列为循环前的「准备」环节 | 它没有教材正文，混入"第 N 节"会让用户点进去发现内容是空的 |
| 诊断跳过的章节 | 步骤条中显示，标记「已跳过」，可回看，不计入阻塞 | 保留路径完整感，否则用户会以为内容丢失 |

### 2.5 显式流程定义：`src/web/flow/study-flow.ts`

新建文件，作为全站动线的唯一事实来源。页面只声明"我是哪个环节"，不再各自 `navigate()` 拼流程。

```ts
// 环节标识
export type StudyStepId = "prepare" | "diagnostic" | "analysis" | "lesson" | "activity" | "summary";

// 环节定义：顺序、中文名、对应路由片段、是否属于循环体
export interface StudyStep {
  id: StudyStepId;
  label: string;          // 面向用户的中文名，来自语义层
  inCycle: boolean;       // lesson / activity 为 true
  route: (ctx: FlowContext) => string;
}

// 循环进度
export interface LessonCycle {
  index: number;          // 第几节，1 起
  total: number;          // 共几节，排除辅助节点
  nodeId: string;
  title: string;
  status: LessonStatus;   // completed | current | locked | skipped
}

export type LessonStatus = "completed" | "current" | "locked" | "skipped";

// 进度计算：跳过的节点计入已完成，不阻塞
export function lessonProgress(nodes: readonly PathNode[]): LessonCycle[];

// 进入条件：决定步骤条中该项是否可点
export function canEnter(step: StudyStepId, ctx: FlowContext): boolean;
```

**关键实现约束：**

- `total` = `path.nodes` 中排除辅助节点后的数量
- 进度百分比 = `(completed + skipped) / total`
- `canEnter` 返回 false 的步骤，步骤条置灰且不可点击——这是当前"导航可点但会 409"的直接修复

### 2.6 动线作为设计判据

动线适用于**任务型**环节，不适用于**探索型**环节。判据只有一条：用户能不能说出"我做完 X 就结束了"。

- 能说出来 → 任务型，用动线组织（诊断、分析、学习、测试、总结都属于此类）
- 说不出来 → 探索型，用索引组织

据此，**「案例」（ShowcasePage）必须移出主流程导航**。它是展示材料，没有终点，塞进动线会打断流程感。改由顶栏或页脚入口进入。

## 四、五层架构：每层为动线做什么

自下而上构建，每层只依赖下层，且每层都有明确的动线职责。

| 层 | 名称 | 为动线提供 |
|---|---|---|
| 1 | 设计 token | 动线的视觉语言：当前、已完成、未解锁、已跳过的色彩与动效 |
| 2 | 语义层 | 动线的说法：五个环节的中文名、状态词、CTA 文案 |
| 3 | 组件层 | 动线的零件：Stepper 为核心，外加三类卡片 |
| 4 | 布局层 | 动线的骨架：步骤条位置、CTA 固定位、进度展示位 |
| 5 | 页面层 | 动线的承载：每页声明自身环节，只做组装 |

**依赖规则**：页面只能调用组件层与语义层；组件层只能消费 token；任何层不得硬编码颜色值、字号或用户可见文案；**所有环节判定必须走 `study-flow.ts`，不得在页面内自行判断**。

## 五、设计 token（动线的视觉语言）

### 5.1 配色：米色纸感

主色调改为暖米色，绿色降级为状态色（保留"答对 / 已完成"的色彩语义，不再当主色）。

| 变量 | 值 | 用途 |
|---|---|---|
| `--paper` | `#F7F4EE` | 页面背景 |
| `--surface` | `#FFFFFF` | 卡片表面 |
| `--surface-soft` | `#F1EDE6` | 次级区域 |
| `--line` | `#E3DDD3` | 分隔线 |
| `--ink` | `#2B2823` | 正文 |
| `--muted` | `#7A736A` | 次要文字 |
| `--accent` | `#3D5A4C` | 当前环节、主操作 |
| `--accent-soft` | `#E8EDE9` | 当前环节浅底 |
| `--warm` | `#B0674A` | 强调、需注意 |
| `--success` | `#4E7A5E` | 已完成、答对 |
| `--danger` | `#A85447` | 答错、异常 |

废弃现有 `--green` / `--sidebar` / `--surface-soft: #eef2ee` 等冷调变量。

**动线状态配色映射**（Stepper 专用）：

| 状态 | 颜色 |
|---|---|
| 已完成 | `--success` |
| 当前 | `--accent` + `--accent-soft` 底 |
| 未解锁 | `--muted`，透明度降低 |
| 已跳过 | `--line` 描边 + `--muted` 文字 |

### 5.2 字体

正文用衬线，界面用无衬线。**必须使用系统字体栈，不得引入 CDN 字体**——离线演示模式无法加载外部资源。

```css
--font-serif: "Source Han Serif SC", "Noto Serif SC", "Songti SC", "SimSun", serif;
--font-sans: -apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif;
--font-mono: "Cascadia Code", "Consolas", monospace;
```

### 5.3 间距与圆角

```css
--space-1: 4px;   --space-2: 8px;   --space-3: 12px;  --space-4: 16px;
--space-5: 24px;  --space-6: 32px;  --space-7: 48px;  --space-8: 64px;
--radius-sm: 6px;  --radius: 10px;   --radius-lg: 16px;
```

正文阅读区最大宽度 720px。

### 5.4 动效

```css
--dur-fast: 150ms;
--dur-base: 220ms;
--ease: cubic-bezier(0.2, 0, 0, 1);
```

动效只作用于 `transform` 与 `opacity`，并对 `prefers-reduced-motion` 降级。**步骤推进时进度条填充用 `--dur-base`**，这是动线反馈的主要动效。

## 六、语义层（动线的语言）

建立 `src/web/copy/ui-copy.ts`，集中管理全部面向用户的文案。页面中禁止出现硬编码的用户可见字符串，尤其是英文枚举原值。

### 6.1 动线相关文案（优先）

| 当前 | 改为 |
|---|---|
| `stage: diagnostic` 等原始阶段值 | 诊断 / 分析 / 学习 / 测试 / 总结 |
| `Session v2` | *(不显示)* |
| `路径版本 3` | *(不显示)* |
| `Revision 3` | *(不显示)* |
| `服务端快照为权威状态` | *(不显示)* |
| `session-da599580ce2fd47fec48f89f` | 今天 14:20 的学习 |
| 无进度提示 | 第 N 节 / 共 M 节 |
| CTA 文案各页不同 | 下一步：进入测试 / 下一节 / 生成总结 |

### 6.2 其余文案

| 当前显示 | 改为 |
|---|---|
| `ACTIVE PROFILE` | 当前教材 |
| `SESSION` | 会话设置 |
| `none / basic / comfortable / uncertain` | 没接触过 / 会一点 / 比较熟 / 说不清 |
| 掌握程度 `1.0` | 已掌握 / 基本会 / 还需练 |
| 可恢复会话（仅 stage + 版本号） | 加时间戳 + 已完成节点数 |

### 6.3 扩展方式

基于现有 `learning-labels.ts` 扩展，保持函数式风格：每个枚举一个映射表 + 一个带兜底的取值函数。**兜底值必须是中文通称，不得回落到英文原值。**

## 七、组件层（动线的零件）

### 7.1 Stepper（动线核心组件）

从 `study-flow.ts` 读取环节与状态，输出步骤条。

- 环节项：准备 / 诊断 / 分析 / 学习 / 测试 / 总结
- 循环体在步骤条中折叠为一项，展开显示各节状态
- `canEnter` 为 false 的项置灰且 `disabled`
- 已跳过的节显示「已跳过」标记

### 7.2 三类卡片（保留卡片式排布，但必须分工）

| 类型 | 语义 | 用法约束 | 视觉 |
|---|---|---|---|
| **A 任务卡** | "现在要做什么" | 每页**恰好一个**，含主操作 | 主色左边框或主色浅底 |
| **B 并列卡** | 同层级可选项 | 一组内样式完全一致 | 等宽网格，整卡可点 |
| **C 信息卡** | 补充信息 | 默认折叠 | 浅底、虚线边框、无阴影 |

### 7.3 其他基础组件

`Button`（primary / secondary / text）、`Tag`（状态标签）、`Callout`（提示块）、`Disclosure`（折叠块）、`ProgressBar`（进度条）。

### 7.4 禁用清单

- **流程步骤不做卡片**——用 Stepper
- **正文不做卡片**——用宽栏阅读区
- **禁止在 UI 显示** `revision` / `pathVersion` / `sessionVersion` / `sessionId` / 任何哈希
- **禁止英文枚举原值直接渲染**
- **禁止页面内自行判断环节状态**——一律走 `study-flow.ts`

## 八、布局层（动线的骨架）

```
┌──────────────────────────────────────────────┐
│ 顶栏：第 2 节 / 共 6 节        ▓▓░░░░ 进度    │
├────────────┬─────────────────────────────────┤
│ Stepper    │ A 任务卡：本节目标 + 主操作      │
│            ├─────────────────────────────────┤
│ ● 准备     │ 正文阅读区（衬线、720px、非卡片）│
│ ● 诊断     │                                 │
│ ● 分析     ├─────────────────────────────────┤
│ ● 第 2 节  │ C 信息卡：误区 / 术语（折叠）    │
│ ○ 第 3 节  ├─────────────────────────────────┤
│ ○ 总结     │                    下一步：测试 →│
└────────────┴─────────────────────────────────┘
```

**关键规则：**

- 侧栏宽度沿用 `STABLE_LAYOUT.desktopSidebarWidth`（232px）
- 主操作 CTA 位置**全站固定**（主区右下角），文案由语义层按环节生成
- Stepper 中：已完成可回看、当前高亮、未解锁置灰不可点、已跳过标记显示
- 「案例」入口移至顶栏或页脚

## 九、页面层（动线的承载）

每页开头声明自身所属环节，其余只做组装。按动线顺序逐页重写：

| 顺序 | 页面 | 环节 | 重写要点 |
|---|---|---|---|
| 1 | `StartPage` | 入口 | 主次分区，可恢复会话加时间索引并限 2 条 |
| 2 | `DiagnosticPage` | 诊断 | 单列进度，明确"摸底不是考试" |
| 3 | `PathPage` | 分析 | 用 A 任务卡承载"这是为你算出的路径"+ 确认 CTA |
| 4 | `LearnPage` | 学习 | 任务卡 + 阅读区 + 折叠信息卡三段式 |
| 5 | `ActivityPage` | 测试 | 统一反馈动效，完成后明确回流动线 |
| 6 | `SummaryPage` | 总结 | 按环节汇总，给出下一步去向 |

## 十一、测试基线处理

`tests/web/` 现有 17 个测试文件，重构必然触碰其中一部分。**禁止通过删除或跳过测试让校验变绿。**

| 测试 | 影响 | 处理 |
|---|---|---|
| `pages.test.tsx` | 高（DOM 结构变化） | 同步更新断言 |
| `routes.test.tsx` | 中 | 路由不变则不受影响，变化则同步 |
| `layout-contract.test.ts` | 中（尺寸常量） | 改尺寸须同步常量 |
| `dto-contract.test.ts` | **不应受影响** | 若失败说明越界改了 DTO，立即回退 |
| `boundary-contract.test.mjs` | **不应受影响** | 同上 |
| `v4-recorded-response-audit.test.ts` | 不应受影响 | 录制数据相关 |

**判据**：`dto-contract` 与 `boundary-contract` 是安全边界的哨兵。它们失败意味着前端重构越界侵入了数据契约，必须回退而不是改测试。

## 十二、验收标准

每个阶段完成后执行：

```powershell
npm run typecheck
npm test
npm run verify
```

动线侧专项验收：

- 完整走通：诊断 → 分析 →〔学习 → 测试〕× N → 总结
- 未解锁环节不可点，点击无跳转、无 409
- 跳过的章节显示「已跳过」且不阻塞进度
- 「第 N 节 / 共 M 节」的 M 与实际路径节点一致（构造跳过场景验证）
- 页面无任何哈希、版本号、英文枚举外泄
- 各页主操作位置一致

## 十三、风险与应对

| 风险 | 应对 |
|---|---|
| 无视觉回归基线 | 阶段 0 截图存档，每阶段对比 |
| 循环次数被硬编码 | 阶段 1 就以动态实现，验收时构造跳过场景 |
| 渐进替换期双套样式冲突 | 新组件统一前缀命名，与旧样式隔离 |
| 结构测试大面积失败 | 分阶段推进，每阶段同步更新测试，不积压 |
| 误改数据契约 | `dto-contract` 与 `boundary-contract` 作为哨兵，失败即回退 |
| 离线字体不可用 | 只用系统字体栈，不引入任何 CDN 资源 |

---

## 十四、执行原则

1. **动线先行**——阶段 1 未完成，不得开始阶段 2
2. **渐进替换，不做一次性重写**——新设施与旧样式共存，页面逐个迁移
3. **每阶段一次提交**，提交前 `npm run verify` 必须通过
4. **只动 `src/web/`**，触碰其他目录即视为越界
5. 前端改动如非本人负责岗位，按仓库规则走岗位任务书流程
