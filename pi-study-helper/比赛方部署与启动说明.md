# Pi Study Helper 比赛方部署与启动说明

本文面向第一次接触本项目的比赛测评人员。目标机器只需是 Windows 10/11 x64，机器上是否已有 Node、Python、Conda 或项目环境都不作假设。启动器会先探测，再复用或补齐环境，最后启动系统。

## 一、测评前准备

请准备：

- Windows 10/11 x64；
- 可访问 `nodejs.org`、`python.org`、npm registry 和 GitHub 的网络；
- 至少 3 GB 可用磁盘空间；
- 一个可用且有余额的 DeepSeek API Key；
- 完整项目目录，不能只复制启动文件。

合同环境固定为：

| 组件 | 合同版本 |
|---|---:|
| Node.js | `22.23.1` |
| npm | `10.9.8` |
| Python | `3.13.7` |
| pandas | `3.0.5` |
| 实时模型 | `deepseek-chat` |
| API 地址 | `https://api.deepseek.com/v1` |

启动器会精确检查这些版本，不会使用未经合同验证的替代版本。

## 二、最简单的启动方法

1. 解压或克隆完整项目。
2. 进入 `pi-study-helper` 目录。
3. 双击 [start-competition-demo.cmd](start-competition-demo.cmd)。
4. 首次运行缺少合同时，阅读提示并输入大写 `YES`。启动器会优先把 Node 和 Python 安装到项目内的 `.runtime`，并按 `package-lock.json` 安装 npm 依赖。
5. 看到“请输入 DeepSeek API Key”后输入真实 Key并按回车。输入过程不会显示字符或星号，这是安全输入的正常表现。
6. 等待构建完成。服务就绪后默认浏览器会打开 `http://127.0.0.1:5173/`。

启动窗口必须保持开启。测评结束后回到该窗口按 `Ctrl+C` 停止服务。

## 三、启动器如何适配陌生电脑

启动器不会使用开发者电脑上的 Anaconda 或 NVM 绝对路径，而是执行以下流程：

```text
检查 Windows x64、PowerShell 和完整项目文件
→ 搜索并验证现有 Node/npm
→ 不匹配时下载项目私有 Node，并校验官方 SHA-256
→ 搜索并验证现有 Python/pandas
→ 不匹配时安装项目私有 Python，并校验官方数字签名
→ 检查 node_modules 与 package-lock.json
→ 首次缺依赖时执行 npm ci
→ 清除外部遗留的 PI_STUDY_DATA
→ 由当前教材 Seal 自动选择新运行目录
→ 隐藏读取 DeepSeek Key
→ 启动真实 AI 服务
→ 等待 5173 真正监听后打开浏览器
```

每次探测会生成 `.runtime/competition-preflight-report.json`。报告只包含操作系统、组件版本、依赖状态和错误原因，不包含 API Key。

## 四、如何确认启动的是实时 AI 模式

启动终端必须出现：

```text
PI_STUDY_READY mode=live_model ... url=http://127.0.0.1:5173/
```

只看到网页并不足以证明实时 AI 已接通。新建学习会话、进入教学章节并触发客观题后，还应在 Agent 流水线看到 Generator、Hunter、必要时的 Defender 和 Judge 运行记录。

页面显示“固定题保障”表示该轮实时生成超时、API失败或未通过审核，不能登记为实时模型成功。为了避免旧 Session 快照影响观察，每次正式验收建议新建会话。

## 五、数据 Seal 与旧数据隔离

不要把 `PI_STUDY_DATA` 长期固定为 `.demo-data-live`。教材更新会产生新 Seal，而旧目录可能绑定旧教材；系统会主动拒绝读取不兼容数据，避免把旧会话误当成新版本结果。

一键启动器会清除继承的 `PI_STUDY_DATA`，由正式 TypeScript 启动器自动选择：

```text
.demo-data-<当前教材Seal前12位>
```

教材 Seal 改变时会自然切换到新目录，旧数据仍保留，不会被删除。

如果正在手动启动并看到 `profile_data_incompatible`，在同一个已配置 Key 的 PowerShell 执行：

```powershell
Remove-Item Env:PI_STUDY_DATA -ErrorAction SilentlyContinue
npm.cmd run demo:live
```

## 六、API Key 安全边界

API Key只保存在当前启动进程的内存环境中：

- 不写入 `.env`；
- 不写入预检报告；
- 不写入浏览器 bundle；
- 不显示在终端；
- 服务退出后由启动器清除。

`.runtime`、`.demo-data-*` 和构建目录均为本机运行产物，不应上传或作为作品源文件提交。

## 七、环境预检

需要只检查环境、不启动网页和不输入 Key时，在 `pi-study-helper` 目录打开 PowerShell：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "./scripts/competition-launcher.ps1" -CheckOnly
```

成功时输出：

```text
CHECK_OK：比赛合同环境与项目依赖均已就绪。
```

## 八、离线故障隔离模式

仅为确认本地网页、诊断、正文和活动闭环能否打开，可执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "./scripts/competition-launcher.ps1" -Offline
```

离线模式使用录制响应或固定保障，不会调用 DeepSeek，不能作为实时 AI 验收结果。

## 九、常见故障

### 1. 首次安装 Git

`package-lock.json` 通过 HTTPS 锁定了 GitHub 上指定提交的 Loop Graph SDK。首次缺少 Git 时，一键启动器会调用 Windows `winget` 安装 Git for Windows，并在当前进程中重新定位它。

如果机器没有 `winget`，请手动执行或从 Git 官方页面安装：

```powershell
winget install --id Git.Git -e
```

安装后如果仍提示找不到 Git，关闭当前窗口并重新双击启动程序。比赛方不需要配置 GitHub SSH Key。

### 2. 端口 5173 被占用

启动器不会擅自结束其他程序。请在 PowerShell 检查：

```powershell
Get-NetTCPConnection -State Listen -LocalPort 5173 -ErrorAction SilentlyContinue
```

确认是旧的 Pi Study Helper 后，回到旧窗口按 `Ctrl+C`，再重新启动。不要强制结束来源不明的系统进程。

### 3. API Key 输入后仍显示固定题保障

先检查终端是否出现 `mode=live_model`。如果没有，当前并非实时模式。若模式正确，常见原因包括：

- Key 输入错误、已失效或账户余额不足；
- 无法访问 DeepSeek；
- 模型响应超过时间限制；
- Generator 输出未通过 Schema 或安全检查；
- Hunter/Judge 拒绝了候选内容。

请保留启动终端中的脱敏错误信息，不要截图或发送完整 Key。

### 4. 下载失败

确认网络能访问以下地址：

- `https://nodejs.org/`；
- `https://www.python.org/`；
- npm registry；
- `https://github.com/`。

下载不完整不会绕过校验。恢复网络后重新启动即可。

### 5. 浏览器没有自动打开

只要终端已出现 `PI_STUDY_READY`，可以手动访问 [http://127.0.0.1:5173/](http://127.0.0.1:5173/)。

### 6. Windows 阻止脚本运行

请从可信的作品目录运行 `start-competition-demo.cmd`。入口仅对本次 PowerShell 进程使用 `ExecutionPolicy Bypass`，不会永久修改系统执行策略。

## 十、重复启动与数据保留

第二次及以后仍然双击 `start-competition-demo.cmd`。已匹配的环境和依赖会被复用，只需要再次输入 Key。

停止服务不会删除学习记录。比赛数据保存在 seal 隔离的 `.demo-data-*` 目录。需要全新验收时，优先在网页中新建会话；不要在不了解数据范围时直接删除项目目录。
