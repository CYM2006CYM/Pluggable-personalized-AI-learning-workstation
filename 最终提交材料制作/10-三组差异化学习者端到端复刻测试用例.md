### 1.3 本文补齐什么

本文按当前代码重新设计三组用例，完整覆盖：

```text
背景问卷
→ 13道客观诊断
→ 初始KnowledgeState
→ 可选跳章
→ 差异化RichLesson版本
→ AI客观题与多Agent审核
→ 错题补救题组
→ 主观代码评测
→ 未掌握继续或重试
→ 最终学情画像与总结
```

三组分别是：

| 用例 | 用户水平 | 讲解偏好 | 诊断正确数 | 获得跳章资格 | 实际跳过 | 预计路径 |
|---|---|---|---:|---:|---:|---:|

| B | 中等基础/局部薄弱 | 案例优先 `practice` | 7/13 | 3章 | 2章 | 226分钟 |
| C | 高基础 | 重点速览 `concise` | 13/13 | 6章 | 5章 | 88分钟 |

这里的“用户水平”不是只看自报经验。当前系统真正用于诊断证据、知识状态和跳章资格的是13道客观诊断结果；Python/Pandas经验问卷用于保留用户背景，讲解偏好用于选择正文版本。

## 2. 当前框架中必须理解的五条规则

### 2.1 三个讲解偏好只决定正文版本

| 页面选择 | 内部偏好值 | 正文版本 |
|---|---|---|
| 逐步讲解 | `step_by_step` | `guided` |
| 重点速览 | `concise` | `concise` |
| 案例优先 | `example_first` | `practice` |

同一会话只绑定一个版本。新建会话并重新选择偏好，才能更换版本。

### 2.2 诊断题固定为13道全客观题

- 1道Python基础题；
- 6个Pandas核心模块；
- 每个Pandas模块2道题，分别提供“概念理解”和“代码/应用辨析”两类证据；
- 某模块必须两题都答对，才出现该章的可选跳过复选框；
- 获得资格不等于自动跳过，默认仍继续学习；
- 最终综合实操始终保留。

### 2.3 路径预计时间是可复算的

完整路径各节点时间如下：

| 节点 | 预计分钟 |
|---|---:|
| Python基础补救 | 5 |
| 读取CSV | 31 |
| 检查DataFrame结构 | 33 |
| 处理缺失值 | 40 |
| 处理重复订单 | 45 |
| 规范类型与格式 | 53 |
| 验证清洗结果与综合实操 | 83 |
| 合计 | 290 |

选择跳过普通章节后，该章节教学和普通活动不计时。最终验证章即使具备跳过资格，也至少保留60分钟综合实操。

### 2.4 AI客观题题量允许变化，判分规则不变

实时AI通常生成4至6题。通过要求是：

```text
至少答对 ceil(题目总数 × 75%) 题
```

| 本轮题量 | 通过所需正确数 | 制造“未达标但不是全错”时可答对 |
|---:|---:|---:|
| 4 | 3 | 2 |
| 5 | 4 | 3 |
| 6 | 5 | 4 |

因此本文不把“第几题选A”写死到动态题中，而是规定本轮要达到“通过”“未达标”或“连续两轮未达标”哪一种状态。题干、选项、题量和耗时可以变化，判分阈值、重试分支和最终画像必须稳定。

### 2.5 主观题采用真实Python评测

- 六个Pandas章节都有代码活动；
- 每次正式评测显示“通过测试点数量/总测试点数量”；
- 当前每个代码活动按5个测试点展示，其中1个公开测试点、4个密封测试点；
- 第一次未通过只能修改后重试；
- 第二次仍未通过时，可以继续修改重试，也可以“放弃并进入下一环节”；
- 放弃会保留未掌握事实，并在最终总结的“仍需处理”中出现。

为避免泄露隐藏测试与权威参考实现，本文不复制通过代码。项目负责人内部复刻时，可使用[《W6-负责人六节主观题答案代码-仅本地参考》](../新版设计文档-重写版/第六周任务/W6-负责人六节主观题答案代码-仅本地参考.md)作为受限测试输入；比赛方正常测评时应根据页面完整题面、公开CSV样例和验收条件作答。

## 3. 三组用例的公共启动方法

### 3.1 推荐启动

1. 完整解压项目；
2. 双击仓库根目录的 `start-pi-study-helper.cmd`；
3. 选择实时AI模式；
4. 在安全输入框中输入DeepSeek API Key；
5. 等待启动器检查或准备Node `v22.23.1`、npm `10.9.8`、Python `3.13.7`、pandas `3.0.5`；
6. 浏览器打开 `http://127.0.0.1:5173/`；
7. 终端出现 `PI_STUDY_READY mode=live_model` 后再开始用例。

详细部署和故障处理见项目中的《比赛方部署与启动说明》。不得把 `npm run demo` 的录制响应写成实时AI证据；只有 `demo:live` 且页面来源为“AI个性化生成题组”时，才算实时AI成功。

### 3.2 三组用例必须使用三个新会话

每做一组都返回主菜单，点击“开始新会话”。不要恢复上一组Session，也不要在同一Session内临时改变人设。记录页面或浏览器地址中的Session标识，用代号关联：

- `CASE-A-BEGINNER`
- `CASE-B-INTERMEDIATE`
- `CASE-C-ADVANCED`

三个用例可以共用同一个服务进程，但不能共用同一个Session。

### 3.3 每组都要保留的证据

每组至少保存以下内容：

1. 背景问卷截图；
2. 13道诊断的输入记录；
3. 诊断后可跳过章节列表；
4. 跳章勾选状态、最终路径和预计分钟；
5. 正文中文版本标签和AI个性化课前提醒；
6. 至少一次客观题Agent流水线截图；
7. 题组来源：`AI个性化生成题组`、`固定题保障`或其他真实标签；
8. 客观题首轮结果、复盘、重试结果和补救上下文；
9. 代码题题面、输入/输出CSV下载、5个测试点结果；
10. 最终总结页的前后状态、主动跳过、仍需处理、正式Evidence数量和画像Agent状态；
11. 本次运行日期、执行人、Git提交号、教材revision和资产指纹；
12. 不含API Key、隐藏测试内容、完整Rubric、模型隐藏思维链和本机绝对路径的Agent导出。

## 5. 用例A：基础薄弱、逐步讲解、完整学习后明显进步

### 5.1 人设与测试目标

测试代号：`CASE-A-BEGINNER`。

这是一位没有Python和Pandas经验、需要老师一步一步解释的学习者。测试重点是：低起点是否保留完整路径；答错后是否形成补救；完成代码实践后最终画像是否真实显示进步，而不是把诊断错误永久保留为结论。

### 5.2 背景问卷

| 字段 | 选择 |
|---|---|
| Python经验 | 没有经验 |
| Pandas经验 | 没有经验 |
| 讲解偏好 | 逐步讲解 |

预期正文标签：`逐步讲解`，内部版本为 `guided`。

### 5.3 诊断、跳章和路径

1. 按第4章A列完成13道题；
2. 预期正确数为0/13；
3. 预期没有任何章节出现跳章复选框；
4. 直接生成路径；
5. 预期7个路径节点全部保留；
6. 预期总时长290分钟。

### 5.4 客观题和主观题操作脚本

| 学习节点 | 客观题操作 | 代码题操作 | 预期系统反应 |
|---|---|---|---|
| Python基础补救 | 首轮故意答错；用新题重做并答对 | 无 | 保留两次Attempt，最佳结果为通过 |
| 读取CSV | 达到本轮通过阈值 | 首轮直接通过5/5 | 进入下一节，不产生未解决项 |
| 检查DataFrame结构 | 达到本轮通过阈值 | 首轮直接通过5/5 | 正文和练习均形成Evidence |
| 处理缺失值 | 首轮答对数设为“通过要求-1”；第二轮达到通过阈值 | 首轮直接通过5/5 | 第二轮题组显示错题和画像补救上下文，错题数下降 |
| 处理重复订单 | 达到本轮通过阈值 | 首轮在TODO内输入`raise ValueError("intentional case A")`；第二轮改为合格实现并通过5/5 | 第一次显示运行错误或测试未运行；第二次形成新的Attempt并通过 |
| 规范类型与格式 | 达到本轮通过阈值 | 首轮直接通过5/5 | 金额、日期、字符串dtype等验收点通过 |
| 验证清洗结果 | 达到本轮通过阈值 | 综合实操首轮通过5/5 | 进入总结生成 |

客观题每轮题量可能不同。所谓“通过要求-1”，例如4题答对2题、5题答对3题、6题答对4题。提交后要在安全复盘中确认原题、正确答案和正文解释均出现。

### 5.5 应重点检查的Agent行为

在“处理缺失值”的第二轮新题组中展开流水线，确认：

```text
教学依据：当前guided正文
→ 学情画像：识别上一轮错题数量和薄弱知识
→ Generator：生成新题组
→ 安检：执行确定性合同检查
→ Hunter：反向找错
→ Defender：仅在存在语义争议或高风险问题时触发
→ Judge：裁决
→ 发布：AI题组或有明确原因的固定保障
```

补救题组应显示它结合了当前章节正文、上一轮错题及解析、学情画像建议。题干不必和首次运行完全相同，但必须重新考察缺失主键、`dropna(subset=...)`或本轮实际错到的同类知识。

### 5.6 最终画像预期

完成全部活动后，预期总结至少满足：

- 路径节点：7；
- 主动跳过章节：0；
- 仍需处理：0；
- 能看到多个知识点从“需要支持”变化为“学习中”“可以应用”或“已掌握”；
- 能看到缺失值错题补救前后变化；
- 重复订单代码题保留失败Attempt和最终通过Attempt；
- 画像总结不能声称诊断时已经掌握这些知识；
- 画像Agent失败时可以显示确定性事实总结，但必须真实标注Agent未采用，不能伪装为实时Agent产出。

### 5.7 本用例通过标准

- [ ] `guided`正文绑定正确；
- [ ] 路径为290分钟且无跳章；
- [ ] 缺失值第二轮是新题组，并带补救上下文；
- [ ] 代码错误不会产生通过Evidence；
- [ ] 代码修改后真实得到5/5；

## 9. 实时AI非确定性如何处理

“可复刻”不等于每次DeepSeek生成完全相同的句子。必须区分两类断言。

### 9.1 必须完全一致的确定性断言

- 背景问卷到正文版本的映射；
- 13道诊断输入及正确/错误结果；
- 两类证据同时正确才有跳章资格；
- A/B/C分别得到0/3/6章资格；
- 用户选择后分别跳过0/2/5章；
- 路径预计时间分别为290/226/88分钟；
- 客观题通过阈值为75%向上取整；
- 第二次仍未通过时出现重试和带缺口继续两个选项；
- 代码评测显示通过数/5；
- 未掌握和主动跳过进入最终总结；
- 综合实操不会被普通跳章删除。

### 9.2 允许变化但必须记录的AI断言

- 每轮具体题干、选项顺序和题量；
- Hunter发现的具体措辞问题；
- Defender是否因本轮争议触发；
- Judge是直接接受、要求返修还是拒绝；
- Agent耗时、Token与缓存命中；
- 最终采用实时AI还是固定保障。

若实时AI失败，不要反复点击同一按钮。记录失败阶段和原因，确认系统明确进入固定保障后，再决定是否新建Session补跑“实时AI成功”证据。固定保障证明系统可降级，不证明实时AI调用成功。
