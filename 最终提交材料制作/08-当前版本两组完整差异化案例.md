## 4. 多Agent链路的真实观察

本轮页面实际显示了以下流水线：

```text
教学依据准备
→ 学情画像分析
→ Generator生成内容
→ 确定性安全检查
→ Hunter反向找错
→ 编排规则按争议性与风险条件触发Defender
→ Judge最终裁决
→ 发布AI内容或固定保障
```

案例A的类型规范题组：

- Generator：15.7秒；
- 安检：40毫秒；
- Hunter：23.3秒；
- Defender：未触发；
- Judge：4.4秒；
- 页面总耗时：68.7秒；
- 发布结果：6道审核通过的AI题，来源 `ai_live`。

案例B的最终验证题组：

- 发布5道审核通过的AI题，来源 `ai_live`；
- Defender未触发，说明该次Hunter没有形成 `disputed=true` 的争议问题；这只能证明当前条件跳过生效，不能简化为“只有高风险才触发”；
- 最终答题5/5，综合代码5/5。

## 5. 本轮同时观察到的问题

这些现象不能从成功案例中删掉，后续回归需要覆盖：

1. 案例A在重复订单题组提交时出现过 `idempotency_conflict`。加载最新服务端快照后再次提交仍冲突，说明同一Attempt的请求身份或提交内容发生了不一致。为不篡改服务端事实，本轮从已确认路径继续后续章节，没有把该次提交伪造成成功。
2. 类型规范代码首次提交因草稿缺少 `import pandas as pd` 而 `runtime_error`，5个测试点均未运行；补入导入后新Attempt真实得到 `5/5`。这说明评测器会区分“代码未能运行”和“测试点判定失败”。
3. 实时AI链路延迟可达几十秒。页面读秒正常推进，能避免用户误以为网页卡死，但后续指标测试仍需单独统计P50/P95，而不能只引用单个案例。
4. 案例B最终总结使用“确定性事实摘要”，未显示画像Agent生成文本；本案例只证明确定性总结可用，不把它写成画像Agent实时调用成功。

## 6. PPT建议用法

- 案例A用于说明“从不会到会”：展示错题诊断、补救题组、代码实操与进步画像。
- 案例B用于说明“会的不用重复学”：展示双证据诊断、用户可控跳过、88分钟短路径与案例优先正文。
- 两组并排时突出三个数字：`290 → 88分钟`、`30 vs 16条Evidence`、`0 vs 5个主动跳过章节`。
- 多Agent效果页只展示公开阶段、状态、耗时、风险和裁决，不展示模型隐藏思维链。
- 当前案例不包含Judge `revise` 后Generator返修成功的轨迹；在返修闭环完成前，不得把 `revise` 后固定保障描述为Judge最终 `rejected`。
