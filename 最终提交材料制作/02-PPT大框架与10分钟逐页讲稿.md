
三个核心痛点与解法：

| 现实痛点 | 项目解法 |
|---|---|
| AI生成专业内容容易出现幻觉 | 固定权威正文作为知识底座；Generator生成候选，确定性安检、Hunter、条件Defender和Judge分层审核AI动态内容 |

**时间：45秒**

屏幕内容采用“一个中心、三层能力”结构：

```text
中心目标：让不同基础的学习者掌握Pandas数据清洗实操能力
```

## 第3页：系统逻辑链——用户如何完成一次学习

**时间：50秒**

屏幕内容：

```text
选择目标与讲解偏好
→ 13道客观诊断形成Evidence
→ KnowledgeState与学情画像
→ 生成路径、预计时长与可选跳过章节
→ AI课前导学建立本章全局观
→ 学习当前Session绑定的权威正文版本
→ 多Agent生成并审核客观题
→ 代码补全与5个测试点正式评测
→ 根据作答更新画像、生成补救题或继续学习
→ 最终总结掌握、进步、跳过和未掌握内容
```

口播：

> 用户首先选择学习目标和讲解偏好，再完成13道客观诊断。每道答案都写成可追溯Evidence，并形成知识状态和学情画像。系统据此生成路径与预计时长；同一模块取得两类以上正确证据时，用户可以自主选择是否跳过。进入章节后，先由AI课前导学说明本节目标和前后关系，再学习Session绑定的一版权威正文。之后，多Agent生成并审核客观题，代码任务用5个测试点进行正式评测。所有结果继续更新画像：答错则生成补救题，仍未掌握但继续学习则保留缺口，最终总结完整呈现学习前后的变化。

页面角落增加图例：

```text
蓝色：确定性程序与正式评测
绿色：AI生成及多Agent审核
黄色：用户自主选择
```

## 第4页：为什么要这样设计——三个真实痛点

**时间：35秒**

屏幕内容只保留三句话：

1. AI专业内容存在幻觉风险；
2. 专业质量与个性化难以同时保证；
3. 学完理论不等于具备实操能力。

口播：

> 这条产品逻辑来自三个真实矛盾。第一，通用大模型可能生成看似合理但不符合专业规则的内容。第二，严格约束模型时，内容容易千人一面；追求个性化时，又可能牺牲专业准确性。第三，用户看懂概念，并不代表能够处理真实数据。下面分别说明我们如何解决这三个问题。

配图建议：三列问题图，并分别用箭头指向后续“多Agent审核”“专业底座加个性化导学”“理论加代码实操”三套方案。

## 第5页：痛点一解法——多Agent审核降低幻觉

**时间：65秒**

屏幕内容：八工位流水线。
面对决策，采用 学情分析+博弈论 ，多层审核保障，降低幻觉

```text
教学依据准备
→ 学情画像Agent分析
→ Generator生成
→ 确定性安检工位（程序规则）
→ Hunter反向找错
→ Defender条件辩护
→ Judge最终裁决
→ 发布AI内容或切换固定保障
```

角色口径说明：Safety是流水线中的独立确定性安检工位，不是模型Agent，也不调用大模型。它使用程序规则检查输出Schema、来源绑定、题目和选项重复、旧题复用、跨题答案提示、越权字段及敏感信息。其余需要语言理解与判断的生成、找错、辩护和裁决任务由模型Agent完成。

口播：

> 对AI动态生成内容，我们没有采用“调用一次API就直接展示”的方式。Generator先根据当前章节正文和用户画像生成候选内容；确定性安检检查结构、知识覆盖、题目独立性和安全边界；Hunter专门寻找题干、选项、答案、解析与正文依据之间的矛盾，但只有提出问题和证据的权力；存在语义争议或高风险时，由Defender逐项承认或反驳；Judge是唯一最终裁决者，决定接受、返修还是拒绝。模型超时、结构错误、返修预算耗尽或审核未闭合时，系统明确降级到固定保障内容，而不会把失败结果冒充AI成功。

屏幕下半部分增加“它具体拦住了什么”表格：

| 候选问题 | 谁发现 | 系统处理 |
|---|---|---|
| 题目或解析超出教学正文、答案不能由正文唯一支持 | Hunter提交问题；必要时Defender辩护；Judge裁决 | Judge确认后返修或拒绝，Hunter不能直接否决 |
| 题目ID重复、选项重复、重做时复用旧题、跨题提示答案 | 确定性安检 | 第一次退回Generator定向修复；重复违规则停止AI发布 |
| 错别字、明显语病、题意含混或选项不互斥 | Hunter题面清晰度审查 | Hunter报告证据，Judge确认后给出`revise`；未闭合不得发布 |
| Agent输出字段缺失、来源未绑定、越权改变路径或判分 | 确定性安检与Judge | 结构错误受控修复；权威/安全边界冲突由Judge拒绝并切换固定保障 |
| 模型超时、服务异常或审核链未闭合 | 服务端运行合同 | 标记真实失败来源，进入固定保障或明确不可用 |

补充口播：

> 这条链解决的不是抽象风险，而是具体的模型输出问题。例如，题目不符合正文、答案不唯一时，Hunter负责提交问题，Defender处理需要辩护的争议，Judge独立确认是否阻止发布；题目ID、选项或旧题重复，以及题目之间互相泄露答案，会被确定性安检直接退回Generator；错别字、明显语病和题意含混属于Hunter的题面质量审查。结构性失败允许受控修复；Judge确认可修复的问题应返回Generator并完整重审，只有触碰安全边界、争议未闭合或返修预算耗尽才拒绝。当前本地真实轨迹已经记录过安全检查退回、Hunter审查合同重试、Judge裁决和模型服务异常，最终PPT应配一条真实run截图，而不是只放流程示意图。

必须展示的真实证据：

- 页面上的实时Agent流水线截图；
- `runId`、工位状态、耗时、公开摘要和裁决；
- `ai_live`或`profile_fixed`来源标签；
- 最终资源SHA-256。

制作证据备注：

- 当前本地110条run中已观察到9次确定性合同退回修订、1次重复违反合同后停止AI发布、3次Judge权威边界修复、2次Hunter审查合同异常和2次模型服务异常；最终使用前需重新从冻结案例统计。
- 自动化负例已覆盖题目ID重复、选项重复、旧题复用、跨题答案提示、来源不匹配、答案与正文冲突等情况。
- “错别字回退”只能在真实Hunter轨迹捕获到明确措辞问题后写成现场案例；否则PPT应写为“Hunter具备题面清晰度与措辞审查职责”，不能虚构已经发生的错别字案例。

## 第6页：多Agent具体参与哪些决策

**时间：50秒**

屏幕内容：

| 决策场景 | 使用的信息 | 最终结果 |
|---|---|---|
| AI课前导学 | 当前章节版本、前序章节、当前画像 | 本节目标、承上启下关系、学习主线和重点建议 |
| 首轮客观题 | 当前章节正式正文、规则与来源 | 4至6道经过审核的中文单选题 |
| 错题补救 | 正文、上一轮错题与解析、薄弱知识点、画像建议 | 对错误知识点进行重复考察的新题组 |
| 学习总结解释 | 初始诊断、过程Evidence、通过/失败/跳过事实 | 学习成果、遗留问题和后续建议 |

口播：

> 多Agent链不是只在某一个演示页面出现，而是服务于多个AI决策场景：课前导学、首轮题组、错题补救和最终学习解释。需要强调的是，路径计算、跳过资格和代码判分由确定性规则负责，Agent只基于这些事实生成解释或内容。这样既保留个性化，也避免模型篡改客观事实。

配图建议：四个场景围绕同一条Agent流水线，标出“AI生成”和“确定性事实”的边界。

页面右侧增加“条件式调度：不为完整而完整（控制Token、延迟和调用成本）”流程：

```text
是否命中同一正文、版本、画像/补救上下文的已审核缓存？
├─ 是 → 跳过Generator和重复审核，复用带哈希的已接受结果
└─ 否 → 调用Generator
         ↓
       确定性安检是否通过？
       ├─ 否 → 返回Generator定向修复；重复失败则停止AI发布
       └─ 是 → Hunter逐题审核
                ↓
              程序路由器按预设规则判断：Hunter找出的问题能否由代码直接验证？
              ├─ 能 → Defender明确跳过，交Judge确认
              └─ 不能/存在语义争议或高风险 → Defender逐项辩护
                                             ↓
                                           Judge最终裁决
                                            ├─ accepted → 发布
                                            ├─ revise → Generator受控返修并完整重审
                                            └─ rejected → 固定保障
```

补充口播：

> 为了控制Token、延迟和调用成本，我们没有让每次请求机械地跑完整条链。只有正文版本、画像或补救上下文、模型和提示词版本等缓存键全部一致时，才复用已经审核通过并带哈希的结果，本次不重新调用Generator，也不重复消耗Hunter、Defender和Judge。新候选先过确定性安检，不合格就提前退回，不浪费后续Agent调用。Hunter仍会审核每一组新候选，但它只能提交问题和证据；是否触发Defender由编排规则根据确定性可验证性、`disputed`和风险等级判断。无争议的确定性问题可跳过Defender，高风险或语义争议必须辩护，再由Judge完成最终裁决。

必须展示的效率证据：

- 一条缓存命中后Generator为`skipped`的真实run；
- 一条无争议时Defender为`skipped`的真实run；
- 一条争议触发Defender的真实run；
- 三条run各自的总耗时和模型调用次数。

## 第7页：痛点二解法——专业底座与个性化决策双轨并行

**时间：50秒**

屏幕内容分成左右两条轨道：

```text
专业质量轨道
六个Pandas知识点 × 统一规则与来源 × 三种讲解版本

逐步讲解 → guided
重点速览 → concise
案例优先 → practice

个性化决策轨道
讲解偏好 → 选择正文版本
诊断Evidence → 形成知识状态、路径和跳过资格
当前画像与历史学习 → 生成课前导学重点
错题与代码结果 → 更新薄弱点和补救方向
```

正文主线：读取CSV→检查结构→处理缺失→处理重复→规范类型→验证结果。

口播：

> 我们用两条轨道同时解决专业质量与个性化。专业质量轨道以六节权威中文正文为底座，每节三种版本绑定相同的专业规则、知识覆盖和来源，只改变讲解组织方式。个性化轨道则持续使用用户事实：讲解偏好选择正文版本；诊断Evidence形成知识状态、路径和跳过资格；当前画像与历史学习决定课前导学重点；后续错题和代码结果继续更新薄弱点与补救方向。因此，个性化不是牺牲专业内容，而是在同一专业边界内改变讲解、顺序、提醒重点和练习重点。

必须强调：正式正文是权威内容，AI只能补充个性化导学和练习，不能替换或删减正文。

## 第8页：用户画像贯穿整条学习决策链

**时间：50秒**

屏幕内容采用“画像输入→参与决策→形成输出”的时间线：

| 学习阶段 | 写入画像的事实 | 个性化结果 |
|---|---|---|
| 开始学习 | Python/Pandas经验、讲解偏好 | 选择讲解版本，形成初始画像背景 |
| 诊断阶段 | 13道题的正确、错误和Evidence | 识别已有基础与薄弱模块，计算路径和可选跳过 |
| 进入章节 | 当前章节、前序学习、掌握状态 | 生成承上启下的课前导学、学习主线和重点建议 |
| 客观题作答 | 错题、正确答案解析、对应知识点 | 诊断错误知识点，形成补救建议和下一轮出题重点 |
| 代码实操 | 5个测试点的通过与失败事实 | 更新理论与实操掌握差异，保留未掌握缺口 |
| 最终总结 | 初始状态、全程Evidence、跳过与补救结果 | 展示进步、已掌握、未掌握和后续学习建议 |

口播：

> 用户画像不是开始时填写一次就不再变化。初始经验和讲解偏好形成画像背景；13道诊断把每个知识点的正确与错误转化为Evidence；进入章节时，画像与历史学习共同生成课前导学。更关键的是，用户答错以后，系统不是简单换一套随机题，而是定位错题对应知识点，把上一轮错题与解析、当前正文和画像补救建议一起送入下一轮生成链，要求新题再次考查薄弱点。代码测试点结果也会继续写入学习事实，最终总结展示整个学习前后的变化。

配图建议：中间放一条不断累积的“Learner Profile + Evidence”纵轴，左右连接诊断、课前导学、错题补救、代码评测和最终总结；右上角嵌入一张真实课前导学截图。

页面必须强调的边界：

- 画像Agent生成解释和建议，不直接改写正确答案、代码评分或权威正文；
- 路径和跳过资格依据Evidence与确定性规则计算；
- 所有补救题仍要经过Generator、安检、Hunter、条件Defender和Judge审核。

## 第9页：痛点三解法——从理论学习走向代码实操

**时间：50秒**

屏幕内容：

```text
权威正文
→ AI客观题检查概念理解
→ 代码补全检查实际操作
→ 5个测试点逐点反馈
→ 修改、重试或带缺口继续
```

口播：

> 每章学习后，用户先完成AI生成的客观题，检查是否真正理解概念；随后进入代码补全任务，在已有函数骨架的指定区域完成数据处理。题面包含明确要求和可下载的输入输出CSV。服务端使用合同版本的Node、Python和Pandas执行正式评测，并按“通过数量/总测试点数量”展示5个测试点结果。这样既检查理论，也检查用户能否真正处理数据。

配图建议：左侧客观题，右侧代码编辑器与5个测试点结果，中间用箭头连接。

## 第10页：答错之后，系统如何动态补救

**时间：45秒**

屏幕内容：

```text
首轮错题
→ 写入Evidence
→ 学情画像识别薄弱知识点
→ 生成补救建议
→ 正文 + 错题及解析 + 画像建议
→ 多Agent审核新题组
→ 再次作答或带缺口继续
```

口播：

> 个性化不是开始时选择一次偏好就结束。用户答错后，系统会保存对应知识点和Evidence，画像服务据此识别薄弱点并形成补救建议。下一轮题组同时绑定当前章节正文、上一轮错题与解析、以及画像建议，对错误知识点进行再次考察。如果用户仍未掌握但选择继续，该章节会被标记为未掌握，并在最终总结中明确体现。

必须展示的真实证据：首轮错题、补救上下文、第二轮题组、前后Evidence版本和总结页结果。

建议在截图旁标出服务端真实绑定信息：


这些字段只证明补救题使用了哪组安全上下文，不展示私有答案或模型隐藏思维链。

## 第11页：差异化案例与量化效果（这一页主要是数据展示，我想做出类似新模型发布的测评指标图，尽量图表等可视化）

**时间：55秒**

本页目标：同时回答“不同学习者得到了什么”和“多Agent相对直接生成是否真的改善了结果”。

屏幕采用“上方指标卡 + 左下案例对比 + 右下Agent前后对照 + 底部代价条”布局。

### 11.1 上方：四张正式指标卡

| 指标 | 正式结果填写格式 | 赛题/设计门禁 | 样本与方法 |
|---|---|---:|---|
| 专业知识幻觉率 | `【错误原子事实数】/【已裁决事实数】=【百分比】` | `<5%` | 3个完整案例 + 20个分层生成run，双人独立复核、分歧终裁 |
| 画像—资源难度适配准确率 | `【命中gold节点数】/【可判定节点数】=【百分比】` | `≥85%` | 60个冻结画像案例，同时报告三类画像分组值和95%威尔逊置信区间 |
| 核心知识点覆盖率 | `【满足全部必需证据的核心点数】/【核心点总数】=【百分比】` | `≥90%` | 扫描教、练、用、验、溯源和fallback全链证据 |
| 路径合法率 | `【合法案例数】/60=【百分比】` | `100%` | 预置、先修、跳过和补救约束确定性检查 |

## 二、全套PPT的表达纪律

1. 先讲痛点，再展示功能如何解决痛点，避免变成产品页面巡游。
2. “多Agent贯穿系统”应准确表述为：多Agent审核贯穿AI动态内容生成；诊断事实、路径、跳过资格和代码判分由确定性规则负责。
3. 专业性来自权威正文、统一规则和知识来源；三版本负责讲解方式差异。
4. 个性化既包括Session绑定的正文版本，也包括课前导学、路径、补救题组和最终建议。
5. 固定题保障是可靠性机制，不是AI生成成功；录制响应也不能写成实时模型证据。
6. 所有测试数字、案例结论和准确率必须能回到原始输入、运行轨迹和哈希复算。
7. 扩展性必须分清“已实现接口”与“未来可扩展场景”，不把迁移设想写成已完成案例。
