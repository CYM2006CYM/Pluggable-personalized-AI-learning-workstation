# Pi Study Helper 十分钟演示脚本（初稿）

> 现场涉及Hunter、Defender、Judge、返修和固定保障时，以[《09-多Agent审计链路逻辑与可视化说明》](./09-多Agent审计链路逻辑与可视化说明.md)为唯一解释口径。

> 建议总时长：9分40秒，预留20秒切换和网络抖动缓冲。脚本以真实运行页面为准；实时 AI 未成功时必须按兜底段落如实说明，不得把录制题组剪辑成实时调用。

## 一、演示目标

十分钟内证明四件事：

1. 系统能根据不同学习者输入形成不同学习路径；
2. 教学正文是固定可信底座，AI动态内容在正文约束下生成；
3. Generator、安检、Hunter、Defender（条件触发）和 Judge 的协作是真实可观察的；
4. 学习反馈会进入画像、补救和最终总结，代码活动有清晰题面和测试点结果。

## 二、演示前准备

- 使用最终候选 Git 提交和对应 Profile seal；
- 比赛方启动器已完成环境预检，终端显示 `mode=live_model`；
- 新建演示 Session，不恢复旧会话；
- 准备两组已脱敏案例：基础薄弱/逐步讲解、已有基础/重点速览；若时间允许加入案例优先/局部薄弱；
- 准备一条实时 AI 成功轨迹、一条错题补救轨迹和一条固定保障降级轨迹；
- 准备题面截图、AgentRun安全摘要、代码输入输出 CSV和最终总结截图；
- 浏览器地址固定为 `http://127.0.0.1:5173/`。

## 三、逐页脚本

### 0:00—0:25｜第1页：封面与一句话定位

**画面**：封面，显示产品名、Pandas数据清洗领域和团队信息。

**口播**：

> 我们的作品是 Pi Study Helper，一个面向 Pandas 数据清洗的个性化 AI 学习工作站。它不是调用一次大模型就直接给出课程，而是把专业知识底座、学习者画像、多智能体审核、真实代码评测和学习总结连接成一个闭环。

### 0:25—1:05｜第2页：真实问题与产品答案

**画面**：三个痛点和三条对应解法。

**口播**：

> 我们针对三个问题设计系统：专业内容可能出现幻觉；严格专业和个性化难以同时保证；看懂理论不等于能处理真实数据。我们的答案是固定可信正文加个性化导学，由Generator生成候选，确定性安检工位执行不调用大模型的规则检查，再由Hunter、条件Defender和Judge完成语义审核与裁决，最后用客观题和 Python 代码任务验证迁移。

### 1:05—1:45｜第3页：开始页与讲解偏好

**画面**：开始页，选择 Pandas 数据清洗目标和“逐步讲解”。

**操作**：展示三个中文讲解偏好，不选择“可用时间”作为学习内容入口；点击开始。

**口播**：

> 用户先选择目标和讲解偏好。偏好只决定当前 Session 绑定哪一套中文正文：逐步讲解对应 guided，重点速览对应 concise，案例优先对应 practice。正文事实和评分规则不会因为偏好改变。学习时长由诊断和路径计算产生，不让用户在开始页凭感觉替系统决定学习内容。

### 1:45—2:30｜第4页：客观诊断与学情画像

**画面**：诊断题页，展示单选/判断题、保存、上一题、跳过和进度；随后展示诊断结果。

**操作**：使用预先准备的脱敏答案快速完成诊断，打开画像区域。

**口播**：

> 诊断题全部是客观题，服务端按固定答案判分。每次回答形成可追溯 Evidence，聚合为 KnowledgeState。画像 Agent 不直接改分数和路径，而是解释已有事实：哪些知识点已有证据，哪些仍需支持，为什么后续会这样安排。

### 2:30—3:15｜第5页：路径、章节关系与跳过选择

**画面**：路径页，显示章节状态、预计时长、必学和可跳过节点。

**操作**：展示一组“可跳过”节点，并保留其中一节；切换到第二组案例时展示路径差异。

**口播**：

> 路径由确定性 PathEngine 根据目标、先修关系、知识状态和时间预算计算。满足多类证据的模块可以选择跳过，但跳过不等于学会，最终总结会保留这条事实。这里对比两组案例：基础薄弱用户保留更多章节；已有基础用户可以合法缩短路径。差异来自诊断证据和用户选择，不是模型随意编排。

### 3:15—4:00｜第6页：固定正文与 AI 课前导学

**画面**：学习页，先展示本节固定正文，再展示页面上方的“AI个性化课前导学”流水线。

**操作**：进入第1节“读取 CSV”，等待导学生成；展示本节概览、前后关系、学习主线和建议。

**口播**：

> 正式正文始终来自 Profile 资料包，页面先保证教材可读。AI课前导学是辅助层：它根据本节版本、章节关系和当前画像说明“这一节要解决什么、与上一节和下一节有什么关系、学习时抓住哪条主线”。它不能替换或删减正文。

### 4:00—5:25｜第7页：客观题实时生成与多Agent流水线

**画面**：客观题按钮和 Agent 流水线，依次展示 Generator、安检、Hunter、Defender（按实际是否触发）和 Judge。

**操作**：点击“进入正式活动”；等待阶段状态和读秒；展示题组题面、选项和来源。展开一条 AgentRun 安全摘要。

**口播**：

> 现在进入本节客观题。Generator读取当前选中的中文正文，生成四到六道独立单选题；确定性安检先检查字段、来源、重复和泄漏；Hunter反向寻找超出正文、答案不唯一、解析不支持或题面含混的问题，但它只能提交问题和证据；无法由程序直接验证的语义争议或高风险问题会触发Defender；Judge是唯一最终裁决者，决定接受、返修或拒绝。页面展示的是实际工位状态和耗时，不是装饰动画。等待期间按钮会显示当前阶段和已处理秒数，让用户知道系统仍在工作。

> 讲稿冻结注意：只有Judge `revise` 后的Generator返修闭环完成并留下真实运行证据，现场才可以口播“返修后重新审核”；当前代码中的 `revise` 仍会降级，未修正前必须如实说明为已知缺口。

**必须说清**：

> 如果页面显示“固定题保障”，表示实时 API、结构检查或审核链本轮没有形成可发布候选。这是明确降级，不把它记录为实时 AI 成功。

### 5:25—6:10｜第8页：答题、复盘与错题证据

**画面**：提交客观题；展示正确答案、原题题面、解析和当前得分。

**操作**：故意答错一题，提交并打开复盘；指出原题、正确答案和正文依据。

**口播**：

> 复盘不会只显示一个答案。系统同时保留原题题面、正确答案、解析和正文依据，让用户知道自己当时回答的是什么。错误会写入学习证据，并成为下一轮补救的输入。

### 6:10—7:05｜第9页：错题补救与画像更新

**画面**：重新生成题组页面，展示学情画像、上一轮错题和补救上下文，再展示新的 Agent 流水线。

**操作**：点击“使用新题组重试”；展示画像阶段识别的错题数量、Generator新题组和Judge结果。

**口播**：

> 重新生成不是简单换一套随机题。学情画像阶段会读取上一轮错题和当前知识状态，Generator同时参考正文、错误知识点和补救建议；新题必须重复考察暴露出的薄弱点，但不能逐字复用旧题。这样可以观察到“错在哪里、为什么补、补完后是否改善”的连续证据。

### 7:05—8:10｜第10页：代码补全与真实输入输出

**画面**：代码活动页面，完整题面、作答要求、已有 starter code、TODO 区域、公开小样例和 CSV 下载链接。

**操作**：展示只需填写 TODO 的代码补全方式；提交一版代码；展开测试点结果。

**口播**：

> 客观题验证概念，代码活动验证迁移。题面先说明输入、输出、处理规则和限制，用户只补全 TODO 区域，不需要从空白写完整程序。页面提供公开小样例和可下载 CSV；服务端在合同 Python 环境运行，结果按多个测试点统计，显示通过数量和公开错误分类，不泄漏隐藏测试和参考实现。

### 8:10—8:50｜第11页：失败分支与可恢复性

**画面**：代码或题组失败后的按钮；展示“修改代码重试/放弃进入下一环节”或“新题组重做/进入下一环节”。

**口播**：

> 失败不是无底洞。第一次未通过要求重做；第二次仍未通过，用户可以修改后重试，也可以放弃进入下一环节。放弃会把本节标记为未掌握，最终总结不会把它伪装成已完成。刷新、重启和重复提交由会话版本、幂等请求和检查点保护。

### 8:50—9:25｜第12页：最终学习总结

**画面**：总结页，展示初始状态、当前状态、进步、掌握、跳过、未掌握和后续建议；展示画像 Agent 生成过程状态。

**口播**：

> 最后，系统把初始诊断、学习过程中形成的 Evidence、客观题和代码结果、跳过记录以及未掌握缺口汇总起来。画像 Agent 负责把这些确定性事实解释成用户看得懂的总结：开始时会什么，学习后掌握了什么，哪里进步了，哪些章节主动跳过，哪些仍需要支持。生成期间页面展示画像 Agent 的阶段和读秒，避免用户误以为网页卡住。

### 9:25—9:40｜第13页：部署、证据与价值收束

**画面**：部署启动器、AgentRun摘要、案例对比和指标占位页。

**口播**：

> 作品可由比赛方在 Windows 合同环境中一键启动，Key只在当前进程内使用。最终材料会把案例、Agent中间数据、代码测试、运行环境和安全审计绑定同一版本。我们的价值是把专业可信、个性化学习和多Agent协同决策放进一个可运行、可复核、可迁移的工作台。

## 四、现场兜底话术

### 4.1 实时 API 超时或审核拒绝

> 本轮真实 API 已进入请求，但候选没有在时间预算内形成通过审核的结果，系统按设计切换固定保障。固定保障保护学习闭环；这条记录不计入实时 AI 成功案例。我们保留了之前同一版本的实时成功轨迹，可在安全摘要中查看。

### 4.2 页面打开但流水线不更新

> 我先检查当前章节 nodeId 和 AgentRun 是否一致。页面流水线只应显示当前节点的运行记录；如果切换章节后残留上一条记录，这是前端状态问题，不代表当前章节已经生成。我们会以服务端 AgentRun 和当前 Session 快照为准。

### 4.3 代码测试点没有全部通过

> 这里显示的是逐测试点评测，不是简单的 0/1。当前失败只说明这次提交没有满足相应合同；我可以按题面要求修改 TODO 后重试。隐藏测试、参考实现和私有输入不会展示给用户。
