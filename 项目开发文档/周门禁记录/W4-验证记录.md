## V4-5 阻塞

问题编号：W4-V4-5-REFRESH-001

复现步骤：

1. 在空临时数据目录启动固定端口 API 127.0.0.1:4310 和 Vite 127.0.0.1:5173。
2. 以推荐模式或章节模式建立合法会话、确认路径并打开题组。
3. 选择题目并提交完整题组；服务端返回 pass、Evidence 和安全答案复盘。
4. 直接刷新同一活动 URL。
5. 页面仍显示原题组和原 Attempt 草稿，回答数回到 0/n，没有显示 SUBMITTED_PROGRESS_RECOVERED。
6. 直接请求 /api/bootstrap?recoverSessionId=<sessionId> 时，服务端 currentAttempt 已为 null，说明服务端提交状态已存在，问题发生在前端恢复投影。

责任文件：

pi-study-helper/src/web/pages/ActivityPage.tsx:18

实际错误：

ActivityPage 从 React Router 的 location.state.opened 初始化 opened。刷新活动 URL 时，历史 location.state.opened 仍被当作权威活动草稿，覆盖了 Bootstrap 的服务端提交状态。

正确行为：

- 刷新后必须优先读取 Bootstrap；
- 已提交活动显示 SUBMITTED_PROGRESS_RECOVERED；
- 不得重新显示旧题组草稿或创建替代 Attempt；
- 点击“进入下一活动”后，必须由服务端游标决定下一活动。

停止条件：

- 在修复前不得签署 W4 GO；
- 不得把本地 744 passed 写成整体 PASS；
- 只允许 Web 文件所有者修复 ActivityPage 恢复优先级，并新增推荐/章节提交后刷新反例；
- 修复后必须重新运行受影响 Web 测试、两条真实浏览器轨迹、全量 verify 和 git diff --check。
