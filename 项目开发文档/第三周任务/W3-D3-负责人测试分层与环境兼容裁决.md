# W3-D3 负责人测试分层、环境兼容与固定轨迹裁决

裁决标识：`W3-D47-TEST-LAYERS-1`
签发日期：`2026-08-09`
适用合同：`W3-C5/W3-R2`
绑定基线：`a0730d667a9429e395e92f687dbf6b2e0e0db179`

## 1. 裁决结论

本裁决新增D47，将第三周及后续MVP验证收敛为确定性测试、评测器集成测试和固定轨迹Demo测试。测试只证明对应能力层，不得因无关环境差异污染其他层结论，也不得为追求生产级覆盖扩展任务、依赖或基础设施。

第三周不使用真实API Key，不运行在线模型，不把网络、供应商或Key可用性设为门禁。负责人可在仓库外使用模型生成候选成功轨迹；候选经Schema、脱敏、权限和确定性结果审计后，冻结为录制响应。自动测试通过同一`ModelExecutionPort`和同一应用Schema使用假LLM/mock回放固定成功与失败轨迹。该结果只证明端口、编排、轨迹、fallback和护栏，不证明在线模型质量或可用性。

本裁决不修改D40的历史测量证据、正式环境锁原字节或`environmentHash`，不放宽Node/Python/Pandas、任务资产哈希、Rubric、墙钟、输出、源码和数据限制，不修改SDK、依赖或上传顺序。

## 2. 三层测试与汇总

| 层 | 目标入口 | 覆盖范围 | 环境要求 | 结论边界 |
|---|---|---|---|---|
| 确定性层 | `test:deterministic` | React、路由、DTO、状态、泄漏；领域、应用、仓储、静态协议和错误映射 | 不启动Python，不要求D40精确环境 | 只判断确定性实现和页面合同 |
| 评测器集成层 | `test:evaluator` | Node父进程、Python子进程、Pandas任务、公开/隐藏阶段隔离、限制、Rubric和错误归因 | Node/Python/Pandas及执行能力满足批准环境 | 只判断代码评测链，V3-3必须在本层执行 |
| 固定轨迹Demo层 | `test:demo:trace` | 假LLM经`ModelExecutionPort`回放固定成功/失败轨迹，验证turn顺序、Schema、脱敏、fallback和越权拒绝 | 不需要Key、网络或在线供应商 | 只证明离线模型边界和可复现演示，不证明在线模型能力 |
| 汇总 | `test:all` | 汇总前三层与既有门禁 | 保留各层原始环境和命令 | 不得把一层失败改写成另一层失败或PASS |

上述脚本名是目标统一入口。本裁决不要求立即修改`package.json`；脚本尚未实现时，验证者可用明确测试文件清单执行等价测试层，并在报告中登记实际命令、文件清单和项数。“脚本不存在”应记为执行入口待补或审计输入不完整，不得冒充业务实现失败。

## 3. Windows兼容口径

D40记录的`win32-10.0.26100-x64`继续作为原型测量事实和既有`environmentHash`输入，不倒改历史文件。后续运行兼容判断只硬校验：

```text
osFamily = win32
arch = x64
processTreeTermination = true
```

Windows补丁号和构建号必须记录，但默认不作为`environment_mismatch`阻塞条件。只有出现可复现证据证明某项批准能力依赖特定构建号时，才能由负责人另行裁决收紧。

Node `v22.23.1`、Python `3.13.7`和Pandas `3.0.5`继续作为第三周正式评测器集成层的精确环境值。C现有适配器若仍比较完整Windows release，属于D47生效前的严格行为；仅当该比较成为A/E可复现的唯一阻塞时，由C按D3-D5既有响应边界做单一所有者最小修正。修正不得改变正式环境锁历史字节，不得顺带放宽版本、进程树、资源、哈希或隔离要求。

## 4. 固定轨迹Demo规范

### 4.1 轨迹来源与冻结

1. 使用简单、固定、无敏感资产的Pandas学习任务。
2. 负责人可在仓库外调用模型生成候选成功轨迹；真实Key、请求头和原始供应商日志不得进入Git、fixture、截图、交接包或普通日志。
3. 冻结前逐项验证公共Schema、turn顺序、最大turn、超时、权限边界、脱敏结果和最终分类。
4. 冻结后登记规范化文件SHA-256、生成方式、模型标识和审计日期；后续修改必须生成新轨迹版本，不覆盖旧证据。
5. 自动测试只由假LLM/mock回放冻结轨迹，不进行真实网络调用。

### 4.2 最小轨迹集合

- 一条固定成功轨迹；
- 一条无效JSON或Schema错误轨迹；
- 一条超时或provider错误轨迹；
- 一条越权请求轨迹，证明Agent不能修改mastery、KnowledgeState、路径、评分、Rubric或gold；
- 对失败轨迹使用确定性fallback，并记录是否触发。

轨迹断言只针对端口输入输出、Schema、turn顺序、状态转换、脱敏、护栏拒绝和fallback，不逐字断言自然语言措辞。隐藏测试、参考实现、私有CSV、原始标注、绝对路径和密钥不得进入轨迹或Agent上下文。

### 4.3 结果声明

第三周及现场演示统一记录：

```text
LIVE_NOT_RUN
MOCK_FALLBACK_USED（仅在实际使用fallback时）
```

`LIVE_NOT_RUN`是按合同主动不运行在线模型，不是业务失败，也不得写成在线模型PASS。固定轨迹测试通过时只可表述为“录制响应/mock集成通过”或“离线模型边界通过”。现场演示必须保留同一固定轨迹fallback，避免网络、Key或供应商状态影响闭环。

## 5. 验证归因与门禁

验证报告使用以下事实分类，不新增21号公共业务错误码：

- `CODE_DEFECT`：对应层实现或断言存在可复现缺陷；
- `ENVIRONMENT_MISMATCH`：评测器集成层的精确运行时或能力不满足合同；
- `AUDIT_INPUT_INCOMPLETE`：审计包缺少执行所需文件、依赖上下文或命令；
- `LIVE_NOT_RUN`：按D47不执行在线模型；
- `MOCK_FALLBACK_USED`：固定失败轨迹触发录制fallback。

V3正式结论仍只允许`PASS`或`BLOCKED`。执行事实可以登记未执行及原因，但不得用未执行冒充PASS。D4必须逐层报告：

1. V3-3只能由批准环境中的评测器集成层结果支持，网页或静态测试不能替代；
2. 评测器环境不匹配不应把已通过的确定性层改写为失败；
3. 固定轨迹Demo不替代V3-1至V3-8中的确定性、评测器或事务门禁；
4. W3 GO仍要求适用的V3项全部PASS、完整gold冻结、Profile事务激活和既有仓库门禁通过。

## 6. 岗位边界

- A：运行并报告A拥有的确定性层测试；评测器环境问题按层记录，不冒充A实现失败。
- C：维护评测器集成层；Windows按family、arch和能力判断，Node/Python/Pandas继续精确锁定。
- D：继续交付D1已冻结的录制响应、成功/失败/fallback和越权拒绝材料；不承担真实Key或实时模型开发。
- E：D2执行前端确定性门禁，D4按层独立复验并逐层给出证据；不要求持有Key。
- 负责人：审计并冻结候选轨迹、登记哈希和能力声明；不得把mock结果宣传为在线模型结果。

本裁决不增加B任务，不修改标注、TaskBundle或gold规则。
