## 版本一：逐步讲解 `guided`

### 学习目标

**需要了解**

1. `None/NaN/pd.NA`、空字符串和纯空格在数据中的区别。
2. 为什么同样是“空”，放在不同字段中会产生不同业务后果。
3. 为什么缺失处理必须保留原始输入并按固定顺序执行。

**需要掌握**

1. 使用`isna/notna`和字符串检查识别真正缺失与空白文本。
2. 删除缺失`order_id`的记录，同时保留缺失`customer_id`等有效订单。
3. 将缺失`note`规范为空字符串，不把未知金额或日期伪造成具体值。
4. 编写不修改输入、结果可重复验证的缺失处理代码。

### 先建立直觉：空白不只有一种含义

看到空单元格时，最危险的反应是“把有空的行全删掉”。订单号缺失时，我们无法知道这条记录属于哪一张订单，删除有明确理由；客户号缺失时，订单本身仍可能有效，删除会丢失真实交易；备注本来就是可选信息，可以用空字符串表示没有备注；金额未知则不能擅自填0，因为0元和金额未知是完全不同的业务事实。

因此，缺失值处理不是一个通用按钮，而是一张字段决策表。代码要先识别缺失，再依据列的角色选择删除、保留或规范化。

### 把概念拆开

#### 1. pandas怎样表示缺失

先用四个最小值观察pandas的判断结果。注意空字符串和纯空格虽然看起来“没有内容”，但并不会自动成为缺失标记。

```python
print(pd.isna(None))   # True：Python空值
print(pd.isna(pd.NA))  # True：pandas统一缺失标记
print(pd.isna(""))     # False：空字符串仍是字符串
print(pd.isna("   "))  # False：纯空格也不是缺失标记
```

`NaN`常见于数值列，`pd.NA`常见于可空字符串等扩展类型，`None`是Python对象层面的空值。对学习者而言，不需要死记内部差异，先掌握统一入口`pd.isna`。但空字符串和纯空格必须额外检查，否则`order_id="   "`会被误认为有效订单号。

【术语注释：缺失标记】缺失标记是用来表达“这里没有已知值”的特殊表示。它不等于数字0，也不等于文本`"未知"`。

#### 2. 关键标识order_id决定记录是否可用

订单号既可能是真正缺失，也可能只包含录入空格。代码要先统一字符串表示并去空格，再决定是否保留整行。

```python
order_id = df["order_id"].astype("string").str.strip()  # 先去首尾空格
invalid_id = order_id.isna() | order_id.eq("")          # 缺失或空白都无效
clean_df = df.loc[~invalid_id].copy()                    # 只删除这些行
clean_df["order_id"] = order_id.loc[~invalid_id]
```

`order_id`是订单记录的关键标识。没有它，后续无法可靠去重，也无法验证唯一性。先转为pandas字符串并去空格，可以把`" O001 "`规范为`"O001"`，也能识别纯空格。

【术语注释：布尔掩码】布尔掩码是一列`True/False`值，用来选择满足条件的行。`~invalid_id`表示选择“不是无效订单号”的行。

### 缺失、空白和未知为什么要分开

数据库或CSV中的空单元格通常表达“没有提供值”，但空字符串可能是明确保存的一段零长度文本，纯空格则可能来自手工录入。对订单号而言，三者最终都不能作为有效标识；对备注而言，缺失可以规范为空字符串；对金额而言，缺失必须继续表达未知，不能因为程序需要数字就改成0。

还要区分“未知”和“不适用”。客户号缺失表示当前不知道客户是谁，但订单仍存在；备注为空表示这条订单没有需要补充的文字。若把两者都写成`"未知"`，程序无法分辨这是原始内容还是人工填充。保留pandas缺失语义，可以让后续统计和审计看见真实不确定性。

```python
unknown_customer = pd.NA  # 值未知，继续保留缺失
empty_note = ""           # 合同明确允许没有备注
zero_amount = 0            # 一个真实数值，绝不能代表未知金额
```

### 判断顺序：先整理表示，再做业务选择

`order_id`可能是`None`、`pd.NA`、空字符串或纯空格。若先调用`notna`，纯空格会通过；若直接`astype(str)`，缺失可能变成可见文本。正确顺序是使用可空字符串类型、去首尾空格、同时检查缺失和空字符串，最后才筛选行。

```python
ids = df["order_id"].astype("string")  # 保留pd.NA
ids = ids.str.strip()                   # 去掉录入空格
keep = ids.notna() & ids.ne("")        # 再执行业务判定
```

这个顺序也使代码容易解释：前两行只是规范订单号的文本表示，第三行才是“记录是否可用”的业务规则。把表示整理和业务判定分开，学习者可以逐步观察每一列发生了什么。

#### 3. customer_id缺失仍要保留订单

客户号缺失只表示当前无法确认客户身份，不能据此否定订单本身。这里应先统计并保留这种未知状态。

```python
missing_customer = clean_df["customer_id"].isna()
print(int(missing_customer.sum()))  # 只统计，不删除
```

客户号可能因上游同步延迟而暂时缺失，但订单号、金额和日期仍具有价值。这里保留pandas缺失值，不填假客户，也不删除整行。后续验证可以继续如实看到“客户未知”。

#### 4. amount、日期和状态的空值不等于0或默认状态

金额未知、日期未知和状态未知都没有可推导的默认答案。下面先对比“伪造默认值”和“保留原始未知”两种做法。

```python
# 错误：未知金额被改成真实的0元
wrong_amount = clean_df["amount"].fillna(0)

# 正确：本节保留缺失，交给类型阶段统一转换
amount_source = clean_df["amount"].copy()
```

日期缺失不能填今天，状态缺失不能默认`pending`。这些默认值会创造资料包中不存在的业务事实。缺失阶段只保证记录是否保留，具体类型和允许值在后续处理。

#### 5. note可以安全规范为空字符串

备注属于可选文本，合同明确批准缺失转为空字符串。这个许可只适用于备注，不能推广到其他字段。

```python
clean_df["note"] = clean_df["note"].astype("string").fillna("").str.strip()
```

备注是可选文本，合同明确允许缺失转空字符串。这样后续显示和比较更稳定，同时不虚构备注内容。`fillna("")`之所以在这里合法，是因为规则按字段明确批准，而不是因为所有缺失都能填空。

### 跟着四条订单走一遍

下面构造四条只保留本节相关字段的公开小样例，用来同时观察删除、保留和填空三种动作。

```python
sample = pd.DataFrame({
    "order_id": [" O001 ", None, "   ", "O004"],
    "customer_id": ["C001", "C002", None, None],
    "amount": ["88", "66", None, None],
    "note": [" 首单 ", "主键缺失", None, None],
})
```

第二条没有订单号，第三条只有空格，都应删除；第四条客户号、金额和备注缺失，但订单号有效，所以保留。执行关键标识规则：

```python
result = sample.copy(deep=True)                     # 不修改输入
ids = result["order_id"].astype("string").str.strip()
result = result.loc[ids.notna() & ids.ne("")].copy()
result["order_id"] = ids.loc[result.index]
result["note"] = result["note"].astype("string").fillna("").str.strip()
```

预期只剩`O001`和`O004`。`O004.customer_id`仍缺失，`O004.amount`仍缺失，`O004.note`变为空字符串。这正是字段语义不同带来的结果。

### 哪里容易错

#### 反例一：整表dropna

整表删除会把任何字段缺失都当成记录无效，最容易误删缺客户号或缺备注但仍有效的订单。

```python
result = df.dropna()  # 错误：任何列缺失都会删除订单
```

```python
ids = df["order_id"].astype("string").str.strip()
result = df.loc[ids.notna() & ids.ne("")].copy()  # 正确：只按主键决定删行
```

#### 反例二：把未知金额填0

0元是一项确定金额，不是“尚不知道金额”。下面的填充会凭空创造业务值。

```python
result["amount"] = result["amount"].fillna(0)  # 错误：伪造零金额
```

```python
amount_missing = result["amount"].isna()  # 正确：保留并登记未知
```

#### 反例三：只用isna检查订单号

仅检查缺失标记会放过空字符串和纯空格，因此必须在字符串规范化后再组合条件。

```python
valid = df["order_id"].notna()  # 错误：纯空格仍会通过
```

```python
ids = df["order_id"].astype("string").str.strip()
valid = ids.notna() & ids.ne("")  # 正确：同时拒绝空白文本
```

#### 反例四：直接在输入上修改

原始DataFrame还要支持重试和审计。使用`inplace`删行会让调用者再也拿不到同一输入。

```python
df.dropna(subset=["order_id"], inplace=True)  # 错误：调用者输入被污染
```

```python
result = df.loc[valid].copy()  # 正确：返回独立结果
```

### 处理顺序为什么重要

先规范订单号空格，再判断是否为空；若先只调用`dropna`，纯空格订单号会漏网。先筛选有效订单，再对筛选后的索引回填规范订单号，可以避免索引错位。备注处理放在保留行确定后，避免对即将删除的行做无效工作。

```python
ids = df["order_id"].astype("string").str.strip()
keep = ids.notna() & ids.ne("")
result = df.loc[keep].copy()
result["order_id"] = ids.loc[keep]
```

### 如何解释处理后的结果

处理完成后，行数减少不一定意味着数据损失错误。若减少的每一行都来自无效`order_id`，这是合同要求；若客户号缺失导致行数继续下降，就是越权删除。可以同时记录删除数量和保留缺失数量，让结果具备解释性。

```python
removed = int((~keep).sum())
customers_still_missing = int(result["customer_id"].isna().sum())
```

备注为空的数量也可以统计，但不要把备注正文写进普通日志。金额和日期仍缺失不是未完成，而是本节有意把转换责任留给后续阶段。教学页面应明确显示“已保留，待类型规范”，而不是用模糊红色错误让学习者以为程序失败。

### 失败、重试与恢复

缺失处理函数不应把结果写回输入对象。若程序在处理备注时失败，调用者仍可以用原始DataFrame重试；如果原表已被`inplace`删除，恢复就只能依赖外部重新读取。独立副本使失败边界更简单，也能让同一输入重复运行得到同一结果。

```python
before = df.copy(deep=True)
try:
    result = clean_missing(df)
finally:
    assert df.equals(before)  # 成功或失败都不能污染输入
```

这不是生产级事务系统，而是比赛Demo中最小、可证明的失败保持性：原始事实没有被半写入，学习者可以修改代码后再次提交。

### 接到最终任务

缺失阶段为后续去重提供非空订单号，为类型转换保留真实未知值，为最终验证建立明确的备注规则。它不决定重复保留项，不转换日期和金额，也不判断状态是否合法。

```python
without_invalid_ids = clean_missing(checked_orders)
deduplicated = deduplicate_orders(without_invalid_ids)
```

完成本节后应满足：结果中`order_id`非空且非空白；缺失客户号仍存在；缺失备注已变成空字符串；金额和日期未知没有被伪造；输入DataFrame逐字段不变。

### 术语与依据

- **缺失标记**：表达值未知或不存在的特殊表示。
- **空字符串**：长度为0的文本，不会自动被`isna`识别。
- **布尔掩码**：用True/False选择DataFrame行的条件序列。
- **字段语义**：某列在业务中的含义，它决定缺失时如何处理。
- **伪造事实**：用0、今天或默认状态替代未知值，产生输入中不存在的信息。

## 版本二：重点速览 `concise`

### 学习目标

**需要了解**

1. 缺失处理是字段策略矩阵，不是统一清理动作。
2. `isna`与空白文本检查的边界。
3. 删除、保留和规范化三类动作对业务事实的不同影响。

**需要掌握**

1. 用向量化掩码稳定识别无效`order_id`。
2. 保留`customer_id/amount/order_date/status`未知状态，不制造默认值。
3. 规范`note`为空字符串并保持输入不可变。
4. 输出可复算的字段级处理摘要。

### 先冻结策略矩阵

| 字段 | 缺失动作 | 禁止动作 |
|---|---|---|
| `order_id` | 去空格后缺失/空白则删行 | 填编号、用客户号代替 |
| `customer_id` | 保留缺失 | 因此删行或填虚构客户 |
| `amount` | 保留行，后续非法转缺失 | 填0 |
| `order_date` | 保留行，后续解析失败转缺失 | 填今天或宽松猜测 |
| `status` | 保留行，后续非法转缺失 | 默认`pending` |
| `note` | 缺失转`""`并去空格 | 生成不存在的备注 |

先有矩阵，再写代码。否则`fillna`和`dropna`会把不同业务语义压成同一个动作。

### 统一识别主键空白

速览版把主键识别压缩为三步：转换为可空字符串、去首尾空格、组合非缺失与非空条件。

```python
ids = df["order_id"].astype("string").str.strip()
keep = ids.notna() & ids.ne("")  # 同时排除缺失和纯空格
```

这里使用pandas`StringDtype`，使缺失继续保持`pd.NA`，字符串操作不会把缺失简单变成文本`"nan"`。`str.strip`只去首尾空格，不改订单号内部字符。

```python
result = df.loc[keep].copy()
result["order_id"] = ids.loc[keep]
```

筛选和回填使用同一个布尔掩码，索引保持对齐。不要在筛选后使用无索引的列表赋值，否则可能把订单号放到错误行。

### 区分“未知”和“空文本”

`customer_id`未知要保留为缺失，因为“尚不知道客户”与“客户号是空文本”在审计上可以不同；`note`合同则要求最终为空字符串，便于显示和比较。

```python
customer_missing = result["customer_id"].isna()  # 保留缺失语义
result["note"] = result["note"].astype("string").fillna("").str.strip()
```

金额、日期和状态暂不填充：

```python
deferred = result[["amount", "order_date", "status"]].copy()
# deferred交给类型格式阶段，不在这里创造默认值
```

### 输入不可变与幂等

缺失处理需要同时证明两件事：调用没有污染输入，并且处理过的结果再次处理时不会继续变化。

```python
before = df.copy(deep=True)
result = clean_missing(df)
assert df.equals(before)  # 输入未改变
```

同一输入重复运行应得到相同字段值和行序。注意：若对已经处理过的结果再次运行，`note`仍为空字符串、订单号仍已去空格，结果也不应继续变化。这种性质让恢复和重试更可靠。

```python
again = clean_missing(result)
assert again.equals(result)  # 字段策略具有幂等性
```

【术语注释：幂等】同一个处理重复执行一次或多次，最终结果相同。

### 反例与修正

#### 全表删除

下面两种简写都不完整：第一种误删所有带空值的订单，第二种仍会保留纯空格订单号。

```python
result = df.dropna()                         # 错误：误删客户号缺失订单
result = df.dropna(subset=["order_id"])     # 仍漏掉纯空格订单号
```

```python
ids = df["order_id"].astype("string").str.strip()
result = df.loc[ids.notna() & ids.ne("")].copy()
```

#### 统一填充

把整张表的缺失都填成0，会同时破坏字符串、日期和金额语义。正确实现只能处理合同点名的备注列。

```python
result = df.fillna(0)  # 错误：字符串、日期和金额被混成一个默认值
```

```python
result["note"] = result["note"].astype("string").fillna("")
# 其他列按各自规则保留或后续转换
```

#### 把缺失转成文本

Python普通字符串转换可能把缺失标记变成可见文字，使后续非空判断失真。应使用pandas可空字符串类型。

```python
ids = df["order_id"].astype(str)  # 风险：缺失可能变成"nan"或"<NA>"文本
```

```python
ids = df["order_id"].astype("string")  # 保留pandas缺失语义
```

#### 索引错位

筛选后若转成普通列表再赋值，就失去了pandas按索引匹配行的保护。保留索引可以避免订单号写错记录。

```python
result["order_id"] = ids[keep].to_list()  # 风险：丢失索引关系
result["order_id"] = ids.loc[keep]        # 正确：按原索引对齐
```

### 处理摘要

处理摘要只记录规则执行数量，用于解释删了什么、保留了什么，不应复制客户号或备注原文。

```python
summary = {
    "removed_missing_order_id": int((~keep).sum()),
    "retained_missing_customer_id": int(result["customer_id"].isna().sum()),
    "empty_note_count": int(result["note"].eq("").sum()),
}
```

摘要记录数量，不输出原始客户号或备注内容。它能证明规则真实执行，但不产生学习Evidence，也不能代替最终DataFrame验证。

### 相邻阶段边界

本节允许去订单号空格和规范备注，因为合同直接规定；城市别名、状态小写、金额货币符号和日期格式属于类型阶段；重复订单选择属于去重阶段。把动作放错阶段会让单元测试难以定位，也可能改变三级去重所依赖的原始日期信息。

```python
missing_ready = clean_missing(structure_ready)
# 下一步才调用deduplicate_orders和normalize_types
```

### 规则实现应来自单一事实

不要在多个函数里分别维护“哪些列能填空”。缺失策略应来自Profile冻结规则，教学正文、代码活动和验证使用同一语义。即使当前代码直接写出列名，也要把它视为合同绑定，而不是开发者习惯。

```python
POLICY = {
    "order_id": "drop_row",
    "customer_id": "preserve_missing",
    "note": "fill_empty_string",
}
```

这张公开策略只表达动作，不包含私有预期值。若未来字段增加，必须先更新Profile和审核来源，不能在运行时根据数据内容自动决定策略。

### 掩码与可空布尔值

字符串比较可能产生可空布尔结果。把`isna`和`ne("")`组合时，要确认最终`keep`对每一行都有明确True或False。当前写法先用`notna`拦住缺失，再检查非空，得到可用于筛选的稳定条件。

```python
ids = df["order_id"].astype("string").str.strip()
keep = ids.notna() & ids.ne("").fillna(False)
```

虽然在当前pandas行为下前半条件已经足够保护缺失，显式`fillna(False)`能向读者表达安全意图。代码选择应在合同环境测试，不能只凭不同版本的印象。

### 错误分类和公开反馈

缺少`order_id`列属于结构错误，不应在缺失阶段伪装成“所有订单号都为空”；传入对象不是DataFrame属于输入合同错误；某些行订单号为空则是正常业务清洗。三者需要不同反馈。

```python
if "order_id" not in df.columns:
    raise ValueError("required_column_missing:order_id")

removed_rows = int((~keep).sum())  # 正常处理结果，不是程序异常
```

公开反馈可以说删除了多少条无标识记录，但不展示私有数据或隐藏预期。学习者需要知道规则为什么生效，而不是看到内部文件路径。

### 行序和索引保持

布尔筛选会保留被选记录的原始相对顺序，索引标签也可能保留原值。此时不必为了“看起来连续”立刻排序。是否重置索引属于比较和输出策略，不能改变记录顺序。

```python
result = df.loc[keep].copy()  # 保持被选行的相对顺序
result = result.reset_index(drop=True)  # 只重建索引，不排序记录
```

后续去重依赖原始相对顺序作为平局规则，因此更稳妥的实现会在需要时显式保存原始位置。缺失阶段至少不能打乱它。

### 内容检查与业务动作分离

金额中的`"N/A"`是否已经被读取器识别为缺失，取决于输入与解析配置。缺失阶段可以观察，却不应该重复实现完整金额解析。类型阶段统一去货币符号、处理非法文本和无穷值，才能保证一个事实源。

```python
amount_missing_now = result["amount"].isna()
# 只记录当前缺失；完整金额转换由normalize_types负责
```

速览版的核心不是把代码压成一行，而是让每个动作只改变合同允许的字段，并为相邻阶段留下清楚输入。

### 与最终任务的连接

最终结果要求`order_id`非空且唯一。缺失阶段只完成“非空”，唯一性由去重阶段完成。它还保证未知客户、金额和日期没有被伪造，为最终结果保留真实不确定性。

完成条件：删除规则只由`order_id`驱动；`note`规则明确；其他缺失按合同保留；输入不变；重复执行稳定；摘要可复算。

### 完成性判定

本节不能用“没有任何缺失值”作为成功标准，因为客户号、金额、日期和状态仍允许保持未知。真正的完成状态是：所有保留记录都有非空白订单号；缺失客户号没有引发行删除；备注不再使用缺失标记；其他未知值没有被填成伪造默认值；原始行序和输入对象保持不变。若缺少`order_id`列、传入对象不是DataFrame或结果仍含空白订单号，应明确停止；若只是金额dtype尚未规范，则正常交给类型阶段。这样的判定既严格，又不会要求当前小节承担后续职责。

### 术语与来源

- **字段策略矩阵**：按列明确缺失动作的规则表。
- **StringDtype**：pandas可空字符串类型，可保留`pd.NA`。
- **索引对齐**：pandas赋值时按行索引匹配数据。
- **幂等**：重复处理不继续改变结果。
- **延迟转换**：把金额、日期等动作留给职责明确的后续阶段。

依据来自`src-pandas-missing-data`和revision 3七列合同。

## 版本三：案例实战 `practice`

### 学习目标

**需要了解**

1. 删除有效订单、伪造零金额和伪造默认状态会造成什么业务风险。
2. 空订单号、空客户号、空金额和空备注为何不能统一处理。
3. 缺失处理结果怎样影响去重、类型转换和最终验收。

**需要掌握**

1. 根据订单字段决策表实现缺失处理函数。
2. 用最小样例验证删行、保留和填空三种动作。
3. 排查纯空格、文本`N/A`、索引错位和输入污染问题。
4. 形成可向下一阶段交接的结果和脱敏摘要。

### 业务场景：四条看起来“不完整”的订单

运营导出中出现四条记录：A缺订单号，B缺客户号，C缺金额，D缺备注。如果统一删除，四条都会消失；如果统一填0，客户号和备注会出现荒谬数值。真正合理的动作是：A因无法识别订单而删除；B、C、D保留；D的备注规范为空字符串；C的金额继续保持未知，等待类型阶段。

```python
sample = pd.DataFrame({
    "order_id": [None, "O002", "O003", "O004"],
    "customer_id": ["C001", None, "C003", "C004"],
    "amount": ["66", "88", None, "45"],
    "note": ["主键缺失", "客户缺失", "金额缺失", None],
})
```

真实公开订单中也有类似情况：一条记录缺订单号，应删除；有记录缺客户号，应保留；空金额和文本金额都要保留行；空状态不能默认成`pending`；空备注最终变成空字符串。现场处理时先把每种现象写进字段决策表，再运行代码，能避免“看见空就删”的本能反应。

### 先预测结果，再运行代码

对四行样例，运行前先写预期：输出3行；O002仍缺客户号；O003仍缺金额；O004备注为`""`。这种预测不是手工伪造PASS，而是教学中的显式业务规则。运行后逐项核对，才能知道代码是否按预期工作。

```python
expected_ids = ["O002", "O003", "O004"]
result = clean_missing(sample)
assert result["order_id"].tolist() == expected_ids
```

如果输出只有2行，应检查是否误把客户号或金额加入`dropna`；如果仍有4行，应检查空订单号掩码；如果O004备注仍是缺失，应检查`fillna("")`是否作用在结果副本。

### 第一步：复制输入并整理订单号

实战代码先建立独立结果，再把订单号整理成可比较的字符串。此时还没有删除任何记录。

```python
result = sample.copy(deep=True)  # 后续修改只作用于结果
ids = result["order_id"].astype("string").str.strip()
keep = ids.notna() & ids.ne("")
```

这一步同时处理`None`和纯空格。不要使用`astype(str)`，否则缺失可能变成普通文本，随后错误通过非空检查。

### 第二步：只删除不可识别订单

根据刚才得到的掩码筛选行，并把去空格后的订单号按原索引写回结果。

```python
result = result.loc[keep].copy()
result["order_id"] = ids.loc[keep]
```

结果保留O002、O003、O004。O002客户号缺失、O003金额缺失都不会触发删行。删除依据只有订单号，这是现场审计时最重要的可解释规则。

### 第三步：规范可选备注

保留行确定后，再处理可选备注。缺失变为空字符串，已有文本只去首尾空格。

```python
result["note"] = result["note"].astype("string").fillna("").str.strip()
```

O004的备注变成空字符串；其他备注保留并去掉首尾空格。代码没有为金额、日期或状态补默认值。

### 第四步：核对结果与输入

代码运行后不能只看行数，还要逐项证明无效主键已消失、允许缺失仍在、备注规则生效且原表未变。

```python
assert result["order_id"].notna().all()
assert result["customer_id"].isna().any()  # 缺客户号订单仍在
assert result["note"].fillna("").eq(result["note"]).all()
assert len(sample) == 4                     # 原始输入未删行
```

断言对应三类动作：无效主键已删除、允许缺失已保留、备注已规范。最后一条提醒我们不要用`inplace`污染输入。

### 现场故障一：纯空格订单号漏网

现场发现结果中仍有看似空白的订单号时，通常是代码只检查了`notna`，没有先去空格。

```python
keep = df["order_id"].notna()  # 错误："   "会被保留
```

```python
ids = df["order_id"].astype("string").str.strip()
keep = ids.notna() & ids.ne("")  # 正确：去空格后判断
```

### 现场故障二：客户号缺失导致误删

如果结果行数比预期更少，先检查是否把`customer_id`错误加入了删除条件。

```python
result = df.dropna(subset=["order_id", "customer_id"])  # 错误
```

```python
result = df.loc[keep].copy()  # 正确：删行只看order_id
```

缺客户号不等于订单不存在。误删会降低订单数，并使后续金额统计失真。

### 现场故障三：用0表示未知金额

金额列出现异常增多的0时，要确认这些0来自原始数据，还是由缺失填充错误产生。

```python
result["amount"] = result["amount"].fillna(0)  # 错误：未知变成0元
```

```python
amount_missing = result["amount"].isna()  # 正确：保留未知状态
```

后续类型阶段会把非法文本转为缺失，但不会把未知改成0。

### 现场故障四：字符串`N/A`和空值混在一起

`read_csv`可能已把部分`N/A`识别成缺失，也可能因配置不同保留文本。缺失阶段不应根据猜测统一金额，类型阶段会使用`pd.to_numeric(errors="coerce")`形成明确结果。

```python
print(result["amount"].head())  # 观察原始表示
# 不在这里替换N/A或货币符号
```

### 现场故障五：链式赋值和索引错位

筛选后直接赋值既可能面对不明确的视图，也可能因转列表丢失索引。应显式复制并按索引回填。

```python
result = df[keep]
result["order_id"] = ids[keep].to_list()  # 风险：副本不明确且索引丢失
```

```python
result = df.loc[keep].copy()
result["order_id"] = ids.loc[keep]  # 明确副本并按索引对齐
```

### 形成处理函数

把前面的公开规则合成一个职责单一的函数。它只处理主键缺失和备注，不夹带去重或类型转换。

```python
def clean_missing(df):
    result = df.copy(deep=True)
    ids = result["order_id"].astype("string").str.strip()
    keep = ids.notna() & ids.ne("")
    result = result.loc[keep].copy()
    result["order_id"] = ids.loc[keep]
    result["note"] = result["note"].astype("string").fillna("").str.strip()
    return result
```

函数只实现本节公开规则，没有去重、城市映射、日期解析或状态校验。职责窄，测试才清楚。

### 用边界样例做一次回归

除了普通缺失，还应加入纯空格、已有空字符串和已经处理过的输入：

```python
edge = pd.DataFrame({
    "order_id": ["   ", "O010", "O011"],
    "customer_id": ["C009", pd.NA, "C011"],
    "amount": ["10", pd.NA, "0"],
    "note": [pd.NA, "", " ok "],
})
edge_result = clean_missing(edge)
```

预期纯空格订单被删除，O010保留缺失客户和金额，O010备注保持空字符串，O011备注去空格后为`ok`，金额0仍是合法原值而不是缺失填充。这组边界能区分真实0和未知值。

### 失败恢复演练

假设第一次代码把`customer_id`也加入删除条件，测试发现行数过少。修正后重新运行时，必须从原始`edge`开始，而不是使用已经删过行的中间结果。

```python
before = edge.copy(deep=True)
first_try = clean_missing(edge)
assert edge.equals(before)  # 失败后仍可从同一输入重试
```

这说明输入不可变不仅是代码风格，也是学习重试和现场恢复的基础。每次Attempt都应面对相同冻结输入，错误结果不能半写回资料包或会话正式事实。

### 如何向学习者展示处理结果

页面可以显示“删除1条缺失订单号记录、保留1条缺失客户号记录、2条备注规范为空”，并解释每个数字的规则。不要只显示“清洗成功”，也不要展示被删除行的客户信息。用户需要看到系统为什么采取不同动作。

```python
summary = {
    "removed_invalid_order": len(edge) - len(edge_result),
    "customer_unknown": int(edge_result["customer_id"].isna().sum()),
    "note_empty": int(edge_result["note"].eq("").sum()),
}
```

这类摘要是教学与演示证据，不改变mastery。正式Evidence仍只来自合同规定的活动提交。

### 与去重规则的关系

去重必须按`order_id`分组。如果空订单号未删除，多条无标识记录可能被错误当成同一订单；如果订单号空格未去除，`"O011"`和`" O011 "`会被当作不同键。缺失阶段先建立非空、去空格的订单号，为三级去重规则准备稳定键。

```python
missing_ready = clean_missing(structure_ready)
assert missing_ready["order_id"].str.strip().ne("").all()
dedupe_ready = deduplicate_orders(missing_ready)
```

但本节不检查唯一性。发现重复是正常输入现象，真正选择保留记录要看日期可解析性、最新日期和原始顺序，由下一节完成。

### 实战交接摘要

交给下一工位前，计算三项不含原始内容的数量，帮助演示者说明处理结果。

```python
before_rows = len(df)
result = clean_missing(df)
summary = {
    "removed_rows": before_rows - len(result),
    "missing_customer_retained": int(result["customer_id"].isna().sum()),
    "empty_notes": int(result["note"].eq("").sum()),
}
```

摘要只记录数量，不展示客户号和备注原文。它帮助现场说明真实规则已执行，但不创建正式Evidence。

### 接到下一工位和最终任务

订单号已经非空后，下一工位才能可靠地按订单号分组并执行三级去重规则。

```python
missing_ready = clean_missing(structure_ready)
dedupe_ready = deduplicate_orders(missing_ready)
```

去重阶段现在可以假设订单号非空，并用它分组。类型阶段仍会面对未知金额和非法日期，这不是缺失阶段失败，而是刻意保留真实信息。最终验证将同时检查订单号非空、唯一和字段dtype。

实战验收时确认：只删除无订单号记录；纯空格也被识别；客户号缺失订单保留；备注缺失为空字符串；金额日期状态未被伪造；原表不变；重复运行结果一致。

### 术语与来源

- **主键/关键标识**：用于唯一识别业务记录的字段，本项目以`order_id`承担关键识别作用。
- **字段决策表**：逐列规定缺失动作，防止统一删除或填充。
- **链式赋值风险**：在不明确副本的切片上赋值，可能产生不可预期行为。
- **索引对齐**：按原始行标签把订单号写回正确记录。
- **脱敏摘要**：只记录数量与状态，不保存敏感原值。

缺失语义和API来自`src-pandas-missing-data`，字段动作来自revision 3公开合同。
