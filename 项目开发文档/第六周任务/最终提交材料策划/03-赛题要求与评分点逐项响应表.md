## 3. 评分标准响应策略

### 3.1 作品完整性：30分

评委需要看到的是一条真正跑通的链，而不是功能清单。主证据应使用一组完整案例贯穿：

```text
学习者输入
→ 客观诊断
→ Evidence与初始画像
→ 个性化路径和跳过选择
→ 匹配版本的教学正文
→ Generator生成题组
→ Hunter/Defender/Judge审核
→ 学习者作答和程序判分
→ 错误知识点补救
→ 代码活动
→ 画像、路径和总结更新
```

提交材料应明确每个Agent的输入、输出、权限和失败处理。视频优先展示真实状态变化、恢复和降级，不用大量时间浏览静态页面。

完整性失分风险：

- Agent只有名称，没有实际运行轨迹；
- 个性化只换文案，路径和资源没有差异；
- 题目生成后没有审核或审核结果不影响最终内容；
- 诊断、学习、判分和总结各自独立，Evidence没有贯通；
- API失败后页面卡住或用固定题冒充实时生成。

### 3.2 技术创新性：25分

重点表达四项技术设计：

1. Profile将专业知识、来源和评测资产从通用框架中解耦；
2. Generator—Hunter—Defender—Judge构成结构化高风险审核链；
3. Agent创造性与确定性程序权威分层，关键结果可复算；
4. 学情画像不是一次性标签，而是以正式Evidence贯穿学习并驱动下一题组。

创新性证据不应停留在架构图。应提供：同一Generator原稿、Hunter问题、Defender回应、Judge终稿的差异；展示一个错误被发现、修订或拒绝的具体例子；用20组配对盲评报告审核前后差异。

创新性失分风险：

- 只是顺序调用多个API，没有角色隔离、结构合同和路由条件；
- 所有Agent使用相同提示词，职责无差异；
- Judge无依据地重写，无法复核裁决；
- 固定规则包办所有个性化，Agent只生成装饰文字；
- 夸大为并行群体智能，而实现只有串行调用。

### 3.3 用户体验：15分

用户体验重点是自然、可理解、可恢复：

- 开始页只收集诊断前真正需要的信息；
- 路径解释“为什么学、为什么跳、预计多久”；
- 教学正文分模块、代码可横向滚动、长文本不重叠；
- Agent等待按钮显示当前阶段和秒数；
- 用户可返回、修改、重试、放弃或恢复；
- 客观题复盘包含原题、答案和正文依据；
- 代码题面包含完整要求、公开样例和下载入口；
- 失败和固定保障来源表达清楚。

用户体验证据应包含桌面、平板和手机截图，关键路径的浏览器自动化结果，以及真人试测中任务完成率、用时和问题记录。

### 3.4 实用价值：30分

以满分档为目标准备：

- 一个完整Pandas专业知识库切片和数据清洗任务；
- 三组不同学情完整案例，至少确保满足提交硬要求的两组；
- 专业知识幻觉率目标`<5%`；
- 难度匹配准确率目标`≥85%`；
- 核心知识点覆盖率目标`≥90%`；
- 证明系统能让学习者完成真实CSV清洗，而不只是回答概念题；
- 说明Profile合同如何迁移到新的职业技能领域。

上述百分比只有正式评测完成后才能写入实际值。材料必须同时给分子、分母、样本数和证据链接。

## 4. 三组建议案例

| 案例 | 初始特点 | 预期差异 | 必须实际证明的结果 |
|---|---|---|---|
| A：基础薄弱、逐步讲解 | Python/Pandas经验少，诊断多处错误 | 完整路径、guided正文、更多补救和脚手架 | 实际Evidence、题组、代码结果和前后画像 |
| B：已有基础、重点速览 | 多个模块双证据正确 | 可自主跳过已掌握章节、concise正文、更短路径 | 实际跳过选择、时长差异和最终实操 |
| C：实践偏好、局部薄弱 | 偏好案例优先，在去重或类型模块犯错 | practice正文、错误知识点定向新题组 | 实际Agent审核轨迹和补救后变化 |

“预期差异”只是案例设计，不能作为最终结果。每组都必须实际运行并保存输入、输出、哈希和截图。
