# Pi Study Helper 作品介绍

> 赛题：XH-202630 领域知识个性化生成与多智能体协同决策系统研究
> 当前示范领域：Pandas 数据清洗
> 文档用途：报名材料、PPT、演示视频和答辩的作品介绍母稿
> 文档状态：提交候选草案；最终提交前须按第6节补齐实测数据与版本信息

## 1. 作品概述

Pi Study Helper 是一套面向职业技能学习的可插拔个性化学习工作台。系统以“Pandas 数据清洗”为首个完整示范领域，围绕读取数据、理解表结构、处理缺失值、去除重复数据、修正数据类型和验证清洗结果六个核心知识模块，为不同基础、不同讲解偏好的学习者提供差异化学习路径、中文教学内容、动态练习和代码实操。

作品解决的不是“让大模型再写一篇教程”，而是三个更具体的问题：

1. 学习者已经会什么、哪里薄弱，系统应当有证据地判断，而不是只听自我评价；
2. AI生成的专业内容可能出错，需要多智能体质疑、辩护和裁决，而不是生成后直接展示；
3. 学习不是一次性推荐，系统应根据后续答题、代码测试和重试结果持续更新画像与下一步安排。

作品采用一句话可以概括的技术路线：

> 用Profile资料包固定可信知识与评测边界，用确定性程序保障路径和判分，用多智能体完成生成、审核、解释与个性化建议，再用持续学习证据驱动动态调整。

## 2. 面向的用户和真实任务

当前作品面向需要学习数据处理技能的学生、自学者和职业培训学习者。示范任务不是孤立记忆Pandas API，而是完成一条可复用的数据清洗链：

```text
原始CSV
→ 读取数据
→ 检查行列、字段和类型
→ 处理缺失值
→ 识别并处理重复记录
→ 修正日期、数值等字段类型
→ 验证清洗结果
```

同一个学习目标下，不同学习者会得到不同安排。例如：

- 基础薄弱且偏好逐步讲解的学习者，获得更完整的概念解释、反例、分步代码和更多练习；
- 已有基础且偏好重点速览的学习者，保留必要知识核验，减少重复讲解；
- 偏好案例优先的学习者，先从脏数据和处理任务入手，再回到概念和边界条件；
- 对某章节已经提供足够诊断证据的学习者，可以自主选择跳过该章节，也可以保留复习。

专业标准、权威答案和最终判分规则不会因学习偏好改变。变化的是学习顺序、讲解方式、练习重点、脚手架和补救内容。

## 3. 学习者看到的完整闭环

学习者的主要流程如下：

```text
选择目标和中文讲解偏好
→ 完成全客观、多证据诊断
→ 查看初始学情画像和证据
→ 确认个性化学习路径
→ 阅读匹配偏好的中文教学正文
→ 完成AI动态客观题
→ 查看题目、答案和正文依据复盘
→ 完成代码补全与最终独立实操
→ Node/Python权威评测
→ Evidence与KnowledgeState更新
→ 薄弱点触发补救题组或路径调整
→ 查看学习成果总结和后续建议
```

当实时模型可用时，系统依据当前章节正式教学内容、知识规则和学习者最新薄弱点生成题组，并经过Generator、Hunter、Defender和Judge协同审核。当模型请求失败、超时、格式不合格或审核不通过时，系统明确切换到经过审核的固定保障题，保证学习主流程可继续，并如实标记题组来源。

## 4. 核心能力

### 4.1 可追溯的学情诊断

系统使用13道全客观诊断题覆盖六个Pandas核心模块。每个核心模块至少包含“概念理解”和“代码或应用辨析”两类证据。程序把诊断答案写成可追溯Evidence，并确定性计算掌握度、置信度和KnowledgeState。诊断Agent负责把这些事实解释成易懂的学情报告，但不能私自修改分数或路径。

### 4.2 个性化路径与自主跳过

路径引擎依据知识先修关系、学习目标、Evidence和KnowledgeState生成合法路径。只有当某模块满足两类证据要求时，才允许学习者选择跳过；最终独立实操不因诊断而被跳过。预计学习时长来自实际保留节点的时长求和，不由用户在诊断前随意填写。

### 4.3 六节三版本中文教学内容

六个核心章节分别提供`guided`、`concise`和`practice`三套中文正文，对应逐步讲解、重点速览和案例优先。每套内容均包含学习目标、直觉与目标、概念拆解、数据演练、反例修正、最终任务、术语与来源，并配有与正文对应的代码示例和必要注释。

每个学习会话只绑定并传输与讲解偏好匹配的一套正文，另外两套不会同时进入浏览器。固定正文是权威教学内容；Agent可以补充个性化提示，但不能替换、删减或篡改正式正文。

### 4.4 多智能体生成与审核

作品包含职责分离的智能体角色：

| 角色 | 主要职责 |
|---|---|
| 学情画像Agent | 根据脱敏学习事实解释薄弱点、进步和未完成项 |
| Generator | 依据当前正文、知识规则和学习状态生成候选题或个性化提示 |
| Hunter | 主动寻找事实错误、歧义、超纲、难度错配、答案冲突和泄漏风险 |
| Defender | 在存在实质争议时逐项回应质疑，承认问题或提供依据 |
| Judge | 综合候选内容、质疑和辩护，决定接受、修订或拒绝 |
| 学习决策Agent | 解释确定性路径为何形成或为何变化 |

多智能体不是多个聊天框的装饰。角色使用隔离会话，交换结构化产物；程序保存阶段、状态、耗时、问题摘要、裁决结果、来源ID和哈希的安全投影。专业规则、正确答案、隐藏测试、Rubric和路径权威不交给Agent自由决定。

### 4.5 多层学习活动与权威评测

作品形成从理解到迁移的递进活动：

1. 中文学习正文：建立概念、方法和边界；
2. 客观题：检查概念理解与应用辨析；
3. 代码补全：在已有函数和明确填空边界中完成关键逻辑；
4. 最终独立实操：在正式提交后运行公开测试、隐藏测试和确定性Rubric。

客观题的题目与候选答案可以由AI生成并经多智能体审核，但学习者答案由程序按审核后的`correctAnswer`确定性判断。代码活动由Node/Python承担权威执行与判分。Pyodide公开预览保持关闭，页面不提供无效的浏览器预览入口。

### 4.6 可插拔领域资料包

Pandas专业知识不是散落在页面代码中，而是封装为可安装、校验、启用、修订和归档的Profile资料包。资料包统一管理知识点、先修关系、教学正文、来源、诊断题、活动、数据集、测试、Rubric和降级资源。框架通过统一合同加载资料包，因此后续扩展其他职业技能领域时，重点是制作新的知识资料包，而不是重写学习系统。

## 5. 作品创新点

### 5.1 “Agent创造力”和“程序确定性”分层

作品没有把所有决定都交给大模型。语言生成、风险发现、争议讨论和解释交给Agent；知识先修、证据计算、答案比较、代码判分、版本校验和安全边界交给确定性程序。这样既保留大模型的个性化能力，又避免关键结果不可复算。

### 5.2 高风险内容使用质疑—辩护—裁决机制

Generator生成后，Hunter从反方角度寻找问题；发生实质争议时才触发Defender；Judge依据结构化证据做最终裁决。该机制可与同一份Generator原稿构成公平的单Agent/多Agent配对比较，验证审核机制是否真正减少错误，而不是比较两次随机生成结果。

### 5.3 学情画像贯穿全程

画像不是开场的一张静态标签。诊断题、客观题、代码判分、重试、放弃和带缺口继续都会形成正式学习事件。确定性事实先更新，画像Agent再生成安全解释；错误知识点可以进入下一轮题组目标，最终总结展示学习前后变化、已掌握、仍薄弱、主动跳过和未掌握后继续等状态。

### 5.4 权威正文与动态个性化并存

系统不要求AI临场重新编写全部课程。固定RichLesson提供完整、可溯源、可离线使用的专业正文；实时AI根据当前正文和学习者状态生成题目、提示与解释。模型不可用时，正文和正式评测仍然可用，系统不会因AI故障失去基本教学能力。
