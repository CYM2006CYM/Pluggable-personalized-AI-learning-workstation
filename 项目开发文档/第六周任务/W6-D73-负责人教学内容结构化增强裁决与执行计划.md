## 4. 教学内容标准

### 4.1 三套独立正文

每个知识点必须提供三套独立中文正文，共`6 x 3 = 18`套：

| 版本ID | 页面名称 | 主要对象 | 写作重点 |
|---|---|---|---|
| `guided` | 逐步讲解 | 非计算机初学者和需要完整脚手架者 | 使用日常语言解释输入、代码、输出和每一步原因；专业词首次出现时立即注释 |
| `concise` | 重点速览 | 高基础学习者 | 压缩基础重复，突出业务规则、API边界、数据不变量、容易忽略的边界情况 |
| `practice` | 案例实战 | 实践导向学习者 | 先给订单业务场景和验收标准，再沿真实数据、代码、输出和排错清单推进 |

每套正文目标为`2000至3000个中文字符`。代码、字段名、URL、source ID和必要英文专业名不计入中文字符下限。不能通过重复同一句话、堆砌定义或复制另一个版本来达到长度。

三套正文的叙述、顺序、例子和解释密度必须显著不同，但必须覆盖同一组`canonicalRuleIds`和来源claim。任何版本都不得改变业务事实、把不确定建议写成冻结规则，或使用不同答案制造个性化。

### 4.2 固定教学模块

每套正文固定包含以下模块，不实现无分自测：

1. **为什么现在学**：结合当前路径、先修和最终订单清洗目标解释学习必要性；
2. **本节目标与先修回顾**：说明学完能做什么，并用简短中文提醒必要先修；
3. **核心概念**：拆成2至5个有标题的概念模块，先用通俗语言，再补准确术语；
4. **跟着数据走一遍**：给出公开输入、分步骤代码、逐步输出和每步解释；
5. **反例与修正**：至少两个真实反例，分别说明症状、原因、风险和正确改法；
6. **接到最终任务**：说明本节对`clean_df`的贡献和最终实操验收检查项；
7. **术语注释**：每个必要专业词给出中文白话解释，注明首次使用的模块；
8. **来源依据**：按claim列出sourceAnchor、官方来源名称、定位、版本/访问日期和Profile revision。

页面呈现时将第2项并入摘要区域，第3至8项按第8节的六个可展开模块组织。

### 4.3 六节内容边界

| 小节 | 必须讲清的事实 |
|---|---|
| 读取CSV | CSV、解析、DataFrame、路径/分隔符/表头的作用；读取不等于清洗；读取后必须进入结构检查 |
| 检查DataFrame | `shape/columns/dtypes/head/isna`各自回答什么问题；固定七列与列序；样例行不能证明整列合法 |
| 处理缺失值 | 缺失值、空字符串、`None/NaN/pd.NA`的通俗区别；`order_id`缺失删除行，其他列按冻结字段规则处理 |
| 处理重复订单 | 重复键、稳定排序和三级保留规则；日期可解析优先、最新日期优先、平局保留原始第一条；最终恢复原始相对顺序 |
| 类型与格式 | amount去货币符号/逗号/空格后转数值；日期按声明格式转无时区时间；city/status/note按冻结规则规范；`StringDtype`白话说明 |
| 验证结果 | 固定七列和列序、`order_id`非空唯一、dtype、允许值、缺失规则和行序不变量；`assert_frame_equal`用途；验证不能偷偷修数据 |

所有示例只使用公开订单学习数据或等价的脱敏最小样例，不读取私有CSV，不照抄hidden test断言，不展示reference solution。

## 5. 结构化资产与公共接口

### 5.1 类型

保持现有卡片摘要字段兼容revision 2和非Pandas smoke fixture，在revision 3核心卡片增加以下公共安全结构：

```ts
type LessonVariantId = "guided" | "concise" | "practice";

interface RichLesson {
  prerequisites: LessonPrerequisite[];
  canonicalRules: CanonicalLessonRule[];
  sourceClaims: LessonSourceClaim[];
  variants: Record<LessonVariantId, LessonVariant>;
}

interface LessonVariant {
  whyNow: string;
  overview: string;
  concepts: LessonConceptModule[];
  walkthrough: LessonWalkthrough;
  counterExamples: LessonCounterExample[];
  finalTaskConnection: LessonFinalTaskConnection;
  termNotes: LessonTermNote[];
  coveredRuleIds: string[];
}
```

`LearningCardSafeView`增加`richLesson`和会话绑定后的`defaultVariantId`。Profile静态资产保存全部三版本；服务端只根据已有背景问卷、KnowledgeState和路径scaffold计算默认版本，不让模型决定版本。

### 5.2 版本选择

默认选择规则固定为：

```text
explanation_preference == example_first
  => practice

python_experience或pandas_experience为none/uncertain
或path scaffold == worked_example
  => guided

python_experience == comfortable
且pandas_experience == comfortable
且explanation_preference == concise
  => concise

其他情况
  => guided
```

Web允许学习者使用分段控件在“逐步讲解 / 重点速览 / 案例实战”之间切换。手动选择只写`sessionStorage`中的展示偏好，不修改服务端sessionVersion、背景问卷、路径、Attempt、Evidence、mastery或正式活动。刷新同一浏览器页面可恢复展示偏好；换端时按服务端默认规则重新选择，不把浏览器状态冒充共享事实。

TUI消费同一`LearningCardSafeView`，默认显示服务端选定版本的摘要、模块目录和术语说明；TUI显示能力不足时必须明确降级为文本，不建立第二套教学正文。

### 5.3 固定正文与Agent边界

固定revision 3正文、canonical rules和source claims是教学事实的唯一权威。Agent只允许提供一段可选的“针对你的学习提示”，不得替换或改写三套正文、业务规则、代码验收标准和来源。

若动态卡片审核通过，系统把其安全提示合并到固定RichLesson之前；动态内容超时、Schema错误、来源越界或审核失败时，完整固定正文仍可用。现有录制响应必须改为中文安全提示并继续登记`LIVE_MODEL=LIVE_NOT_RUN`，不得把录制结果写成实时生成。

## 8. Web展示裁决

### 8.1 视觉方向

学习页采用“数据清洗实验手册”方向，延续现有安静的工作台风格：白色内容面、浅灰绿色背景、深绿路径栏、蓝色信息提示和琥珀色风险提示。不得改成营销落地页，不使用装饰性渐变球、嵌套卡片、超大标题或一页铺满全部正文。

页面的唯一强化视觉标识是数据清洗链：

```text
原始CSV -> 读取 -> 检查 -> 缺失 -> 去重 -> 类型 -> 验证
```

当前小节高亮，已完成和后续步骤使用不同但克制的状态。该清洗链表达真实知识顺序，不承担路径判定。

### 8.2 页面结构

页面保持现有左侧路径栏，主阅读区使用六个全宽教学模块，不做卡片套卡片：

1. `先建立直觉`：为什么学、目标、先修、预计时长；
2. `把概念拆开`：概念模块和术语注释；
3. `跟着数据走一遍`：输入、步骤、代码、逐步输出；
4. `哪里容易错`：反例、症状、原因和修正；
5. `接到最终任务`：`clean_df`关系和验收清单；
6. `术语与依据`：术语表、claim和官方来源定位。

模块使用原生可访问的展开/收起语义，摘要行必须说明模块内容而不是只显示“点击展开”。提供“一次展开全部”和“全部收起”。默认展开规则：

```text
guided  => 1、2、3
concise => 1、5
practice => 1、3、5
```

正式练习入口位于正文之后的稳定底部操作区；模块展开不能让按钮漂移覆盖正文。代码和输出使用等宽字体、固定内边距和横向滚动；不得动态缩小字体以塞入容器。

### 8.3 响应式和可访问性

- 桌面：路径栏和主阅读区双列，正文行宽受控；
- 平板：路径栏转为横向步骤条，正文单列；
- 手机：清洗链和路径可横向滚动，版本分段控件保持三等分，代码块独立横向滚动；
- 所有展开按钮、版本选择和来源链接支持键盘焦点；
- 尊重`prefers-reduced-motion`，只使用必要的展开过渡；
- 术语在桌面可悬停、在触屏可点击，解释不能遮挡正文或超出视口；
- 页面加载、固定fallback、来源缺失和卡片Schema失败必须显示明确状态，不留下空白教学区。

## 11. 停止条件

出现以下任一情况时停止冻结并登记`BLOCKED`：

- 任一知识点只有部分版本或正文未达到质量要求；
- 三版本业务规则、答案语义或source claim不一致；
- 需要修改hidden tests、Rubric、reference solution、gold或判分逻辑才能让正文成立；
- revision 2发生任何字节变化；
- 新正文导致路径预算超过现有合同且无法在不改路径规则的情况下解释；
- 动态Agent能够覆盖固定权威正文；
- 版本切换产生正式状态写入或跨端事实分叉；
- seal不可复算、泄漏扫描有命中、全量或移动端视觉测试失败；
- W6正式评测已经开始后仍试图继续修改正文或页面。
