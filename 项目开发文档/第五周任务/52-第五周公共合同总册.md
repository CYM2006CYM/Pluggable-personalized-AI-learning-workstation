## 2. 公开运行合同

沿用12号定义，不建立第二套代码活动或评测端口：

```ts
interface PublicExecutionBundle {
  runId: string;
  sessionId: string;
  activityId: string;
  profileRevision: number;
  environmentId: string;
  starterCodeHash: string;
  publicDatasetFiles: Array<{ name: string; content: string; hash: string }>;
  publicTestSources: string[];
  expiresAt: string;
  bundleHash: string;
}

interface BrowserCodeRunner {
  run(bundle: PublicExecutionBundle, code: string, signal: AbortSignal): Promise<ActivityResult>;
}
```

- `POST /api/activities/:id/run`只校验会话、活动和revision并签发公开包，不执行正式判分。
- 公开包不得含隐藏测试、参考实现、完整Rubric、私有CSV、密钥、宿主路径或正式答案。
- `runId`过期、bundle摘要不符、会话/活动不匹配统一拒绝；不得降级为使用陈旧包。
- 浏览器预览结果不回传服务端，不创建Attempt、Evidence、mastery或路径重算。
- `POST /api/activities/:id/submit`保持Node.js/Python权威正式提交，不受Pyodide开关影响。

## 3. Worker生命周期

- 首次进入代码活动时按需加载，不阻塞开始页。
- 每次运行使用干净命名空间；无法可靠清理时销毁并重建Worker。
- 取消、墙钟超时、输出超限或初始化失败必须终止Worker并保留代码草稿。
- stdout/stderr按字节流式计数，达到上限立即停止转发，不能先无限聚合再裁剪。
- Worker销毁后忽略旧`runId`迟到消息；两次运行不得共享Python全局状态。
- 页面刷新恢复代码草稿，不承诺恢复预览输出。
- Pyodide失败属于`preview_unavailable`，不是学习者错误，不产生负Evidence。

## 4. D3 Pyodide裁决门

负责人只允许以下两种正式状态：

```text
PYODIDE_ENABLED
PYODIDE_DISABLED_WITH_NODE_FALLBACK
```

启用必须同时满足：锁定版本可离线/本地加载；公开Pandas任务连续3次稳定；10组公开输入与Node的通过/失败结论一致或差异已解释；取消、超时、输出裁剪、迟到消息和运行间隔离测试通过；Worker/DOM/网络/bundle零敏感泄漏；Node正式提交仍独立可用。

任一项失败立即关闭预览入口，页面显示明确不可用状态，不继续修成生产级沙箱。`import js`、网络隔离和可靠内存限制只有实测证明后才可标`true`；否则明确标`false`并依赖受信任试用者边界。

## 5. 环境锁与seal

- C测量并提交结构化证据：Node/Python/Pandas/Pyodide版本、允许库、墙钟、stdout/stderr、源码/数据上限、进程树终止、网络隔离和可靠内存限制。
- B只能逐字段抄录C正式证据，不得估算、四舍五入或把“未证明”改为支持。
- Node `v22.23.1`、Python `3.13.7`、Pandas `3.0.5`继续精确锁定；Windows补丁号只记录。
- Pyodide关闭时`pyodideVersion`保留实测候选值或`null`并配套关闭能力标志，不得写`measured_dual_backend`。
- 只有启用门通过且双后端证据绑定完成时才可将状态更新为`measured_dual_backend`。
- B修改环境锁后必须重算revision 3 seal；C不得修改锁或自行定义seal算法。
- 本条覆盖06号第10.2第6项的历史简写：C不直接冻结Profile文件，只提交可复核实测；B不得凭开发机现值、摘要或猜测填写锁值。

## 6. Web/TUI共享会话与深链

- Web、TUI和HTTP只消费同一`LearningRuntimeFacade`、同一Profile revision和同一服务端会话。
- 深链只携带安全标识：`sessionId`及必要的`nodeId/activityId`；不得放绝对路径、Key、答案或隐藏资产引用。
- TUI打开Web前先读取服务端当前步骤；Web不可用时保存pending活动并显示可复制的localhost深链，不把活动标为完成。
- 深链失效、会话不存在或revision冲突时提示从开始页恢复，不自动新建替代会话。
- Web/TUI并发写入沿用`sessionVersion/requestId/attemptId` CAS和幂等规则；陈旧端返回冲突并重新Bootstrap。
- Zustand、TUI内存和`sessionStorage`只保存交互状态，不能覆盖服务端事实。

## 7. 三个展示案例

案例固定为：

1. 高基础学习者；
2. 非计算机初学者；
3. 实践导向学习者。

三者必须使用同一revision 3、同一目标和确定性PathEngine，不手写结果。每对案例至少有3项可观察差异，允许来自路径节点、难度、脚手架、解释偏好、诊断证据或活动顺序；不得用改答案、改Rubric、跳先修或删最终实操制造差异。案例输入、输出和路径哈希必须可重放。

案例交接顺序固定为：B提供三类合法输入、差异假设和可重放材料；A使用正式PathEngine运行并绑定实际路径/状态输出；E独立复验路径合法性、页面展示和每对案例至少三项差异；负责人复核输入、输出和哈希绑定。B不得手工编辑路径、难度、Evidence或mastery。

## 8. 故障与恢复矩阵

必须覆盖：刷新、API/服务重启、模型失败、Pyodide初始化失败、取消、超时、输出洪泛、磁盘写失败、版本冲突、重复提交、进程树残留和临时目录清理。

- 公开预览故障不影响正式提交；
- `evaluator_error`不推进、不产生Evidence；
- 重复正式提交只返回原结果；
- 陈旧版本不覆盖新状态；
- 服务重启后可由Profile和会话快照重建准备状态，摘要不符则安全失败；
- 事务任一点失败不得半写入；
- 残留能力不可靠时检测、报告并在锁中标`false`。

## 9. development-20彩排合同

固定输入为已冻结`evaluation/personas/development-20.jsonl`，不得修改案例制造通过。彩排顺序固定：

```text
自动测试 → 案例评测 → 幻觉复核 → 组内盲评 → 指标计算 → 报告生成
```

彩排版`metrics.json`必须登记指标名、分子、分母、排除项、输入哈希和非正式标志；人工复核至少记录一个单案例实际耗时。彩排不是第六周正式评测，不得覆盖60例gold或写成最终比赛结果。每个流程缺陷必须有责任岗位和停止条件。

彩排启动前必须封存D的轨迹/分镜/盲评候选、B的案例与PPT、A/C的正式主链和环境证据、E的演示脚本；封存后才能开始六环节运行，不得在运行中修改输入或指标口径。

## 10. 安全与隐私

扫描React state、DOM、网络响应、浏览器缓存、Worker消息、Agent输入、普通日志、Attempt、错误反馈和前端bundle。隐藏断言、参考实现、完整Rubric、API Key、宿主绝对路径、私有输入和精确隐藏预期必须零命中。

Pyodide Worker不是恶意代码沙箱；生产级容器、低权限账户、系统调用过滤、可靠网络/内存隔离和外部判题继续延期。
