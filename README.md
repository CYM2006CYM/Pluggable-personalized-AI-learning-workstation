# Pluggable Personalized AI Learning Workstation

本仓库是“可插拔个性化 AI 学习工作站”的完整比赛交付仓库。系统以 Pandas 数据处理学习为示范资料包，提供学情诊断、个性化路径、章节教学、客观题多 Agent 审核链、代码补全评测和学习总结等功能。

## 一键启动指南

适用于 Windows 10/11 x64。测评人员无需预装 Git、Node.js、Python、pandas 或 Conda，也不需要管理员权限。

### 启动前准备

- 从 GitHub 使用 `Code -> Download ZIP` 下载完整仓库，并将 ZIP 完整解压到本地普通目录；不要只下载或复制某一个启动文件。
- 保证电脑可访问 GitHub、`nodejs.org`、`python.org`、npm registry 和 DeepSeek API。
- 准备一个可用且有余额的 DeepSeek API Key；Key 只用于当前启动进程，不会写入项目文件或浏览器。
- 预留至少 3 GB 可用磁盘空间，用于首次准备项目私有运行环境和依赖。

### 运行步骤

1. 进入解压后的仓库根目录，双击 [`start-pi-study-helper.cmd`](start-pi-study-helper.cmd)。
2. 在弹出的“Pi Study Helper 比赛版一键启动”窗口输入 DeepSeek API Key。
3. 点击“启动并打开网页”。首次启动会自动下载或复用合同版本的 Node.js、Python、pandas 与 npm 依赖；后续启动会复用已准备的组件。
4. 保持启动窗口和随后的终端窗口开启。终端出现 `PI_STUDY_READY mode=live_model ... url=http://127.0.0.1:5173/` 后，浏览器会自动打开系统。
5. 未自动打开浏览器时，手动访问 [http://127.0.0.1:5173/](http://127.0.0.1:5173/)。结束测评时，在服务终端按 `Ctrl+C`。

网页能打开只说明本地服务已就绪。新建学习会话、触发章节客观题后，应在多 Agent 流水线看到 Generator、Hunter、必要时的 Defender 和 Judge 记录，才表示该轮使用了实时 AI。页面显示“固定题保障”时，表示该轮未形成通过审核的实时题组，常见原因是 Key、网络、响应超时或审核未通过。

完整的环境适配逻辑、手动预检、离线隔离模式和故障排查见 [`pi-study-helper/比赛方部署与启动说明.md`](pi-study-helper/比赛方部署与启动说明.md)。

## 比赛交付材料导航

### `项目介绍与设计方案/`

面向评审老师阅读的项目说明材料：

- `01-项目策划方案.md`：项目背景、目标、实施与评测证据边界；
- `02-作品设计与技术实现说明.md`：系统架构、资料包、Agent 链和关键实现；
- `03-多智能体协同审核与可视化说明.md`：多 Agent 决策过程、可视化和安全边界。

### `测试数据材料和结果/`

面向复核的测试材料与结果，按用途分为三个子目录：

- `01-测试方案与评价口径/`：评价方法、量化指标口径、核心指标对照结果及单 Agent/多 Agent 对比图；
- `02-差异化学习者测试用例/`：三类学习者的可复刻端到端测试输入与预期观察点；
- `03-端到端运行结果与过程证据/`：过程记录索引、协同过程汇总、运行耗时和案例结果说明。

其中过程性案例用于展示系统如何运行，不能代替规模化对照测试的统计结论；最终量化结论以 `01-测试方案与评价口径/核心指标对照结果.md` 为准。

### `项目开发文档/`

完整保留项目开发过程中的设计、合同、周任务、验证记录和审计材料。建议先读 [`00-文档索引.md`](项目开发文档/00-文档索引.md)，再按需要查阅资料包、路径、执行器、Agent、界面和测试专项设计。该目录为实现与审计的技术依据，不是测评系统运行所必需的依赖。


## 文件和目录说明

### `start-pi-study-helper.cmd`

比赛测评入口。它只负责转发到应用目录中的图形启动器，不保存 API Key。

### `pi-study-helper/`

学习助手应用主工程，也是后续功能开发的主要目录，包含：

```text
pi-study-helper/
├─ src/              # TypeScript应用源码
├─ tests/            # 单元、集成和回归测试
├─ fixtures/         # Profile、来源、模型响应和评测结果夹具
├─ scripts/          # 检查、验证脚本和按周可复算证据
├─ package.json      # 项目命令和依赖
└─ README.md         # 应用自身的安装与运行说明
```

Profile、诊断、Evidence、KnowledgeState、PathEngine、统一学习入口、代码执行器、模型端口和网页均由该工程实现。运行时可在网页中查看学习流程和多 Agent 协同记录；具体设计边界与实现说明见 `项目介绍与设计方案/` 和 `项目开发文档/`。

第三周PathEngine的V3-1/V3-2可复算证据及逐文件哈希位于`pi-study-helper/scripts/w3-path-validation/`。测试只读取和核对已提交证据，不在仓库内重写证据文件。

常用检查命令以该目录内的 `README.md` 和 `package.json` 为准。克隆公共仓库后可从仓库根目录安装和验证：

```powershell
pi install .\pi-study-helper
Set-Location .\pi-study-helper
npm.cmd ci
npm.cmd test
```

### `evaluation/`

确定性评测输入、独立标注、负责人资格记录和正式gold所在目录。`evaluation/golden/annotations/audit/`只保存历史审计记录和原始交付归档；其中ZIP用于审计追溯，不是应用运行依赖，也不得进入浏览器DTO、HTTP安全响应、日志、Agent上下文、学习者反馈或安全导出。

### `pi-loop-graph-sdk-main/`

项目使用的 Loop Graph SDK 完整源码。当前统一基线为 `0.2.0`，负责人批准的提交为 `401d3e9bfa49e630196caefbabd732a3209b17a0`。`pi-study-helper/package.json`、`package-lock.json` 通过带 SHA-512 完整性记录的 HTTPS 源码包锁定同一提交，首次安装不依赖 Git；本目录用于源码审计与复核。

它提供项目使用的图编排语言和运行机制，包括：

- `defineGraph`（定义图）和 `entry`（入口）；
- `codeNode`、`agentNode`、`graphNode`（阶段节点）；
- `firstMatch` 和 `finish`（路由与结束）；
- `call`（调用子图）；
- `compose`（组合子图）；
- `delegate`（委托独立Agent会话）；
- `Mechanism`（横切机制）；
- Graph校验、运行、取消、Recording/Replay、恢复和测试能力。

主要目录包括：

```text
pi-loop-graph-sdk-main/
├─ src/              # SDK源码
├─ tests/            # SDK测试
├─ docs/             # SDK文档和使用指南
├─ package.json      # SDK命令和依赖
├─ README-zh.md       # SDK中文说明
└─ README.md
```

SDK版本和提交哈希由负责人统一管理，普通成员不得自行升级、改成本地路径依赖或混入其他版本文件。需要升级时，必须同步替换SDK源码目录，更新`pi-study-helper`依赖声明和锁文件，修订公共合同，并完成SDK自身测试与应用回归测试。

### `项目开发文档/`

当前开发使用的正式设计文档目录，包含：

- `00—18`号产品和专项设计文档；
- Profile、诊断、路径、活动、执行器、Agent、界面和测试设计；
- `第一周任务/19`：第一周总任务、依赖顺序和仓库协作规则；

普通成员不得直接修改总设计文档、冻结决策、公共合同和任务书。发现设计缺口时提交问题，由负责人统一修改。

## 交付与复核边界

本仓库同时包含可运行系统、项目介绍、测试材料和完整开发记录。评审或复核时，建议按以下顺序查看：

```text
一键启动网页并体验完整学习流程
→ 项目介绍与设计方案/（理解方案与技术实现）
→ 测试数据材料和结果/（核对测试口径、量化结果和可复刻案例）
→ 项目开发文档/（追溯详细设计、合同和开发记录）
```

设计文档中可能保留历史方案、阶段性决策或后续优化项，它们不应单独被视为当前网页已提供的功能。以当前 `pi-study-helper/` 源码、网页运行结果和测试材料中的明确记录为准。

所有本地运行数据均应留在项目目录的 `.runtime/`、`.demo-data-*` 和 `.demo-build/` 中，不应提交到 GitHub；尤其不要上传 API Key、访问令牌、未脱敏模型轨迹或隐藏测试资产。
